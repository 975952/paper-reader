# 📖 论文阅读器

**桌面应用**（原生窗口，不需要浏览器、不需要 Node）。
划词即译、选中即问、图/表/公式框选交给 AI、正文引用可点、参考文献一键找 PDF。
PDF 不离开本机；问答默认只发送选中文字和当前页上下文，点「整篇」后才会把整篇论文作为本次上下文发送给你自己配置的 API，划词翻译和解释会发送选中文字及其附近上下文。

---

## 能做什么

| 能力 | 说明 |
|---|---|
| **划词** | 译 / 释 / ＋对话 / ✎笔记 / 复制；气泡和结果卡片都能拖动、能记住位置 |
| **整篇论文上下文** | 默认只发送选中文字和当前页上下文；点「整篇」只对下一次发送生效，会提示读取 / 请求量增加，发送后自动关闭；超过 10 万字自动降级成「阅读索引 + 关键词检索出的相关段落」 |
| **联网搜索** | 输入框下面点「联网」，回答前先搜一遍，来源链接列在回答下方（`[来源1]` 与论文自己的 `[27]` 区分开） |
| **论文操作（✦）** | 15 个可按需调用的操作：菜单首屏直接放 **一句话速览 / 阅读路线 / 方法拆解 / 术语表**，其余贡献 / 定位 / 公式 / 类比 / 实验评估 / 局限 / 审稿人问题 / 复现要点 / 可迁移 / 自测题 / 延伸阅读收在默认收起的「更多操作」里；结果可缓存（重复调用不花钱）、可重新生成 |
| **会话恢复与重试** | 重开论文会恢复隐藏的译文 / 问答结果，但不会强制展开；失败、停止、未完成的历史提供重试或恢复问题入口，截图跨重启只保留提示标记并需重新添加 |
| **跨论文安全** | 切换论文时丢弃旧的全文读取 / 阅读索引；缓存命中直接定位已有结果，不重复追加结果或请求 |
| **文献关系** | 自动解析全部参考文献、跟本地书架互相匹配、扫描库内互相引用；每条可查 PDF |
| **书架管理** | 一次可选 / 拖入**多个 PDF** 批量导入；左栏文件列表按住拖动调整顺序（存 `data/papers-order.json`，不改文件名）；每行右侧 × 删除文件（会二次确认；笔记 / 会话 / 进度保留，重新导入还能看到） |
| **一键导入**（界面已下线） | 后端 `/api/import-pdf` 仍在（服务端下载、校验 `%PDF-`、挡内网地址），但界面只保留「打开链接 / 复制链接」，不再提供直接抓进 `papers/` 的按钮 |
| **公式 + 表格** | 内置 KaTeX（离线）渲染 `$...$` / `$$...$$`；Markdown 表格渲染成真表格，窄侧栏可横向滚动 |
| **自动适配** | 打开论文按窗口宽度自动铺满，窗口缩放跟着变；手动缩放过就不再抢 |

> 规划中：**Coach 模式**（苏格拉底式多轮：它问、你答、答完才往下讲）。
> 调研与设计见 [`docs/paper-explainer-plan.md`](docs/paper-explainer-plan.md)。

## 从源码跑

```bash
# ① 浏览器模式（开发/调试用，需要 Node 18+）
node server.js            # 然后打开 http://127.0.0.1:8787

# ② 桌面应用（需要 Rust 工具链）
cd desktop
build.bat                 # cargo build --release + 复制 exe + 校验 SHA256
```

前端是**零依赖**的原生 ES module（没有打包步骤），`server.js` 只用 Node 内置模块。
desktop 端是 `wry + tao + tiny_http + ureq + rust-embed`，前端资源在编译期内嵌进 exe。

跑测试（需要 `cd test && npm i` 装 puppeteer-core；浏览器套件默认调用本机已装的 Chrome，
可用 `CHROME=` 指向别的路径）。

测试**不会碰你的 `data/`**：`test/_env.mjs` 是一道拒绝式护栏 —— 被测服务的 data 目录只要
不在 `test/artifacts/` 下面，套件会在发出任何写请求之前直接抛错退出。

浏览器套件需要一个**隔离实例**。推荐用 Node 后端：它从磁盘读 `public/`，改了前端立刻生效；
exe 的前端是编译期内嵌的，不重新 build 就还是在测旧前端。

```bat
:: ① 隔离书架 + 隔离 data（data 必须是 papers 的兄弟目录）
mkdir test\artifacts\baseline\papers
mkdir test\artifacts\baseline\data
copy test\fixtures\multipage-sample.pdf test\artifacts\baseline\papers\fixture-multipage.pdf
copy test\fixtures\cn-sample.pdf        test\artifacts\baseline\papers\fixture-cn-sample.pdf

:: ② 起服务（8787/8788 常被真实实例占着，用 8790）
set PORT=8790
set PRT_PAPERS_DIR=%CD%\test\artifacts\baseline\papers
set PRT_DATA_DIR=%CD%\test\artifacts\baseline\data
set NO_OPEN=1
node server.js

:: ③ 先塞一个假 Key —— 没配 Key 时前端根本不发请求，
::    math / cards / selection 会因此假红。
curl -X POST http://127.0.0.1:8790/api/config -H "Content-Type: application/json" ^
  -d "{\"apiKey\":\"sk-fake-for-tests\",\"baseURL\":\"https://api.deepseek.com/v1\",\"model\":\"deepseek-chat\"}"

:: ④ 逐个跑（它们共用同一个服务，别并行）
cd test
set BASE=http://127.0.0.1:8790
node e2e.mjs
```

自起服务、不依赖上面实例的：`node test/ux.mjs`、`node test/save-reliability.mjs`。

**不要跑**：
- `test/real.mjs` —— 已禁用，第 3 行就 `exit 2`；
- `test/desktop.mjs` —— 会按 exe 路径**强制结束正在运行的阅读器**，只在专门验 exe 时用；
- `isolate.mjs` / `diag*.mjs` / `smoke.mjs` —— 硬编码 8787 与固定文件名、零断言、恒返回成功，不能当门禁；
- `pack.mjs` —— 那是打包器，不是测试。

所有自动化测试都使用隔离目录、合成论文和本地假响应，不调用真实 AI API。
`test/real.mjs` 已禁用，避免误用用户密钥或产生付费请求。

## 怎么用

### 方式一：双击 `论文阅读器.exe`（推荐）

一个独立窗口，自带界面。第一次打开点右上角 **⚙**，填两样东西：

| 字段 | 例子 |
|---|---|
| API Key | `sk-…` |
| 模型名 | `deepseek-chat` |

点「保存」会自动测一次连接，通过就关掉弹窗。
把 PDF 拖进窗口（可以一次拖多个），或丢进 exe 旁边的 `papers/` 文件夹。
左栏文件列表：**按住一行拖动**可以调整顺序，行尾的 **×** 删除文件（删除前会问一次）。

> 需要**支持图片输入**的模型才能用「框选看图」（如 `gpt-4o-mini`、`qwen-vl-max`）。

### 方式二：`启动.bat`（浏览器模式，给开发和调试用）

需要电脑上有 Node.js。双击后启动本地服务并打开 `http://127.0.0.1:8787`。

## 交互

划选正文后，气泡上有五个按钮：

| 按钮 | 行为 |
|---|---|
| **译** | 直接翻译，译文就地弹在选区旁，同时进「译文」块 |
| **释** | **不需要提问**，直接在侧栏把这段讲明白（拆概念、拆符号、说明它在论文里的作用）—— 不弹浮层 |
| **＋对话** | **不发请求**，把选中的文字加进输入框上方的附件区。可以连续加很多段 |
| **✎** | 写笔记。**不会画黄色高亮**，只在页面右边缘留一个小书签 |
| **⧉** | 复制 |

**Ctrl/⌘ + 划选** = 把上一段选区拼进来一起处理（对付被图表/换栏切开的句子）。

### 截图 / 长截图

- **顶部 `⎚`** 或输入框右边的 **✂** 进入截图模式
- 拖一个框 → 那一块变成**图片附件**加进对话（不会自动发问，你自己提问）
- **框拖到正文区上下边缘会自动滚动**，于是可以一路框到下一页 —— 这就是长截图。
  因为图是从 PDF 重新渲染的（不是屏幕截图），超出视口的部分也能完整拿到，
  实测一次可以拿到跨 3 页、3000px 高的长图
- 发送时图片会作为多模态内容一起发给模型（需要支持图片输入的模型）

### 正文里的 `[12]` 可以点

- 正文中形如 `[12]`、`[3,4]`、`[5-7]` 的引用会被标成可点区域（鼠标移上去会亮）
- **点一下**：跳到文末那条参考文献，并弹出它的完整条目
- **再点「🔍 找这篇的 PDF」**：去 arXiv / OpenAlex / Crossref 查它的开放版本，
  给出**可直接打开的 PDF 链接**，以及 Google Scholar / 网页搜索的兜底入口
- 查的时候先从那一条文献里**认出标题**再按标题检索；认不出来（比如只剩一个缩写字母）
  就退回整条文献串。卡片顶部会写清楚这次是**按什么搜的**
- 结果按标题相关性过滤：和标题明显不是一个东西的条目直接丢掉，
  所以「查不到」时宁可给你一条空结果 + 说明，也不会塞一堆无关论文
- 这个功能需要联网；查不到时会明确告诉你，不会假装有结果

### 笔记

- 点 **✎** → 直接弹出编辑框写想法（留空也会保存这段文字）
- **正文右边缘出现一个小书签**：灰色 = 只有收藏，蓝色 = 写了笔记
- **点书签**随时重新打开读 / 改；点到别处会自动保存
- 左栏「笔记」区可以跳转、编辑、删除
- 笔记**不会**在正文里留下黄色高亮块（避免遮挡原文）

### 快捷键

| 键 | 作用 |
|---|---|
| `T` / `E` / `Q` | 译 / 释 / 问 |
| `R` | 框选区域 |
| `Ctrl+F` | 全文搜索 |
| `+` `−` `0` | PDF 放大 / 缩小 / 适应宽度 |
| `Ctrl` `+` `−` `0` | **阅读字号** 增大 / 减小 / 复位（在输入框里也生效，且不会触发浏览器整页缩放） |
| `PgUp` `PgDn` `Home` `End` | 翻页 |
| `Alt+↑` `Alt+↓` | 面板头上：与相邻面板换位 |
| `Alt+H` | 面板头上：隐藏该面板 |
| `Enter` / `Space` | 面板头上：折叠 / 展开该面板 |
| `Shift+F10` | 面板头上：打开面板管理器 |
| `Ctrl+Alt+←` `Ctrl+Alt+→` | 把浮动面板停靠回左 / 右栏 |
| `Esc` | 关气泡 / 取消框选 / 停止生成 / 关菜单 / 浮动面板回停靠 |

## 界面

```
┌ 📖 文件名 │ ‹ 3/15 › │ 大小 − ▬●▬ + ⤢ 145% │ ⎚ ⌕ ▤ ⚙ ┐
├──────────┬──────────────────────────────┬──────────────┤
│ 文件列表  │                              │  ┌ 译文 ────┐ │
│ 目录      │          PDF 正文             │  ├ 问答 ────┤ │
│ 笔记      │       （[12] 可点）           │  └──────────┘ │
│ 文献关系  │                              │              │
└──────────┴──────────────────────────────┴──────────────┘
   ▤活动栏      ↕ 可拖拽调宽        ↕ 可拖拽调宽     ▤活动栏
                                  ┌ 输入框 ────────┐
                                  │ 译文 问答      │ ← 分块开关
                                  └────────────────┘
```

- **左右两栏都能拖动边界调宽**，宽度会记住；**拖到阈值以下松手即收起**，**双击分隔线**切换收展
- **窗口放不下时自动收起**：正文有最小可用宽度（`--viewer-min`，默认 420px），放不下时先收右栏、
  再收左栏；**窗口变宽按你的意图自动恢复**（自动收起只存内存，不会写进你的偏好）
- **收起后出现活动栏**：左侧 4 个图标（文件 / 目录 / 笔记 / 文献关系，点了展开并滚到该区）；
  文献关系默认只留标题入口，论文打开后后台整理，点击标题再展开列表（已保存的展开偏好继续沿用），
  右侧 1 个（展开右栏）
- **面板管理器**（顶栏 `▤`，或面板头上的 `⋯`）：六个面板——文件 / 目录 / 笔记 / 文献关系 / 译文 / 问答——
  首屏显示面板名称、当前停靠位置和显示·隐藏；展开每行的「布局设置」可用 **固定 / 上移·下移 / 浮出 /
  停靠到左·右·底部**。底部保留明显的「恢复默认布局」，「全部显示 / 全部收回停靠」在「批量操作」里；
  固定（pinned）只影响「窗口变窄时先牺牲哪一侧」，不影响手动收起
- **应用内浮动面板**：可以浮出窗口、拖动、缩放（右下抓手）；原位置留一个虚线占位块；
  拖到左/右/底部会显示**停靠预览**，松手平滑收回；关闭时朝最近边缘收起；**切换论文自动回停靠**
- **系统级独立面板窗口（桌面版）**：面板管理器 →「布局设置」→「独立窗口」→「打开独立窗口」；
  译文 / 问答 / 文件 / 目录 / 笔记 / 文献关系都可单独放到系统窗口，布局变化会和主窗口同步
- **动效**：100–260ms、可被下一次操作打断，`prefers-reduced-motion` 下全部关闭
- **大小** 是独立的 PDF 缩放控件：`−` / 滑块 / `+` / `⤢适应宽度`
- **双指缩放速度**（设置 →「双指缩放」）：触摸屏两指张开与触摸板两指捏合**共用同一个滑杆**，
  0.5×~2×，1.0× 是默认手感；拖动当场生效（不用重开论文、不打断手势），值存进
  `localStorage reader.ui`（老存档没有这个字段时落回 1.0，手感不会被升级偷偷改掉）
- **三个尺度互相独立**（设置 →「阅读助手样式」）：主题与**结果密度**（紧凑 / 标准 / 宽松）直接可见；
  **界面字号** / **阅读字号** / **控件大小**、行高、代码字号、结果最大宽度、结果透明度，
  以及「显示页码」「显示原文引用」「默认展开来源」收在默认收起的「更多样式」里；底部有「恢复默认布局」「恢复默认样式」
- **结果区以正文为主体**：正常回答不再显示「回答完成」；页码 / 原文引用 / 底部操作条默认降低对比度，鼠标移上去才恢复
- **AI 区是可选的两块**（没有「看图」块了，图片直接进对话）：
  - 默认一个都不开，用到哪块自动出现（点「译」出「译文」，点「释」或发消息出「问答」）
  - 输入框**下面**一排就是开关，点一下开、再点一下关
  - 块与块之间可以**拖动分隔条调高度**
  - 按住块头的 **⠿** 拖动，可以**和其他块上下交换位置**
  - 每块都写了自己的用途，鼠标悬停开关也有说明
- **文献关系**：按 **书架已有 / 已找到开放版本 / 待查·未找到 / 被引用** 分组（每组带计数、可折叠），
  顶部一行概览计数，支持**搜索 / 状态筛选 / 排序**；点任意一行打开详情（条目全文、书架匹配、开放版本链接、
  跳回正文、复制引用）；单条查询失败只影响那一条，可单独重试
- **输入框上面是附件区**：选中的文字、截图都堆在这里，可以加很多个，逐个 ✕ 移除
- **选中的文字是自己画的方块**，上下不会重叠（Chrome 原生选区画的是行盒，
  而 pdf.js 的行盒常常比行距还高，看着就是一块块互相压着，所以换成了自绘）
- 主题跟随系统（浅色 / 深色自动切换），也可以手动指定
- 设置里有两部分：**AI 字段**（API Key、模型名；接口地址默认折叠在「改接口地址」后面）
  和**阅读助手样式**（主题 / 结果密度直接可见，其余正文大小 / 行高 / 代码大小 / 结果最大宽度 /
  结果透明度与三个显示开关在默认收起的「更多样式」里），底部还有「恢复默认布局」「恢复默认样式」

## 逐条对照你的反馈

| # | 反馈 | 根因 | 修法 | 验证 |
|---|---|---|---|---|
| 1 | 放大之后就不清晰 | 高倍下单页 canvas 涨到 **69.8 MP（≈280MB）**，多页叠加爆显存，浏览器静默降采样 | 高倍时**只渲染可见切片** + 至少 2× 超采样 | 444% 时密度仍 2.0、面积封顶 17.7MP |
| 2 | 界面不能拖动 | 固定列宽 | 左右分隔条可拖 | 210→300px、360→430px |
| 3 | 设置太复杂 | 低频样式和核心选项混在一起 | 主题 / 结果密度直接可见，其余低频项收进「更多样式」 | 核心可见；展开后保留全部旧控件 |
| 4 | 要单独的大小调节 | 只有 ± | 独立「大小」控件：`−` + **滑块** + `+` + `⤢` | 拖到 250% → scale=250% |
| 5 | **翻译功能不正常** | 重写时丢了 `onDelta` —— 译文只在整段生成完后一次性出现 | 四个调用点补回逐块渲染 | 第一块 **420ms** / 全部 2470ms（17%） |
| 6 | 问和解释没区别 | 「问」直接发请求了 | **释 = 直接输出**；**问 = 只放引用不发请求** | 点「问」新请求数 = 0 |
| 7 | 选中的词和送去的词差几位 | pdf.js 用 `scaleX()` 压整段文字，命中测试差 1~2 字符 | 换成等效 `letter-spacing` | 真实拖选 35% 处 **26/26 零误差** |
| 8 | 等很久没输出像卡住 | ①同 5；②上游回 JSON 时代理仍贴 `text/event-stream` 标签（**Node 和 Rust 两侧都有**）；③没有超时 | ①逐块渲染；②透传上游 content-type；③客户端空闲看门狗 + 服务端空闲超时 + 「■停止」和计时 | 卡死用例 4.0s 后明确报错 |
| 9 | 除核心按键外全部移除 | — | 删掉标签页、快捷行、术语表、预设、温度、字号等 | 审计：标签页 0 / 折叠 0 / 术语表 0 |

## 隐私

- 只监听 `127.0.0.1`，不对局域网暴露（实测局域网 IP 访问超时）
- PDF 解析、渲染、区域截图全在本地完成，**PDF 本身永不上传**
- 只有你主动划选的那段文字 / 主动框选的那块图片会发给你自己的 API
- 只有点「找这篇的 PDF」时，才会把**那一条参考文献的文字**发给 arXiv / OpenAlex / Crossref 检索
- 密钥只写在本机 `data/config.json`，不进浏览器 localStorage、不经第三方
- **密钥填一次就一直有效**：关掉窗口、重新打开、换论文都不用再填；想换一把就直接在 ⚙ 里粘贴新的覆盖
- 自动化测试不会再动你的配置（`test/_env.mjs` 要求被测服务的 data 目录必须位于 `test/artifacts/` 下，否则直接拒绝运行）
- 想完全离线：把接口地址改成 `http://127.0.0.1:11434/v1`（Ollama），文献检索不用即可

## 已知限制

- **扫描版 PDF** 没有文本层，划词无效 → 用顶栏「⬚」整篇 OCR，或用「⎚ 框选」交给视觉模型
- **双栏排版**跨栏划选可能把两栏文字混在一起（按列重排未做）
- 引用跳转依赖 PDF 文本层里的 `[n]` 编号和文末文献列表；**作者-年份制**的引用（如 `(Vaswani et al., 2017)`）暂时点不了
- 文献检索靠三个公开接口，**需要联网**；冷门文献或有付费墙的论文可能只有 DOI 落地页，没有免费 PDF
- 一次只能开一篇论文
- 扫描版 OCR 逐页发图，**页数多的论文会比较慢**，而且需要支持图片输入的模型

## 为什么长这样

完整调研见 [`docs/RESEARCH.md`](docs/RESEARCH.md)。一句话：

> 「开源 + 划词 + 本地 + 自带阅读器」这个组合，在调研范围内不存在 —— 做划词的都要装 Zotero 或没有阅读器，
> 做全文对照的全是 Python + ONNX 的离线批处理，闭源阵营全是把论文上传到云端的 SaaS。
