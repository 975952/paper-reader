## 0. 本轮拍板的决策（v2 与 v1 的差异）

| # | 决策项 | 用户拍板 | 对设计的影响 |
|---|---|---|---|
| 1 | 首页 | **不做常驻「书架」标签**：所有标签关闭 → 显示 Welcome 界面；有标签时顶栏不放首页入口 | 删除 v1 的 HomeTab；标签条只在有文档标签时出现；`#homeBtn` 在标签模式下隐藏 |
| 2 | 翻译归属 | **翻译属于文档**（doc 级，独立于问答会话） | 译文单独存盘（零后端改动的伪会话方案，§4.5）；旧会话里的译文迁移出来 |
| 3 | 问答归属 | **问答属于文件夹**（folder 级；同一文件夹内多篇论文共用一批会话） | 会话键从 `docId` 改为 `folderKey`；切换文档标签不换会话；右栏会话 chips 按文件夹显示（§4.4） |
| 4 | 文档可见性 | **同时看到已打开哪几个文档、文件夹里有哪几个文档，并能按需打开** | 标签条 + 左栏文件夹树「已打开」标记 + 「全部标签/文件夹文档」菜单 + 右栏文档条（§4.6） |
| 5 | 生成中切换 | 翻译生成中切标签**后台继续**；问答生成中切会话**后台继续** | 任务按「文档键 / 文件夹会话键」注册；DOM 按标签 / 会话保留（§4.7、§6.4） |

## 1. 目标与非目标

### 1.1 目标

1. **同时打开多个 PDF**：正文上方出现标签条（有标签时），点击切换、拖动排序、关闭、溢出可达；
2. **切换不丢状态**：每篇论文的阅读位置/缩放/译文/搜索，每个文件夹的问答会话，都按标签/文件夹保留；
3. **右栏结构重做**：
   - 译文块 = **当前文档**的译文（切标签跟着换，独立存盘）；
   - 问答块 = **当前文档所在文件夹**的会话（同文件夹内切文档不换会话；切到别的文件夹才换）；
   - 右栏顶部有「文件夹 + 文档」上下文条，能同时看到**已打开文档**和**文件夹内其他文档**，并可点击按需打开；
4. **生成不中断**：翻译生成中切标签、问答生成中切会话，任务在后台继续，完成后再落盘；
5. **Welcome 语义**：没有打开的文档 = Welcome 书架页（现有 `#home`），不占标签、不显示标签条、顶栏不放首页入口；
6. **不破坏现有行为**：单篇打开、既有测试、双后端契约、构建流程保持可用；新行为有开关可回退；
7. **不动后端**：继续用现有 `/api/session`、`/api/sessions`、`/api/papers`、`/api/state`（§4.4 的文件夹键与译文伪会话都复用现有接口）。

### 1.2 非目标（本次不做）

- 左右/上下分屏（用户已确认暂时不做；P4 再评估）；
- 标签预览模式、标签固定（pinned）、标签组、多选批量操作；
- 拖出标签成新窗口 / 浮动窗口（桌面壳不支持，系统级独立窗口已删除）；
- 跨文件夹的全局问答（问答严格按文件夹隔离）；
- 同时参考多篇文档回答（「多文档上下文」列为 P4 可选项；P3 先做单文档为主 + 文档可见/按需打开）；
- 移动端 `public/mobile/`（保持单文档）；
- 新增 `/api/*` 接口（Node 与 Rust 双实现成本高；本设计不依赖新接口）。

## 2. 概念模型

```
Workspace（一个窗口 = 一个工作区）
├── 全局：uiStyle / state.panels / 左栏文件树 / fileSel / folderOpen / settings / profileStore / jobs
├── Welcome（无标签时）：现有 #home 书架页 + 最近打开 + 打开 PDF
├── DocumentTab[0..N]（N ≤ 10；同一 docId 至多一个；有标签时标签条出现）
│    └── DocRuntime（文档级）
│         ├── PDF 文档句柄（pdf.js PDFDocumentProxy + 页面骨架 + 视图状态）
│         ├── 文档级 app 状态（搜索 / 高亮 / 目录 / 参考文献 / docText / docProfile / 剪贴草稿…）
│         ├── 译文块 DOM + 译文条目（doc 级，独立存盘）
│         └── 该文档上的后台任务（翻译生成等）
└── FolderRuntime（文件夹级，按需创建；与打开几个文档无关）
     ├── 问答会话列表 + 当前会话（folderKey 标识）
     ├── 每个会话的运行时：entries/history/DOM 片段/后台生成任务
     └── 问答块 DOM（会话 chips + 当前会话 body）
```

术语：

| 术语 | 含义 |
|---|---|
| 标签（tab） | 一个打开的文档；`kind='doc'`。没有 `home` 标签 |
| Welcome | 没有打开文档时的书架页；不是标签、不进标签条 |
| 文档键 `docId` | 服务端按文件名哈希的稳定键（现有）；笔记/阅读进度/译文用它 |
| **文件夹键 `folderKey`** | 前端由文件夹相对路径计算的稳定键（`folder-<8 位 hex>`，§4.4）；**问答会话用它** |
| 文档运行时 `DocRuntime` | 一篇打开文档的 PDF 句柄 + 文档级状态 + 译文块 DOM |
| 文件夹运行时 `FolderRuntime` | 一个文件夹的问答会话集合（列表、当前 sid、每个会话的运行时与 DOM） |
| 会话（session） | 一个文件夹下的一段问答，`sid` 标识；服务端 `session-<folderKey>-<sid>.json` |
| 译文存档 | 一篇文档的译文条目，服务端 `session-<docKey>-__translate.json`（复用 session 接口） |
| 后台任务 job | 一次翻译/问答生成；按 `translate:<docId>` 或 `qa:<folderKey>:<sid>` 注册，切标签/切会话不中断 |

### 2.1 数据归属矩阵（最终版）

| 数据 | 归属 | 切换标签/会话时 | 持久化 |
|---|---|---|---|
| 打开文档集合 / 顺序 / 活动标签 | 工作区 | 不变 | `localStorage.reader.workspace.v1` |
| 左右栏宽度、面板显隐/顺序、主题、字号 | 工作区 | 不变 | `reader.ui` / `reader.panels`（现有） |
| 阅读页 / 缩放 / fit | 文档 | 随标签 | `data/state.json` 的 `docs[docId]`（现有） |
| **译文条目** | **文档** | 切标签跟着换（各自保留） | **译文存档（doc 级）** |
| **问答会话 / entries / history / 摘要 / 教学进度** | **文件夹** | 切标签不换（同文件夹）；切到别的文件夹才换 | 会话文件（folderKey） |
| 搜索（query/hits/idx） | 文档 | 随标签 | 不持久化 |
| 目录 / 笔记 / 参考文献 / docText / docProfile / 扫描索引 | 文档 | 随标签（缓存命中不重建） | 笔记服务端；其余现有缓存 |
| 输入框草稿 / 待发附件 | 文档 | 随标签 | 不持久化（关标签进已关闭栈时保留草稿） |
| 翻译生成中任务 | 文档 | **不中断** | 完成后写译文存档 |
| 问答生成中任务 | 文件夹会话 | **不中断**（切标签/切会话都继续） | 完成后写会话文件 |
| 学习画像 / 长期记忆 / API 配置 | 工作区 | 不变 | 服务端 data / localStorage（现有） |

> 右栏面板布局（译文/问答谁开着）仍是工作区级；内容按「文档 / 文件夹」各自隔离。
> 译文与问答的块可以同时只有一块可见（一栏只开一个，沿用现有决定），但两者数据源不同：
> 译文看**当前标签**，问答看**当前标签所在文件夹**。

## 4. 交互规范

### 4.1 标签条

#### 4.1.1 显示条件

- **有至少一个文档标签才显示**；关掉最后一个标签 → 标签条隐藏、正文切回 Welcome、底栏禁用、左右侧栏收成活动栏（沿用 `setView('home')`）；
- 启动恢复：上次关闭时有标签且文件还在 → 恢复标签；一个都没有 → 直接进 Welcome（不恢复任何标签）；
- `?open=xxx` 参数：打开/激活对应文档（保持现有测试/脚本入口）。

#### 4.1.2 标签形态

```html
<div class="tab" role="tab" tabindex="0" data-tab-id="doc:attention-xxxxxxxx"
     aria-selected="true" aria-controls="viewer">
  <span class="tab-ico" aria-hidden="true"><!-- file 图标 --></span>
  <span class="tab-title" title="Attention Is All You Need.pdf">Attention Is All You Need</span>
  <span class="tab-badge hidden" data-state="loading|translate|done|error" aria-hidden="true"></span>
  <button type="button" class="tab-close" tabindex="-1" title="关闭" aria-label="关闭 …">×</button>
</div>
```

| 状态 | 视觉 | 触发 | 清除 |
|---|---|---|---|
| 活动 | `--bg-elev` + 顶部 2px 主色线 + `--fg` 500 | 激活 | 切走 |
| 悬停 | 背景提亮 + 关闭按钮显形 | 悬停 | 移出 |
| 加载中 | spinner（12px 主色） | 首次打开/重载 | 完成/失败 |
| **译文生成中** | 主色呼吸小圆点 | 该文档有翻译后台任务且不活动 | 任务结束 |
| **译文完成未读** | `--ok` 实心点 | 非活动标签的翻译任务完成 | 激活该标签时 |
| 加载失败 | warning 图标（`--err-text`） | 打开失败 | 重试成功/关闭 |
| 拖拽中 | 原标签变淡 + 跟手幽灵 + 插入线 | 拖动 > 4px | 松手 |

> 问答的生成状态不挂在标签上（问答属于文件夹）：见 §4.7 与左栏文件夹行/会话 chip 的指示。

#### 4.1.3 操作表

| 操作 | 行为 |
|---|---|
| 单击标签 | 激活（热切换；冷标签先加载） |
| 中键单击 / `Ctrl+W` / `Ctrl+F4` | 关闭该标签；有未发送草稿时草稿进「已关闭」栈并 toast；生成中先确认 |
| 双击标签 | 无操作（避免误触） |
| 双击标签条空白 | 打开 PDF 文件选择 |
| 右键标签 | 关闭 / 关闭其他 / 关闭右侧 / 关闭全部 / 复制文件名 / 在左栏中定位 / 重新加载 |
| 拖动标签 | 拖拽排序（Pointer Events；§4.1.4） |
| 滚轮（标签条） | 溢出时上下滚 → 横向滚动 |
| 「…」按钮 | 打开「全部标签 / 文件夹文档」菜单（§4.6.2） |
| 「＋」按钮 | 打开 PDF 文件选择 |
| 关闭活动标签 | 激活右侧邻居，其次左侧；一个不剩 → Welcome |
| 关闭生成中的标签 | 确认后 abort 该标签上的**翻译**任务并关闭；文件夹问答任务不受影响（它不属于这个标签） |
| 关闭**文件夹最后一个标签** | 若该文件夹有问答后台任务 → 确认「关闭会停止该文件夹正在生成的回答」，确认后 abort 该文件夹会话任务 |

#### 4.1.4 拖拽排序（Pointer Events）

```
pointerdown(tab)：记录起点/tabId/标签条滚动量；不 preventDefault（保留点击/中键）
pointermove：位移 > 4px 且主键按下 → 拖拽：setPointerCapture、原标签淡出、克隆幽灵跟手、
             用「除自己外的标签中线」计算插入位、画 2px 主色插入线；指针进入两侧 32px 自动滚动
pointerup：按插入位重排 → FLIP 动画 120ms → persistWorkspace()
pointercancel / Esc / 指针离开窗口：取消并回原位
```

- 阈值 4px；触摸/笔：长按 250ms 才允许拖拽，长按前移动 > 8px 视为横向滚动；
- 不做跨窗口拖出（拖出=取消）；
- 键盘替代：标签聚焦时 `Alt+←/→` 移动位置。

#### 4.1.5 键盘

现有 `initShortcuts()` 先处理 Esc/F11/Ctrl±/Ctrl+0，再 `if (typing) return`，再 Ctrl+F，最后带修饰键一律 return。
标签快捷键插在「带修饰键 return」之前：

| 快捷键 | 行为 |
|---|---|
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | 最近使用（MRU）循环 |
| `Ctrl+PageDown` / `Ctrl+PageUp` | 按标签顺序循环切换 |
| `Ctrl+1 … Ctrl+8` | 第 n 个标签（不含已关闭的） |
| `Ctrl+9` | 最后一个标签 |
| `Ctrl+W` / `Ctrl+F4` | 关闭当前标签（首页按钮无） |
| `Ctrl+Shift+T` | 重开最近关闭的标签（内存栈，最多 10 个；草稿随标签回来） |
| `Alt+←/→`（标签聚焦） | 移动标签位置 |
| `←/→/Home/End`（标签聚焦） | 移动焦点（不激活）；`Enter/Space` 激活 |

注意：`Ctrl+W` 必须 `preventDefault()`（Chrome 里否则关页面）；输入框里也生效；Esc 不关标签。

#### 4.1.6 无障碍

`role="tablist"` / `role="tab"` + `aria-selected` / `aria-controls="viewer"`；
关闭标签后焦点落到相邻标签；状态指示不是纯颜色（带 `title`/`aria-label` 文本）；
拖拽是增强，键盘可完成同样的排序与切换。

### 4.4 会话数据模型：从「按文档」改为「按文件夹」

#### 4.4.1 键

前端计算（必须永久稳定，改动会造成历史会话“失联”）：

```js
// FNV-1a 32bit → 8 位十六进制；路径归一化后再算
function folderKeyOf(folderPath) {
  const p = String(folderPath || '').replace(/\\/g, '/').replace(/^\/+|\/+$/g, '').replace(/\/{2,}/g, '/');
  const raw = p ? `folder:${p}` : 'folder:__root__';
  let h = 2166136261;
  for (let i = 0; i < raw.length; i++) h = Math.imul(h ^ raw.charCodeAt(i), 16777619) >>> 0;
  return `folder-${h.toString(16).padStart(8, '0')}`;
}
```

- 结果形如 `folder-1a2b3c4d`，匹配服务端 `docIdOf()` 的「已是 docId → 原样返回」规则，所以可**直接当 doc 参数**；
- 服务端因此不需要任何改动：`/api/session?doc=folder-1a2b3c4d&sid=…`、`/api/sessions?doc=folder-…`、附件目录全部沿用现有逻辑；
- 会话文件落到 `data/session-folder-1a2b3c4d[-sid].json`；
- **文件夹重命名/移动会改变路径 → 键改变**：需要迁移（§7.3），并保留旧文件。

#### 4.4.2 会话内容（服务端对象，checkSession 只做体积/条数校验，允许新增字段）

```jsonc
{
  "kind": "folder-session",
  "folder": "Transformer",          // 说明性；路径可能变，键才是权威
  "entries": [
    { "block": "chat", "kind": "user", "text": "为什么除以 √dk？",
      "docId": "attention-xxxx", "docTitle": "Attention Is All You Need",
      "page": 5, "quote": "…", "ts": 1750000000000,
      "status": "user" },
    { "block": "chat", "tag": "answer", "kind": "assistant", "text": "…",
      "docId": "attention-xxxx", "docTitle": "Attention Is All You Need",
      "page": 5, "status": "complete", "sources": [], "meta": "", "retry": { /* 含 docId */ } }
  ],
  "history": [ /* 每轮带 docId/docTitle（§4.8.1） */ ],
  "ops": [], "teaching": null,
  "summary": "", "summaryCovered": 0,
  "updatedAt": 1750000000000
}
```

- `docId/docTitle` 让「文件夹会话跨文档」可追溯：UI 打文档标签、引用可跳回对应文档；
- 旧会话条目没有这两个字段 → 迁移时补上（迁移来源文档的 docId/标题）；再读不到的旧数据按「未知文档」处理；
- 每个会话最多 90 条回放、payload 体积上限沿用现有（客户端裁到 ≤350KB，服务端 4MB）。

#### 4.4.3 当前会话

- `localStorage['reader.activeFolderSession.v1'] = { [folderKey]: sid }`（新键）；
- 旧键 `reader.activeSession`（docId→sid）保留不动，供旧模式/回退使用；
- 打开文档时：先加载该文件夹会话列表；若无 active sid → 取最近更新的会话或新建空会话；
- 切标签到同文件夹其他文档：**不换会话**（folderKey 相同）；切到别的文件夹：挂起当前文件夹的问答块，挂载目标文件夹的问答块。

### 4.5 译文数据模型：文档级存档

- 目标语义：译文属于文档，和会话无关；切换标签/会话都不影响；
- **零后端改动方案**：复用 `/api/session`，每题文档用固定 `sid = "__translate"`：
  - 写：`POST /api/session?doc=<docId>&sid=__translate`，payload `{kind:'doc-translate', docId, entries:[...], updatedAt}`
  - 读：`GET` 同 URL；打开文档时恢复；
  - 列表里的过滤：`/api/sessions?doc=<docId>` 会列出 `__translate` 这一项，前端一律过滤掉（不作为会话显示，也禁止删除入口）；
- 服务端 `checkSession` 允许任意字段与体积内内容 → 不需要 Node/Rust 改一行；
- 附件：译文条目不含截图，不会触发附件目录问题（即使有，也落在该 doc 的独立附件目录里，删除文档时自行清理）；
- **迁移**（§7.3）：旧会话 `entries` 里 `block === 'translate'` 的条目抽出来 → 追加到该文档的译文存档；
  旧会话正文（chat）复制成文件夹会话；旧文件不删；
- 译文条目的内存结构沿用现有 `{block:'translate', tag, page, quote, text, kind, status, ts}`，落盘时加 `docId/docTitle` 便于排查。

### 4.6 「同时看到已打开文档 / 文件夹内文档 / 按需打开」的三处入口

#### 4.6.1 左栏（常驻）

- 文件面板顶部新增「已打开」区（`#openEditors`）：
  - 列出所有打开的文档（按标签顺序），行 = 图标 + 短名 + 所在文件夹（用于同名区分）+ 关闭按钮；
  - 当前活动标签对应行高亮；点击 = 激活该标签；关闭按钮 = 关标签；
  - 默认展开；为空时整块隐藏（Welcome 时自然为空）；
- 下方文件夹树（现有）增强：
  - 已打开的文档行左侧加 3px 主色竖线（与「活动高亮」区分：活动=整行强调，已打开=左竖线）；
  - 文件夹行右侧计数改为 `已打开 n / 共 m`（n=0 时只显示 m）；
  - 行为不变：点击文档 → 已打开则激活、未打开则新建标签并激活（按需打开）；
  - 这样「已打开列表 + 文件夹树」同屏可见，满足「同时看到」。

#### 4.6.2 标签条「全部标签」菜单（`…`）

- 标签溢出时出现；也允许 `Ctrl+Shift+E`/右键菜单打开；
- 内容分两组：
  ```
  ┌ 全部标签（3）───────────────┐
  │ [过滤标签…]                 │
  │ ● Attention Is All You Need │  ← 点击激活；× 关闭
  │ ● BERT                      │
  ```

- 「当前文件夹」组 = 活动标签所在文件夹的**全部文档**（已打开的置灰/打勾），点未打开项 = 按需打开；

- 已打开（本文件夹）→ 点击激活；文件夹内其他文档 → 点击新建标签并激活；

### 4.7 后台生成（翻译 & 问答都不中断）

#### 4.7.1 任务注册表

```js
// tabs.js / jobs 模块
const jobs = new Map();   // key -> Job
// key: `translate:${docId}` | `qa:${folderKey}:${sid}`
const Job = {
  key, kind: 'translate'|'qa',
  docId?, folderKey?, sid?,
  abort,                 // AbortController
  startedAt, hint,       // 进度文案
  entry?,                // 输出目标 message 节点（DOM 已捕获）
  sessionRt?,            // qa：该会话的运行时（写 entries/history）
  tab?,                  // translate：该文档的运行时（写 translateEntries）
  status: 'running'|'done'|'stopped'|'failed',
};
```

#### 4.7.2 行为

| 场景 | 行为 |
|---|---|
| 翻译生成中切标签 | `translate:<docId>` 任务继续；写该标签的译文条目与（停放的）译文 DOM；标签上显示生成中/完成未读点；切回来看到实时/完整译文；完成时保存译文存档 |
| 翻译生成中关闭该标签 | 确认后 abort；已收到的部分作为 stopped 保存（与现有停止语义一致） |
| 问答生成中切会话（同一文件夹） | `qa:<folderKey>:<sid>` 继续；写该会话的 entries/body（body 脱离文档但仍在内存）；会话 chip 显示生成中/未读；切回该会话时是实时/完整内容 |
| 问答生成中切到**别的文件夹**（标签去了另一文件夹） | 旧文件夹会话任务继续；左栏该文件夹行显示生成中指示；右栏当前文件夹不受影响；旧文件夹 chip 在下次打开时显示结果 |
| 问答生成中关闭该文件夹最后一个标签 | 确认「会停止该文件夹正在生成的回答」→ abort 该文件夹所有 qa 任务 |
| 停止按钮 / Esc | 只停**当前上下文**的任务：问答块开着→停当前会话任务；译文块开着→停当前文档翻译任务 |
| 并发 | 每个文档/会话最多 1 个任务；全局同时最多 2 个问答 + 1 个翻译（超出时提示先等一个完成） |
| 任务完成时 | 若对应上下文是活动的 → 走原有渲染与提示；否则只更新标签/文件夹/会话指示；可选 toast（2.5s，可关） |

#### 4.7.3 为什么要按会话保留 DOM

- 现有流式实现 `streamTarget(node)` 直接写一个已捕获的 DOM 节点；
- 如果切会话时 `clearChatBlock()` 清空 DOM，后台任务会写进脱离文档的旧节点，切回来时内容不在；
- 方案：**每个会话一个 `.ai-body` 节点**（首次访问时创建/从服务端恢复），切会话 = 从 `chatBodyMount` 摘下旧 body、挂上新 body；
  后台任务继续写自己的 body（脱离文档但对象仍在），切回来直接挂上 → 内容、滚动位置都在；
- 内存控制：会话 body 只保留「最近 3 个 + 有后台任务的」；其余冷会话切回时从服务端重建（体验稍慢但省内存）。

### 4.8 跨文档问答（P4 可选项，先写清目标）

> P3 的问答是「文件夹会话 + 以当前活动文档为主上下文」：会话跨文档存在、消息标文档、引用可跳；
> 但每次回答只喂当前文档的上下文。下面是把「同时参考多篇」做实的设计，排 P4。

#### 4.8.1 历史消息的文档标注

- `readingTurn()` 增加 `{ docId, docTitle }`（user 消息带，assistant 继承同轮 doc）；
- `snapshotHistory()` 保留 `docId/docTitle` 两个字段；
- `historyMessages(history, currentDocId)`：当前文档的回合原样发送；**其他文档的回合**在前面加
  `【当时讨论的文档：《BERT》】`，避免模型把上一篇的上下文当成当前篇；
- 会话入口/恢复时按 `entries[].docId` 回填（迁移数据用来源文档补齐）。

#### 4.8.2 多文档上下文（P4）

- composer 上「参考文档 chips」：勾选的已打开同文件夹文档进入本次上下文；
- 上下文预算（沿用现有 FULL_LIMIT/PICK_K 思路）：
  - 主文档（当前）：按当前发送范围（当前页 / 整篇 / 索引 + 相关段）照旧；
  - 参考文档：优先 `docDigest`（索引）+ 与问题相关的 1–2 段原文；没有缓存则 `extractPdfText` 现取（限页数/字数）；
  - 总上下文设上限（例如主文档 60% / 参考文档合计 40%），超出按相关度截断；
- 提示词新增「参考文档」段，要求区分来源；引用格式扩展为
  `〔《文档短名》p.N‖片段〕`，点击时先激活/打开对应标签再定位（§4.3.4 的跳转规则）；
- 未打开文档不进入上下文（保持「按需打开」的直觉：想参考就先打开）。

### 6.5 异步任务改造（现有入口 → 新键）

| 现有入口 | 任务键 | 写什么 | 切换时 |
|---|---|---|---|
| `send()` / `chat()` | `qa:<folderKey>:<sid>` | 会话运行时的 entries/history、该会话 body（捕获的 entry DOM）、会话文件 | 切会话/切文件夹不 abort；完成写盘 |
| `doTranslate()` / `doExplain()` | `translate:<docId>` | 文档的 translateEntries、译文块 body、译文存档 | 切标签不 abort；完成写盘 |
| `runOperation()` / `runTeaching()` | `qa:<folderKey>:<sid>`（结果进会话） | 会话 entries、opsCache（全局按 docId:opId） | 同上；结果按 docId 标注 |
| `scheduleSessionSummary()` | `qa:<folderKey>:<sid>` | 会话运行时的 summary/history | 由任务完成回调写回对应会话 |
| `startDocProfileScan()` / `warmDocText()` | 文档级（非生成任务） | tab.rt 的 docProfile/docText | 切标签不中断，守卫 `tab.loadSeq` |
| 参考文献解析 / 目录 / 笔记 | 文档级 | tab.rt | 切标签不中断，只有活动标签才渲染 |
| 学习记忆提取 | 工作区级 | 全局 profileStore | 不受影响 |

守卫函数（取代现有 `readingRequestCurrent`）：

```js
function requestAlive(job) {
  if (job.kind === 'translate') return !!job.tab && !job.tab.closed;
  if (job.kind === 'qa') return !!job.folderRt && !job.folderRt.closed && !!job.sessionRt;
  return false;
}
```

- 不再要求「活动标签/活动会话」才允许完成；
- 但只有活动上下文才更新全局 UI；非活动上下文只更新标签/文件夹/会话指示与持久化。

### 6.6 竞态规则

1. 切换标签串行化（`switchQueue`）；切换文件夹/会话各自串行；
2. 每个任务带 `jobKey`，重复触发同键任务时先 abort 旧的（或直接忽略提示“正在生成”）；
3. 关闭标签/文件夹/删除文档/删除会话时：先 `abort` 相关任务 → 再释放 DOM/句柄；
4. 后台任务完成时若其 DOM 已释放（例如会话被冷淘汰）→ 只写会话文件，不渲染；
5. 会话 body 冷淘汰时若有任务在跑 → 不淘汰（保留到任务结束）。

## 7. 持久化与迁移

### 7.1 本地/服务端键

| 键 | 内容 | 说明 |
|---|---|---|
| `localStorage['reader.workspace.v1']` | `{version, tabs:[{docId,name,path}], active, updatedAt}` | 只存定位信息；没有标签时 tabs=[] |
| `localStorage['reader.tabs']` | `'1'`/`'0'` | 标签功能开关；`'0'` 时走旧单文档路径 |
| `localStorage['reader.activeFolderSession.v1']` | `{ [folderKey]: sid }` | 每个文件夹当前会话 |
| `localStorage['reader.folderSessionMigrated.v1']` | `{ [docId]: {folderKey, at} }` | 旧会话/译文已迁移的文档标记（防重复迁移） |
| `data/state.json` 的 `docs[docId]` | `{page, scale, fit, ts, name}` | 现有；切换/关闭标签时把所有打开标签的进度写进去 |
| `data/session-<folderKey>[-<sid>].json` | 文件夹问答会话 | 现有接口，新键 |
| `data/session-<docKey>-__translate.json` | 文档译文存档 | 现有接口，伪会话 |
| `data/notes-<docKey>.json` | 笔记/高亮 | 现有，不变 |
| `data/state.json` 的 `lastDoc` 等 | 最近阅读 | 现有；Welcome 的「继续阅读」继续用 |

### 7.2 启动/恢复

```
Settings.load → loadPanels → initViewer（空 viewer，不变）→ ... → loadServerState → refreshPaperList
→ restoreWorkspace():
    1. 读 reader.workspace.v1；与 state.papers 对账（docId → path → name）
    2. 缺失文件丢弃并 toast（「N 篇已不在书架，相关标签未恢复」）
    3. 建文档标签元数据（不加载 PDF）；tabs=[] 则直接 setView('home')（Welcome）
    4. 活动标签 = 存档 active；找不到 → 第一个标签；仍没有 → Welcome
→ activateTab(活动标签)（冷加载：viewer.load + 恢复译文 + 该文件夹的会话）
→ ?open= 参数优先（打开/激活对应文档）
→ 不恢复「书架标签」（不存在）
```

### 7.3 迁移（旧「按文档」→ 新「译文按文档 + 问答按文件夹」）

**原则：复制，不删旧文件；失败不影响旧数据；每个文档只迁一次。**

触发时机：标签模式下第一次激活某文档时（懒迁移，不扫全部书架）：

1. 检查 `reader.folderSessionMigrated.v1[docId]`，已标记则跳过；
2. 读该文档旧会话列表：`GET /api/sessions?doc=<docId>`（过滤 `sid === '__translate'`）；
3. 对每个旧会话：`GET /api/session?doc=<docId>&sid=<sid>` 取 payload：
   - `entries` 里 `block === 'translate'` 的条目 → 追加到该文档译文存档（`__translate`），按 `(page, text, ts)` 去重；
   - 其余条目（chat/操作/教学）→ 复制成该文件夹下的会话：
     - 新 sid：保留旧 sid 若该文件夹下不存在，否则生成新 sid；
     - 每个条目补 `docId/docTitle`（来源文档）；
     - 标题取首条 user 文本（与 `/api/sessions` 同规则）；
     - `POST /api/session?doc=<folderKey>&sid=<newSid>`；`summary`/`summaryCovered`/`ops`/`teaching` 原样带过去；
   - **旧文件不删除**（`/api/session` DELETE 不调用）；
4. 若该文件夹还没有 active sid → 把「最近更新的迁移会话」设为当前会话；
5. 写 `reader.folderSessionMigrated.v1[docId] = {folderKey, at}`；
6. 失败处理：单个文档失败只 toast 提示并保留标记为空，下次重试；绝不阻塞打开文档。

**文件夹重命名/移动**（路径变 → folderKey 变）：

- 在 `startInlineRename`（PATCH `/api/folders` 成功）与 `moveItem`（移动文件夹）之后调用
  `remapFolderSessions(oldPrefix, newPrefix)`：
  1. 旧 `state.folders` 里所有以 `oldPrefix` 开头的路径（含自身/子孙）逐一算新旧 key；
  2. 对每个旧 key：`/api/sessions?doc=<oldKey>` 列会话 → 逐条 GET → POST 到新 key（同 sid；新 key 已有同 sid 则跳过）；
  3. 迁移 `reader.activeFolderSession` 与 `reader.folderSessionMigrated` 中的 key；
  4. 旧文件保留（回滚/追溯用）；失败只 toast，不阻塞重命名；
- **删除文件夹**：不自动删会话文件（非破坏；数据留在 data/ 里），UI 提示「该文件夹的问答会话仍保留在 data/，如需清理可在删除时勾选」——勾选清理为 Phase 4 可选。

**文档被删除/移出文件夹**：译文按 docId 保留（与笔记一致，删文件不删笔记）；旧会话里该文档的条目保留 docId，
若文档已不在书架，消息上的文档标签仍显示标题、引用不可跳转（降级为文字）。

## 8. 边界与状态矩阵

| 场景 | 行为 |
|---|---|
| 打开已打开文档 | 激活已有标签（不新建/不重复加载） |
| 加载中再点同一文件 | 只激活/等待 |
| 加载失败 | 标签 error；正文空态（原因/重试/关闭标签）；其他标签/Welcome 仍可用 |
| 关闭最后一个标签 | Welcome；标签条隐藏；底栏禁用；左右侧栏按 `setView('home')` 收起 |
| 启动时没有可恢复标签 | 直接 Welcome |
| 顶栏「首页」按钮 | 标签模式下隐藏（不放入口） |
| 删除正在打开的文件 | 确认后关标签（停它的翻译任务）；若它是文件夹最后一个标签 → 按 §4.1.3 处理文件夹问答任务 |
| 移动正在打开的文件 | 更新标签 url/path/name；**译文仍跟文档**；它在新文件夹里的问答从新文件夹会话开始 |
| 重命名/移动文件夹 | 迁移该文件夹（含子孙）的问答会话键（复制，不删旧）；译文/笔记不受影响 |
| 删除文件夹 | 文档删除时关对应标签；该文件夹问答会话保留在 data/（Phase 4 可选清理） |
| 同一文件夹内切标签 | 问答块不重载、不换会话；译文块换成新文档的译文；文件/文档上下文条更新 |
| 切到另一个文件夹的标签 | 挂起旧文件夹问答块（后台任务继续）；加载/挂载新文件夹会话；译文块换成新文档译文 |
| 翻译生成中切标签 | 后台继续；标签指示；回来可看结果 |
| 问答生成中切会话 | 后台继续；chip 指示；切回实时/完整 |
| 问答生成中切到别的文件夹 | 后台继续；左栏该文件夹行/其会话 chip 指示 |
| 关闭生成中的标签/文件夹最后一个标签 | 按 §4.1.3 确认并 abort 对应任务 |
| 关闭应用 | `beforeunload` 保存活动标签会话/译文/进度（现有 keepalive）；非活动上下文已在切换/完成时保存 |
| 标签上限 10 | toast 提示先关，不自动淘汰 |
| 全屏 | 标签条隐藏；Esc 退出后恢复 |
| 窄窗 | 标签切 `tabbar-compact`（100–130px）；溢出菜单可达；右栏自动收起逻辑不变 |
| 触摸屏 | 点标签切换；横滑=滚动标签条；长按=菜单；长按后拖=排序 |
| Welcome 里打开文档 | 新建标签并激活；标签条出现 |
| 多窗口（浏览器开两个页面） | 不同步工作区；最后一次写入生效；桌面版单窗口无影响 |

## 15. 关键时序

### 15.1 启动恢复（上次打开 A（Transformer）、B（生成模型），停在 B）

```
boot → 读 workspace = [A, B]，active=B
→ 建标签元数据（不加载 PDF）；B 在 "生成模型" 文件夹
→ activate(B)：viewer.load(B.url) → 恢复 B 的译文存档 → 加载 "生成模型" 文件夹会话、挂载当前会话
→ A 保持冷；左栏文件树：A/B 行有已打开标记
用户点 A → activate(A)：suspendTab(B)（存 B 进度/译文块/视图状态 + viewer.detach()）
→ attach A 的 pdf 句柄或冷加载 → 恢复 A 的译文 → 换到 "Transformer" 文件夹会话
```

### 15.2 同文件夹内切文档（问答不换、译文换）

```
活动 A（Transformer）→ 点 B（同在 Transformer）
→ suspendTab(A) 存 A 的视图/译文块/文档状态；viewer.attach(B 的句柄)
→ 译文块：挂 B 的译文 DOM；问答块：folderKey 不变 → 不卸载、不换会话、不停任务
→ 文件夹条：📁 Transformer · 📄 B
```

### 15.3 翻译生成中切标签

```
A 划词翻译 → 任务 key=translate:<A>，流式写 A 的译文块 body
→ 用户切到 B：A 的译文 body 随 A 的译文块停放到 A.park；任务继续写它（脱离文档但对象在）
→ B 正常阅读；A 标签显示「译文生成中」点
→ 任务完成：写 A 的译文存档；A 标签变「未读」点
→ 切回 A：挂回译文块，看到完整译文，指示清除
```

### 15.4 问答生成中切会话 / 切文件夹

```
在会话 S1（文件夹 F）提问 → 任务 key=qa:<F>:<S1>，流式写 S1 的 body
→ 切到同文件夹的 S2：S1 的 body 从 mount 摘下保留；S2 的 body 挂上；任务继续写 S1
→ S1 chip 显示生成中；切回 S1 看到实时/完整内容
→ 若此时切到另一个文件夹的标签：F 的整个问答块停放；任务继续；左栏 F 文件夹行显示生成中
→ 任务完成：写会话文件；非活动时只更新指示
```
