## 0. 一页结论（先看这）

今天的会话系统是**一轮“文件夹化”改造（PROGRESS §73）的结果**：会话属于文件夹、
一次只处理一个文件夹、重新进入文件夹默认新会话、会话列表藏在一个小胶囊里。
它解决了“跨论文串味”，但**把会话变成了隐式副作用**：用户看不见自己有几个会话、
不知道刚才聊到哪、回来看不到上次的讨论、AI 功能记录跟着会话被切碎。

调研 VS Code Copilot、Cursor、Claude Code、JetBrains AI、Codex CLI 后，方向很明确：
**会话要成为一等公民**（列表、状态、标题、置顶/归档/搜索、显式新建、后台继续），
但“是否自动恢复上次会话”要按阅读器场景取舍——IDE 自己在 1.107→1.108 之间改过一次主意。
本项目按“阅读器”的体量做裁剪，核心改 7 件事：

| # | 改动 | 一句话理由 |
|---|---|---|
| 1 | **进文件夹默认显示“空态选择卡片”**：不自动恢复，但把「继续上次会话『…』（N 条 · 时间）」「新建」和最近会话放在眼前；会话入口（会话头/历史面板）常驻 | **用户拍板选 B（2026-11-03）**，与 VS Code 1.108 一致：会话入口一眼可见，但不把长对话硬塞回来；仍保留 `resume`/`new` 两档设置给不同习惯（见 §3.4） |
| 2 | **会话升级为一等公民**：标题、创建/更新时间、置顶、归档、状态、涉及论文、预览 | 现在标题只能靠首条问题猜，列表只有标题+条数+时间 |
| 3 | **右栏聊天头改造 + 全高历史面板**：搜索、时间分组、当前高亮、行内重命名/置顶/归档/删除 | 替代现在“小胶囊 + 迷你菜单”，对标 VS Code 的 sessions list（compact 布局） |
| 4 | **会话元数据内嵌进会话文件**（`title/titleSource/createdAt/pinned/archived/folderPath/docIds/...`），扩展 `/api/sessions`，新增 `PATCH /api/session` | 零新增文件类型、向后兼容、Node/Rust 改动小；会话数少，暂不需要独立索引 |
| 5 | **归档 ≠ 删除 ≠ 清空**；删除改应用内二次确认；新增“导出 Markdown / 复制全部” | 现在删除即永久删文件+附件，且用原生 `confirm` |
| 6 | **AI 功能结果（深入阅读/读懂论文）加“论文级记录”**：当前会话没有但别的会话做过 → 提示“其它会话有结果”，可直达或重新生成 | 现在换会话后“已生成”消失、点一次就重新花 token |
| 7 | **修掉四个隐藏缺陷**：①`updatedAt` 被浏览行为刷新导致会话乱序 ②文件夹改名后会话失联 ③生成中切会话会丢内容 ④“清空会话”措辞含糊、无归档兜底 | 见 §1.5 §4.3 §4.4 |

**不做**：嵌套会话/子会话、自定义分组、跨设备同步、云端会话、把译文并进会话历史。
**默认策略（用户拍板 B）**：进文件夹默认显示空态选择卡片（继续上次 / 新建 / 最近），
不在后台自动恢复；`reader.session.onEnter` 仍留三档（默认 `choose`）。会话仍属于文件夹（= IDE 的 workspace）；
历史面板可切“全部文件夹”只读浏览，点击跨文件夹会话 = 切文件夹 + 打开该会话（带确认）。

## 1. 现状：会话系统怎么工作（代码级）

### 1.1 数据与归属

**存储**（`server.js:1965-2039`，Rust 对等实现 `desktop/src/api.rs:1318-1450`）：

| 内容 | 文件 | 键（`doc` 参数） | 说明 |
|---|---|---|---|
| 文件夹问答会话 | `data/session-<folderKey>-<sid>.json` | `folderKey = folder-<fnv1a8(路径)>`（`app.js:5244-5256`） | 有 sid 时带后缀；老数据无 sid 是 `session-<folderKey>.json` |
| 文档译文 | `data/session-<docId>-__translate.json` | `docId`（文件名哈希，`server.js:125-132`） | 伪会话，`sid=__translate`（`app.js:5240`），不是真会话 |
| 旧版按文档会话 | `data/session-<docId>[-<sid>].json` | `docId` | 只用于懒迁移（`migrateLegacySession`，`app.js:5483`） |
| 旧版全局会话 | `data/session-<__global__ 的 docId>-<sid>.json` | URL 里仍用 `doc=__global__`（`LEGACY_GLOBAL_SESSION_DOC`，`app.js:5239`） | 启动时按条目 `docId` 拆进各文件夹（`migrateGlobalSessionsToFolders`，`app.js:5706`） |
| 截图附件 | `data/attachments/<sessionKey>/<id>.png` | 与会话同键 | 会话文件里只存 id 引用；保存时 GC，删会话时整目录删（`server.js:235-256`） |

**会话文件内容**（`buildSessionPayload`，`app.js:5389-5459`；服务端只做体积/条数校验，
`security.js:427-448`，允许额外字段）：

```jsonc
{
  "entries": [ /* 可见消息：block/tag/page/quote/kind/text/docId/docTitle/shots/status/
                  sources/meta/basis/retry/chips/teaching，最多回放 90 条 */ ],
  "history": [ /* 发给模型的轮次记录，restoreReadingHistory 恢复，最多 80 条 */ ],
  "ops": [ { "id": "<docId>:<opId>", "text": "...", "at": 0, "page": 0 } ],  // 深入阅读等结果缓存
  "teaching": { "walk": { "docId": "...", "sid": "...", "step": 3, "messages": [...] } },
  "summary": "…", "summaryCovered": 12, "summaryPrompt": "2026.11.4",
  "updatedAt": 1730000000000
}
```

**归属结论**：会话（`entries/history/summary/ops/teaching`）属于**文件夹**；
译文属于**文档**；截图附件属于**会话**；AI 功能结果属于**会话**；教学进度属于**会话**。

**活动会话**存在 `localStorage['reader.activeSession']`，一张 `{ [folderKey]: sid }` 表
（`app.js:5231-5284`）；当前文件夹存 `reader.currentFolder.v1`。

### 1.2 生命周期（今天的行为）

```
启动
  └─ initFolderContext（app.js:5692）：读 currentFolder → state.folderClosed = true
       → migrateGlobalSessionsToFolders（一次性）
打开论文（openDocColdSwitch，app.js:3554）
  ├─ 若当前有会话内容 → saveSessionNow（即使没新消息也写！→ updatedAt 刷新，见 §1.5-⑥）
  ├─ ensureFolderForDoc（app.js:5608）
  │    ├─ 换文件夹：关掉旧文件夹全部标签 → startFolderSession()（新 sid）
  │    └─ 同文件夹但 folderClosed：startFolderSession()
  ├─ restoreSession（app.js:5895）：并行读「文件夹会话 + 本文档译文」
  └─ loadSessionList（app.js:6065）→ loadPaperMemory（新会话首轮注入旧会话摘要）
回首页 / 关掉全部标签（app.js:3441）→ folderClosed = true（下次进 = 新会话）
切文件夹（app.js:5629）→ 生成中则拒绝；保存 → 关旧标签 → 新会话
新建会话（newSession，app.js:6180）→ 存旧的 → 换 sid → 清空问答 DOM/内存 → 清 AI 记录
                           → 立刻落盘空文件（否则列表看不到）
切换会话（switchSession，app.js:6156）→ 存旧的 → 换 sid → 只重放问答（译文不动）
删除会话（deleteSession，app.js:6207）→ 原生 confirm → DELETE → 若删的是当前则回默认会话
清空会话（clearCurrentSession，app.js:6028）→ 原生 confirm → 只清问答 + AI 记录
关页（beforeunload，app.js:10673）→ keepalive 保存两组会话
```

**会话菜单里的动作**（`renderSessionMenu`，`app.js:6077`）：切换、删除（行内 ×）、
「本篇对话记忆」开关、「清空当前会话」、「新建会话」。

### 1.3 前端交互

- **入口唯一**：右栏问答块顶部一个小胶囊 `#sessBar`（`index.html:174-184`，
  `style.css:898-966`），只在问答面板显示时出现；胶囊文字 = 当前会话标题或「会话」。
- **列表**：点胶囊弹出迷你菜单，一行一个会话：标题（首条用户消息前 60 字）+「N 条 · X 前」，
  行内只有删除按钮；底部三个文字按钮（记忆/清空/新建）。
- **标题**：没有存标题；`/api/sessions` 每次从 `entries` 里取第一条 user 文本截 60 字
  （`server.js:2016-2026`、`api.rs:1394-1408`），**不可改、措辞不可控**。
- **状态**：列表没有任何状态（生成中/未读/失败）；当前会话只靠高亮。
- **空会话**：新建立即写空文件，列表里显示「新会话」。
- **记忆**：新会话首轮注入本论文最近 2 个会话的 `summary`（`loadPaperMemory`，`app.js:6580`），
  可在菜单关掉（localStorage 按 docId 记）。

### 1.4 周边耦合（改会话会牵动谁）

| 能力 | 现状代码 | 会话改造要注意 |
|---|---|---|
| 问答流式 | `chat()` + `state.abort`；`addEntry` 建 DOM，`finishEntry` 收尾 | 生成中切会话会丢内容（§1.5-③） |
| 译文 | `restoreSession` 合并 `__translate` 条目；切会话只重放问答 | 不得把译文写进会话，也不得因切会话覆盖译文文件（历史上踩过，PROGRESS §65.2） |
| AI 功能（深入阅读/读懂论文） | `runOperation`（`app.js:7198`）读 `state.opsCache`（键 `docId:opId`） | 缓存按**会话**装回（`restoreSession` 5955-5963），换会话 = 已生成消失 |
| 读懂论文教学 | `state.teaching.walk` 存在会话 `teaching` 字段 | 换会话后进度不在 |
| 会话摘要 | `scheduleSessionSummary`（`app.js:6608`）滚动摘要写 `summary` | 标题自动生成可以复用这条模型调用 |
| 跨论文阅读（Agent） | 提示词里“当前文件夹 / 默认只读” | 会话的可见范围要跟它一致 |
| 热切换停放 | `parkDocView`/`unparkDocView` + `chatVersion`/`chatSigOf` | 切会话要作废停放视图，否则旧内容挂回（PROGRESS §66 的坑） |
| 多标签 | `tabs.js` + `openDocColdSwitch` | 同文件夹切标签不换会话（要保持） |

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| ① | **进入文件夹默认新会话**，旧会话只能去小胶囊菜单里翻 | `startFolderSession` 在 `ensureFolderForDoc`/`switchFolder`/`initFolderContext` 被无条件调用（`app.js:5587,5622,5639,5699`） | “我回来接着聊”变成默认做不到；用户以为会话丢了 |

| ⑥ | **`updatedAt` 被“打开别的论文”刷新**：`buildSessionPayload` 无条件 `updatedAt: Date.now()`（5433），而打开论文/切文件夹都会存一次 | `openDocColdSwitch` 3557-3561、`switchFolder` 5634 | 会话列表“X 分钟前”和排序失真：只是浏览别的文件，旧会话就跳到最前 |
| ⑦ | **文件夹改名/移动后会话失联**：`folderKey = hash(路径)`，改名后新键下没有会话 | `folderKeyOf`（5254）、`startInlineRename`（3049）只改目录不改会话 | 用户重命名文件夹后，之前的问答“消失”（文件还在 data/，但列表读不到） |
| ⑧ | **AI 功能结果被会话切碎**：`ops` 按会话装回，换会话后“已生成”消失 | `restoreSession` 5955-5963；`runOperation` 7206-7220 | 同一个结果可能被重复生成付费；用户想要“这篇论文做过就能直接看” |
| ⑨ | **教学进度跟着会话**：`teaching.walk` 存在会话里 | 5946-5954 | 新建会话后“继续下一步”没了；只能回旧会话 |
| ⑩ | **空会话文件堆积**：每次进文件夹都建一个空会话文件 | `newSession` 6196-6197 | data/ 里 `session-*` 越积越多，列表里全是“新会话” |
| ⑪ | **列表只有元信息、没有状态**：生成中/未读/失败在列表里看不见 | `renderSessionMenu` 6077-6126 | 切走再回来不知道刚才那条答完了没 |
| ⑫ | **删除/清空语义相近**：两个都是“删内容”，没有“收起来”的中间态 | 菜单三项（6118-6124） | 用户想“整理一下”时只能二选一：留着占地方 / 删掉冒险 |

| ⑮ | **双后端重复逻辑**：`/api/sessions` 元信息派生在 Node 与 Rust 各写一遍 | `server.js:2002-2039`、`api.rs:1362-1450` | 改造时两边必须同步，否则桌面版与网页版行为不一致 |

> 推断会标「推论」。VS Code 站点当前最新稳定版 1.144。来源见附录 B；未确认事项在附录 B 末尾列出。

### 2.1 VS Code Copilot Chat（主参考；跟踪到 1.144 / 2026-11）

**概念层级**：VS Code 把 `session` 定义成“一个任务的单位（工作区 + 代码改动 + 会话记录）”，
`chat` 是 session 里的对话；支持多 chat 的 harness 一个 session 可含多个 chat（主 chat + 嵌套会话）。
[来源：Understand sessions and chats](https://code.visualstudio.com/docs/agents/concepts/sessions.md)

**列表与可见性**（最值得抄的部分）：
- Chat view 顶部就是 **sessions list**，显示**当前工作区**的会话、**按时间分组**（今天/更早…）；
  没打开工作区时显示跨工作区会话。Agents window 的列表在左侧栏、跨工作区、默认按工作区分组。
- 列表有两种布局：**Compact**（列表与对话共用面板，点进会话、返回键回列表）与
  **Side-by-side**（列表常驻在对话旁边）；设置 `chat.viewSessions.enabled` 可隐藏/显示。
- 过滤器区分 **活跃 / Archived（已归档）/ Done**；还有 **External**（发现 Copilot CLI、Claude Code、
  Codex 等其它应用的会话，可选最近 24 小时/7 天/30 天）。
- 会话可 **置顶（pin）**；可 **归档**（移出活跃列表、保留记录、可恢复）；**删除**是永久删除并带警告；
  **关闭 chat tab ≠ 删除**（关掉只是隐藏）。[来源：Manage agent sessions](https://code.visualstudio.com/docs/agents/run/sessions/manage-sessions.md)
- 支持**自定义分组**（Create Group/Subgroup、拖动排序、拖动改归属、Promote to Session），
  但这是 Agents window 的多项目能力，对本项目过重（不学）。

**状态与并发**：
- 每个 chat 有自己的**状态**（in progress / waiting for input / unread / error）与未读标记；
  session 只要还有任一 chat 在跑就显示进行中；标题栏有 **status indicator**（未读/进行中徽标）。
- 会话**可以并行运行，切换界面不打断**；“sessions run in parallel and keep running when you switch between them”。
- 外部会话的写入有**单写者保护**：只允许一个应用写；冲突时显示
  “This chat is open in another app”，禁止发送/排队，直到解决。

**生命周期语义（非常有参考价值）**：新会话 / 嵌套会话 / **分叉（fork）** / **旁问（side chat）** 四选一：
- 新会话：无关任务，全新历史与工作区；
- 嵌套会话：相关任务、上下文全新；
- fork：从**任意一条历史消息的 checkpoint** 分叉，继承到该点为止的历史，原会话不变（`/fork`、
  Fork Conversation）；
- side chat：`/btw` 或选中文字 “Ask in Side Chat”，继承上下文但**独立 transcript**，不污染主对话。
- 恢复：sessions list 里选会话即继续，归档的也能 Unarchive 后继续。
  **注意 1.107→1.108 的反转**：1.107 曾默认恢复上次会话（`chat.viewRestorePreviousSession`），
  1.108 又改成「重启后空 Chat 视图 + 从列表进历史」——说明“自动恢复”是产品口味问题，不是唯一解（见下）。

**上下文与导出**：
- 输入框有**上下文窗口用量控件**；自动压缩，或 `/compact` 手动压缩（`github.copilot.chat.summarizeAgentConversationHistory.enabled`）。
- 每条 chat 有独立标题（自动生成、可 Rename）与模型选择；
- **导出**：`Chat: Export Chat...` 导出 JSON；右键 Copy / Copy All / Copy Final Response（Markdown）。
- **搜索**：本地会话索引（SQLite：session metadata/对话轮次/文件变更/Pull Request 引用），
  `/chronicle:search`、自然语言查询、standup 汇总。[来源：Save, sync, query session history](https://code.visualstudio.com/docs/agents/run/sessions/session-history.md)

**2026-07 的新东西（验证方向）**：Agents window 公共预览；**多 chat sessions**（一个 session 内多个

### 2.6 取舍：学什么、不学什么

**学（按优先级）**

1. **列表是一等公民**：常驻入口、时间分组、当前高亮、搜索、置顶、归档（VS Code / Cursor / Claude Code 一致）。
2. **“默认策略”要看得见，而不是二选一**：不靠“自动恢复”也不靠“自动新会话”偷偷决定，
   而是进入文件夹时把上次会话**放到眼前**（恢复 + 轻提示，或空态 + “继续上次”卡片）+ 设置项。
   VS Code 1.107→1.108 的反复说明这是产品口味问题（§2.1、§3.4）。
3. **新建 ≠ 清空**：新建只开新会话，旧会话原样保留；“清空/归档/删除”是独立动作。
   （Claude Code `/clear` 明确旧会话可 `/resume` 回；VS Code 明确新建不清已保存文件/指令/memory。）
4. **状态可见、切换不丢**：生成中/未读/失败；P0 先做守卫，P1 做后台继续。
5. **归档 ≠ 删除**：给“整理”一个安全中间态；删除必须明确确认（VS Code 把 close/archive/delete 分得很清）。
6. **标题**：自动派生可改；AI 自动标题放 P1（Claude Code 用小模型按首条 prompt 生成，验证了成本可行）。
7. **草稿随会话保存**：切换/重开不丢未发送输入（三家都做）。
8. **跨归属查找**：本文件夹默认 + “全部文件夹”只读浏览 + 搜索（业界共识是“归属决定默认可见性，查找必须跨归属”）。
9. **导出 / 复制全部**：论文笔记场景很有用，实现便宜。

**学但必须裁剪（阅读器不需要原样照搬）**

- VS Code 的 **session ⊃ chat 两级结构**：本项目只保留「会话」一级，不引入 nested chat；
  “分叉”只作为一条消息上的操作（P2），不单列概念。
- **fork / checkpoint**：只做“从某条分叉 / 回退对话”，不碰文件快照——阅读器没有代码改动，
  影子 git / 三选恢复（Cline）用不上（当前 Agent 工具也是只读的，见 `public/js/agent.js:5`）。
- **单写者**：P0 先做“生成中守卫”，P2 再做多窗口 409 / 租约提示（VS Code 的 “open in another app” 同款思路）。
- **存储**：本期不拆 `data/sessions/` 目录、不引 SQLite、不改 JSONL；理由见 §4.1。
  等会话数上千或跨文件夹搜索变慢再上索引（P2 备选）。

**不学**

- 嵌套会话 / 多 chat 组 / 自定义分组 / 拖动排序 / 批量操作：单用户、会话数量级几十，收益低。
- worktree / 代码 diff / PR / 云同步 / 跨设备：不是代码工具。
- 语义搜索 / 自然语言查询会话：本地全文子串搜索足够（P1）。
- “会话 = 任务 = 工作区产物”的完整概念：阅读器没有产物边界，概念越重用户越糊涂。
- 会话内检查点恢复（Cline 三选）：当前没有写操作，等 Agent 开放写能力再评估。

## 3. 重新设计

### 3.1 设计原则

1. **会话是用户资产**：用户攒下的对话不能被“进文件夹/切论文/切换”这些副作用弄丢或藏起来。
2. **工作区语义不变**：一次一个文件夹、文件夹内多篇论文共用会话、译文按文档、面板一栏一个。
3. **续聊要看得见，新建要显式**：进入文件夹默认把「继续上次」和最近会话放到眼前（空态选择卡片，
   用户拍板 B），不用“自动新会话”表达“换话题”；新建 = 用户的明确决定。
4. **一屏内可完成**：列表、切换、重命名、置顶、归档、删除都在右栏内完成，不新增左栏图标、不开弹窗路由。
5. **数据向后兼容**：老会话文件原样可读；新字段缺省可派生；迁移只复制不删除。
6. **双后端同构**：所有接口 Node 与 Rust 行为一致，测试同时覆盖。

### 3.2 概念模型

```
工作区（= 当前文件夹，一次只开一个）
   ├── 会话 Session（一等公民：id/标题/时间/状态/置顶/归档/涉及论文）
   │     ├── entries 可见消息（问答 / 教学 / 深入阅读结果 / 截图引用）
   │     ├── history 模型轮次（最近 3 轮原文 + 更早的滚动 summary）
   │     ├── ops AI 功能结果缓存（docId:opId）
   │     └── teaching 教学进度
   ├── 论文 Document（可多篇；会话可跨论文，消息带 docId/docTitle）
   │     └── 译文 Translate（按文档，不进会话；伪会话 sid=__translate）
   └── 截图附件（按会话目录单独存）
```

术语统一（写进使用说明）：
- **会话** = 一段持续对话（今天的“会话”保持不变，只是变成可见可管理）；
- **新建会话** = 开一段新的、从零开始的对话（保留旧会话）；
- **清空会话** = 把当前会话的内容抹掉（保留会话壳与标题时间）；
- **归档会话** = 收进“已归档”，不删内容，可恢复；
- **删除会话** = 永久删除内容与截图（二次确认）。

### 3.3 归属与可见范围

**保持“会话属于文件夹”**，理由：
- 与“一次只处理一个文件夹”一致（同一时刻只有一套标签/文件上下文）；
- 文件可在文件夹间转移，但一个文件夹的讨论属于那个阅读场景（如“Transformer 论文专题”）；
- 历史上做过“全局会话”，被用户否掉（PROGRESS §73.1：会话应该属于文件夹）。

**新增两个“看得见”的维度**（不改存储）：

1. **按论文筛选**：会话消息本身带 `docId/docTitle`（早已有），列表可按当前论文过滤
   “只显示聊过这篇的会话”。解决“会话属于文件夹，但我想找这篇论文的讨论”。
2. **全部文件夹（只读浏览）**：历史面板顶部切“本文件夹 / 全部文件夹”。后者列出所有
   文件夹的会话（含已失效文件夹的），点击时提示“该会话属于文件夹 X，切换过去打开？”——
   确认后走 `switchFolder` 再打开会话。满足“全局可查、默认只看当前”的口径，不引入跨文件夹生成。

> 备选（不推荐）：改成按论文（每篇一份会话）。它会和“文件夹内多篇论文共用一批会话”的用户口径冲突，
> 且切论文就断片（历史上因此改过两轮）。若将来要，只需在 meta 里加 `primaryDocId` 与按 docId 过滤，
> 不需要动存储结构（当前设计已预留 `docIds`）。

### 3.4 生命周期与状态机

**持久状态**（写进会话文件 meta）：

```
active（默认，出现在“本文件夹/全部”列表）
  ├─ pin → pinned（置顶，仍在 active 区，排序最前）
  ├─ archive → archived（从活跃列表隐藏；可 unarchive 回 active）
  └─ delete → 删除（文件 + 附件目录，不可恢复；二次确认）

清空（clear）≠ 状态变化：保留会话文件与 meta，只把 entries/history/ops/teaching/summary 归零；
updatedAt 保持不变（避免“清空”把空会话顶到列表最前）；列表仍显示该会话（标题保留，预览清空）。
```

**运行态**（不落盘，前端内存 + 可选 localStorage）：

```
idle（默认）
running  ← 该会话有流式任务在跑（切走也标在列表里）
unread   ← 任务在非当前会话完成，或应用启动后有新内容；进入该会话即清
error    ← 最近一次回答失败（entries 里 status=failed 派生）
```

排序规则：`pinned 优先` → `updatedAt 降序`；分组：置顶 / 今天 / 昨天 / 最近 7 天 / 更早 / 已归档。
“X 分钟前” = `updatedAt`（**只在内容变化时更新**，见 §4.3），另显示 `最后打开` 时可选用 `lastOpenedAt`。

**会话创建规则**（替换今天“进文件夹即新建”）

设置项 `reader.session.onEnter` 三档（**默认 `choose`，用户 2026-11-03 拍板 B**；设置放会话 ⋯ 菜单或 ⚙ 里，先用 localStorage）：

| 档位 | 行为 | 适用 |
|---|---|---|
| `choose`（默认） | 显示空态选择卡片：继续上次（N 条 · 时间）/ 新建 / 最近会话 | 既想一眼看到入口，又不想被长对话打断；VS Code 1.108 同款 |
| `resume` | 自动恢复上次会话 | 阅读是持续性活动，回到同一文件夹通常=接着读 |
| `new` | 总是新会话（= 今天的行为） | 习惯旧行为的回退开关 |

自动降级（只对 `resume` 生效）：

```
进入文件夹（启动恢复 / 切换文件夹 / 从首页打开）
  1. onEnter = choose → 直接显示选择卡片（「继续上次「…」N 条 · 时间」+ 新建 + 最近 5 条），不自动恢复
  2. onEnter = resume：localStorage 里该文件夹的 activeSession 有 sid，且服务端存在、未删除、未归档 → 恢复它
  3. resume 但该会话超过 7 天未更新，或条目 > 60 → 不硬恢复，降级为 choose 卡片
  4. 没有 active sid → 取该文件夹最近更新的 active 会话 → 走 2/3
  5. 一个 active 会话都没有 → 空态卡片（只有「新建会话」，最近区为空）
  6. onEnter = new → 新建空会话（今天的旧行为）
```

> 为什么默认 choose 而不是无脑 resume：这是用户拍板（m00413 前的拍板回复）——VS Code 也曾在
> 1.107 默认恢复、1.108 又改回空态（§2.1），说明这是口味问题；阅读器把入口和最近会话放在眼前，
> 让用户点一下决定，既不会“回来发现是空的”，也不会被一个月前的长对话硬塞回来。
> `resume` 档保留给“就是想接着聊”的用户，`new` 档保留旧行为。

**新建会话的触发**（全部显式）：
- 会话头 `＋` 按钮 / 历史面板顶部「新建会话」/ 快捷键 `Ctrl+Shift+N`；
- 空会话上再点新建：不重复建文件，聚焦输入框；
- 新建时：先保存当前 → 换 sid → 清空问答 DOM/内存 → 清“本会话已生成”AI 记录
  → **不立刻写空文件**？→ 保留现状“立刻落盘”（列表可见、实现简单），P1 再优化为“首次发消息才落盘 +
  虚拟当前会话行”。

**删除/归档当前会话后的回退**：优先“最近更新的 active 会话”；没有则新建空会话。

### 3.6 会话内容、AI 功能结果与记忆

**会话内容不变**：`entries/history/ops/teaching/summary` 原样保存；改动只在“meta + 界面”。

**“新建 ≠ 清空”的边界（对齐业界）**：VS Code 明确“新建会话/嵌套会话不会清掉已保存文件、自定义指令、
持久 memory”；Claude Code 的 `/clear` 也是“开新上下文、旧会话已保存、可 `/resume` 回”。

- **新建会话**：只创建新会话；旧会话的内容、位置、AI 结果都留在旧会话里。
  当前“新会话清 AI 功能已生成标记”的口径保留——清掉的是**本会话**的“已生成”状态，不是删除旧结果；
  旧结果通过下面的论文级索引仍可找回。
- **清空会话**：独立动作，只清当前会话内容；**不可恢复**，所以文案要写清楚并建议先导出，
  且不放在主菜单第一层（收进 ⋯ 菜单）。
- **归档会话**：安全中间态，可恢复；比“清空/删除”更推荐用于整理。

**AI 功能结果（P1）**：加一层**论文级结果索引**，只存指针，不复制正文：

```
data/ops-index.json
{
  "v": 1,
  "docs": {
    "<docId>": {
      "<opId>": { "sid": "...", "folderKey": "...", "title": "深入阅读：…",
                  "at": 1730000000, "preview": "前 120 字…", "entryPage": 7 }
    }
  }
}
```

- 生成成功时同时写会话 `ops` 与 `ops-index`（只记最近一条/每个 op）。
- “读懂论文”菜单的点击逻辑变成三段：
  1. 当前会话有 → 定位（现有 `focusExistingResult`）；
  2. 当前会话没有、论文级索引有 → 菜单项显示「在其它会话有结果」，点击弹选择
     「打开那个会话查看 / 在当前会话重新生成」；
  3. 都没有 → 生成。
- “新会话清 AI 记录”的用户口径不变（当前会话仍然不显示“已生成”），但结果不再“消失”。

**教学进度（P1 可选）**：`teaching.walk` 除存会话外，把 `{docId, step, sid, at}` 摘到论文级
`profile`/localStorage；新会话首次打开论文时提示「上次讲到第 N 步（在旧会话）」，点击跳过去。

**记忆分层不变**（`docs/问答与翻译-整体设计.md` §6）：

| 层 | 载体 | 与会话的关系 |
|---|---|---|
| 会话内 | `history` 最近 3 轮 + `summary` 滚动摘要 | 会话私有 |
| 本篇跨会话 | 最近 2 个会话的 `summary`（`loadPaperMemory`） | 仅新会话首轮注入，可关 |
| 长期 | `profile.js` 学习画像 + 长期记忆 | 与会话无关 |

改造后注意：**恢复上次会话时不再注入“本篇之前的讨论”**（当前会话本身有历史），
只有显式新建会话且历史为空时才注入——现有 `if (state.history.length) return` 已保证，不用改逻辑，
但要确认“恢复”路径不误触发。

### 3.7 生成任务与并发

**P0（必要，修缺陷 ③）**：

- 所有会改变当前会话的动作（切换/新建/删除/归档/切文件夹/切论文）统一走一个守卫
  `guardBusyThen(action)`：`state.busy` 时弹应用内对话框「正在生成回答」→ [停止并继续] / [取消]；
  选择停止则 `abortStream('session-switch')` 后再执行。
- 保存顺序固定：`persistSession.cancel()` → 等 `sessionSaveInFlight` → `saveSessionNow()` → 再换 sid。
- `chatVersion` / `globalChatSig` 语义保持不变（切会话必须作废停放视图）。

**P1（体验，对标 IDE“后台继续”）**：

- 任务注册表：`runningTasks: Map<sessionKey, { abort, entry, sid, folderKey }>`；
  键 = `<folderKey>:<sid>`。切换会话/文件夹只“取消绑定 UI”，不 abort。
- 每会话独立 DOM（参考 `docs/多标签工作区-设计.md` §4.7.3）：切走时把当前 `.ai-body` 摘下保留，
  切回挂回；冷会话切回时从服务端重建。只保留最近 3 个 + 有任务的 body。
- 任务完成时：若其会话不是当前会话 → 更新列表状态为未读 + 轻 toast「『会话名』的回答已完成」（可关）；
  写盘走对应会话，不写当前会话。
- 最终一致：`/api/session` 保存的是该会话整包内容（前端持有会话运行时数据），不会串写。

**P2（多窗口）**：`POST /api/session` 带 `contentRev`；服务端比对文件里的 `contentRev`，
不一致返回 409 + 服务端当前 rev/hash；前端提示「这个会话在另一个窗口被修改过」→ [重新载入] / [覆盖保存]。
（VS Code 的 “This chat is open in another app” 是同一问题的完整版：第二端降级只读、
阻断发送/排队，直到一端退出；Claude Code 则官方警告“两个终端 resume 同一会话会交错写”。
本项目单机单用户，先做 409 提示，P2 再考虑加锁。）

**P2（分叉 / 回退对话）**：消息行操作加「从这里分叉」→ 新建会话，`entries/history` 截到该条（含），
`forkedFrom={sid, at, entryIndex}`；原会话不动。阅读场景：对某条回答换个思路重问。
“回退”只截断对话、不涉及文件（与 VS Code checkpoint 不同——阅读器没有代码改动可回滚）。

## 4. 数据与接口

### 4.1 会话文件 v4（内嵌 meta，向后兼容）

在现有内容之上新增顶层字段（`security.js:427` 的 `checkSession` 已允许额外字段；
Rust `limits::check_session` 只查数组/大小，也不用改校验逻辑）：

```jsonc
{
  "v": 4,                              // 新增：结构版本（旧文件无此字段 = 1）
  "folderPath": "NLP/Transformer",     // 新增：所属文件夹相对路径（'' = papers 根）
  "title": "为什么 T2T 的 token 要 +1", // 新增：显式标题（显示优先用它）
  "titleSource": "user",               // 新增：auto | user | ai
  "createdAt": 1730000000000,          // 新增：首条内容时间（旧文件用文件 birthtime 兜底）
  "updatedAt": 1730000009999,          // 语义修正：只在内容变化时更新（见 §4.3）
  "lastOpenedAt": 1730000011111,       // 新增：最近打开（打开时 PATCH，用于“最后打开”显示）
  "pinned": false, "pinnedAt": 0,      // 新增
  "archived": false, "archivedAt": 0,  // 新增
  "docIds": ["Attention-1a2b3c", "T2T-9f8e7d"],   // 新增：派生（entries[].docId 去重）
  "docTitles": ["Attention Is All You Need"],     // 新增：派生（entries[].docTitle 去重）
  "contentRev": 7,                     // 新增：内容版本（PATCH/内容保存时递增，P2 冲突检测用）
  "entries": [], "history": [], "ops": [], "teaching": null,
  "summary": "", "summaryCovered": 0, "summaryPrompt": "2026.11.4"
}
```

设计说明：
- **为什么不加独立索引文件**：会话数量级 = 每文件夹几十个 × 文件夹数；`/api/sessions` 本来就要逐个
  读文件（现状如此），内嵌 meta 不增加 I/O，且**没有索引与内容不一致的问题**，Node/Rust 改动最小。
  等出现“上千会话/跨文件夹搜索慢”再引入 `sessions-index.json`（P2 备选）。
- **为什么本期不重构存储目录**：业界有 `data/sessions/<id>/meta.json + messages.jsonl`（Claude Code）、
  SQLite 索引（VS Code）等做法，但本项目有两个后端（Node + Rust，exe 内嵌前端）和一份既有测试契约，
  目录结构变更要两边实现 + 迁移 + 双份测试，成本远高于收益；现有会话 payload 上限 4MB、
  写盘已是“临时文件 + rename”原子替换 + 串行链，丢整包的窗口很小；真正的痛点是生命周期与可见性，
  不是容量（见 §1.5）。等会话数上千或跨文件夹搜索明显变慢，再按 P2 上索引；
  JSONL 追加写不引入（整包保存是现有前后端契约的一部分）。
- **schema 版本**：`v` 字段必须存在；读取时 `v < 4` 走派生补全；遇到 `v > 4`（未来版本）→
  只读打开并提示，不静默覆盖（参考 Claude Code 把 transcript 格式当内部实现、跨版本会变的教训）。
- `createdAt` 旧文件兜底：Node `fs.stat` 的 `birthtime`（Windows 支持）→ 失败用 mtime；
  Rust `metadata.created()` → 失败用 `modified()`；再失败用 `updatedAt`。
- `title` 缺省派生规则（服务端，保证列表直接可用）：
  第一条 `kind=user` 的 `entries[].text` → 去掉开头 `【…】`/引用行 → 折叠空白 → 截 28 个字符；
  没有 user 消息时用 `preview`；全空 → `''`（前端显示「未命名会话」）。
- meta 更新只走 `PATCH`（小请求），避免整包读改写放大冲突。

### 4.2 接口设计

**扩展**：`GET /api/sessions`（Node `server.js:2002`，Rust `api.rs:1362`）

| 参数 | 值 | 说明 |
|---|---|---|
| `doc` | `folderKey` | 查本文件夹；`scope=all` 时可省略 |
| `scope` | `folder`（默认） \| `all` | `all` = 扫 `session-folder-*.json` 全部文件夹（列表用） |
| `archived` | `0`（默认） \| `1` \| `all` | 是否包含已归档；面板“已归档”区用 `1` |
| `q` | 字符串 | 标题/预览子串匹配（P0）；P1 扩到正文全文；大小写不敏感，返回 `match` 摘要 |
| `limit` | 数字（默认 200，上限 500） | `scope=all` 时的保护 |

响应（旧字段保留，新增字段在前端使用）：

```json
{ "sessions": [ {
  "sid": "", "title": "为什么 T2T 的 token 要 +1", "titleSource": "auto",
  "count": 12, "turnCount": 6, "preview": "……",
  "createdAt": 0, "updatedAt": 0, "lastOpenedAt": 0,
  "pinned": false, "pinnedAt": 0, "archived": false, "archivedAt": 0,
  "docIds": ["…"], "docTitles": ["…"],
  "folderKey": "folder-1a2b3c4d", "folderPath": "NLP/Transformer",
  "hasAttachments": true, "contentRev": 7, "v": 4
} ] }
```

**新增**：`PATCH /api/session?doc=<folderKey>&sid=<sid>`

```jsonc
// 请求（只允许白名单字段；每个字段有长度上限）
{ "title": "实验部分讨论", "titleSource": "user", "pinned": true,
  "archived": false, "lastOpenedAt": 1730000011111 }
// 响应
{ "ok": true, "meta": { "title": "…", "pinned": true, "updatedAt": 0, "contentRev": 7 } }
```

- 实现：读内容 → 合并 meta → 串行写盘（Node 用 `writeChain`；Rust 用 `store::write_json` 的现有锁）。
- 文件不存在 → 404（不自动创建，避免幽灵会话）。
- 归档当前会话后，前端负责切到下一个会话并刷新列表。
- 多文件夹“归档/置顶/重命名”都需要 `doc=<folderKey>`；从 `scope=all` 列表里操作跨文件夹会话时，
  前端先展示提示（P0 只允许“打开看看”，重命名/归档要求切到该文件夹；P1 放开）。

**新增（P0，文件夹改名/移动迁移）**：`POST /api/sessions/move-folder` body `{ from: "folder-旧", to: "folder-新", folderPath }`
—— 文件夹改名/移动时复制会话文件到新键（不删旧，成功后再由前端清理/或保留为备份），
详见 §4.4。Rust 同构。

**删除**：`DELETE /api/session?doc=&sid=` 不变（同时删附件目录、删除索引项）。

**不做**：会话创建接口（仍用空内容 `POST /api/session` 落盘）、独立 meta 文件、列表分页游标。

### 4.3 时间语义修正（缺陷 ⑥）

现状 `buildSessionPayload` 无条件 `updatedAt: Date.now()`，而打开论文、切文件夹、关页都会存一次，
导致：**只是浏览别的论文，旧会话就被标成“刚刚”并排到最前**。

修正：

| 字段 | 何时更新 |
|---|---|
| `updatedAt` | 仅当内容变化：新增/修改条目、清空、重试、摘要更新、ops 变化。实现：保存前比较内容指纹（条目数 + 最后一条文本 + history 长度 + summary 长度/summaryCovered），不同才 `Date.now()`，否则沿用文件里的旧值 |
| `lastOpenedAt` | 打开/切到该会话时（PATCH；节流到每会话 1 分钟） |
| `pinnedAt` / `archivedAt` | 对应动作时 |
| `contentRev` | 每次内容变化时 +1（meta 变更不 +1），用于 P2 冲突检测 |

列表排序用 `updatedAt`；“X 分钟前”显示 `updatedAt`；hover 提示可显示“最后打开”。
`buildSessionPayload` 需把「文件里读到的 updatedAt」带入比较（`state.sessionUpdatedAt` / `_fileUpdatedAt`）。

### 4.4 文件夹改名 / 移动 / 删除时的会话迁移（缺陷 ⑦）

现状：`folderKey = folder-<fnv1a8(路径)>`，文件夹改名 = 换键 = 会话失联。

处理（P0 只做“改名/移动”迁移，删除保留）：

1. `startInlineRename` / `moveItem(folder)` 成功后：
   - 计算 `oldKey = folderKeyOf(旧路径)`、`newKey = folderKeyOf(新路径)`；
   - 若 `oldKey !== newKey`：`POST /api/sessions/move-folder {from,to,folderPath:新路径}`；
   - 服务端：列出 `session-<oldKey>-*.json`，逐个写 `session-<newKey>-<sid>.json`
     （已存在同 sid 则跳过），更新每个文件 meta 的 `folderPath`；**不删旧文件**（保留兜底，
     P2 再提供清理入口）；
   - 前端：更新 `reader.activeSession` 里的键：`map[newKey] = map[oldKey]`，删旧键；
   - `state.currentFolder = 新路径`、`persistCurrentFolder()`（现在改名后不更新，是同一个 bug 的一半）。
2. 移动文件夹（`moveItem` 的 folder 分支）同理。
3. 删除文件夹：会话文件保留（非破坏），历史面板 `scope=all` 里以 `folderPath` 显示；
   行菜单提供「删除会话」（P1）与 P2 的「清理已失效文件夹的会话」。
4. 外部（资源管理器里）改文件夹名：无法感知，不做迁移；`scope=all` 里文件夹名对不上时
   显示“（文件夹已不在）”，会话仍可读内容、可导出、可删除。

### 4.5 Node / Rust 双后端实现要点

| 逻辑 | Node（server.js） | Rust（desktop/src/api.rs） |
|---|---|---|
| 列表 meta 派生 + 新字段 | `sessions` handler 内加 `metaOf(data, fileName)` 辅助函数 | `sessions` 函数内加 `meta_of(&Value) -> Value` |
| 派生标题/预览/时间戳 | 同一套规则写常量（截断长度、前缀剥离） | 逐字对齐（测试 `desktop.mjs` 对比网页版返回） |
| `PATCH /api/session` | 新增分支：`readDataFile` → `mergeMeta` → `writeDataFile` | 新增分支：`store::read_json` → merge → `store::write_json` |
| `scope=all` | `fsp.readdir(DATA_DIR)` 过滤 `session-folder-` | `store::list_data_files()` 过滤 |
| `move-folder` | 新增 handler：copy + patch `folderPath` | 同构 |
| 体积限制 | `security.js` 的 session 限制不变；PATCH 额外限 title ≤ 120、folderPath ≤ 400 | `limits::check_session` 不变；PATCH 复用 `check_title` 之类小函数 |

**一致性测试**：`test/desktop.mjs` 对隔离副本调同一组接口（GET/PATCH/scope=all/move-folder），
逐字段对比网页版（除时间戳容差），防止两边漂移。

### 4.6 迁移与回退

**数据迁移（全部非破坏）**

| 旧数据 | 处理 | 时机 |
|---|---|---|
| 旧会话文件（无 meta） | 读时派生：title/preview/createdAt(t 用 birthtime|mtime)/count；首次 PATCH 时落盘 | 列表请求时（不批量写） |
| 旧 `_fileEntries`/history/summary | 不动 | — |
| `reader.activeSession`（按 folderKey） | 直接复用；键在文件夹改名迁移时同步改 | 改名时 |
| 旧按文档会话 / 旧全局会话 | 现有 `migrateLegacySession` / `migrateGlobalSessionsToFolders` 保留（一次性标记），不再扩展 | 不变 |
| 空会话文件 | 保留；列表里“未命名会话”；P2 提供「清理空会话」 | — |

**行为回退开关**（配置写到 localStorage，避免设置页改动）：
- `reader.session.onEnter`：`'choose'`（**默认，用户拍板 B**，空态选择卡片）/ `'resume'`（自动恢复上次）/
  `'new'`（回到“进入文件夹总是新会话”旧行为，给用户适应期），见 §3.4；
- `reader.session.historyPanel = '0'` → 用旧胶囊菜单（P0 保留旧渲染函数 1 个版本，P1 删除）。

**回滚点**：动 `public/js/app.js` 前先 `git commit`（AGENTS.md 约定），前端改动集中在一个新文件
`public/js/sessions.js`（约 600–900 行：状态、渲染、接口、迁移），`app.js` 只做接线，便于整体回退。

## 7. 风险与边界

| 风险 | 等级 | 缓解 |
|---|---|---|
| 默认选择卡片被用户忽略、以为不能续聊 | 中 | 卡片把「继续上次」放在主按钮位置 + 显示条数/时间 + 最近列表；设置里可切 `resume`；首次使用给一句提示 |
| 改 `app.js` 大段会话逻辑引发回归（停放视图/译文覆盖是历史重灾区） | 高 | 逻辑搬进新 `sessions.js`；改前 commit；先跑 `tabs/attachments/memory-session` 回归 |
| `updatedAt` 指纹判断写错导致时间一直不更新或一直更新 | 中 | 指纹定义写死并加单测（Node/Rust 各一）+ 手验两种路径 |
| 文件夹改名迁移写一半失败 | 中 | 只复制不删旧；失败保留旧文件并 toast 可重试；幂等（同 sid 跳过） |
| Rust/Node 行为漂移 | 中 | `desktop.mjs` 一致性断言；Rust 侧实现只依赖已有 `store` 能力 |
| 会话数增长后 `scope=all` 慢 | 低 | `limit` 200 + 只读首层 JSON；P2 再上索引 |
| 用户已有的旧测试套件（global-session 等）与新版冲突 | 中 | 明确“重写而非兼容”，在 PROGRESS 记录；旧断言先存档到 `test/archive/` 或 git 历史 |
| 多窗口静默覆盖（P0 未解决） | 低（单机单用户） | P2 加 409；P0 文档提示“同一会话别开两个窗口” |

**明确不做**：嵌套会话、自定义分组、跨设备/云端、把译文并入会话、AI 功能结果全文进列表、
按论文拆成多份会话（改动集中在 `meta.docIds` 过滤，未来可加）。
