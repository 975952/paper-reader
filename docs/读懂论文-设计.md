# 「读懂论文」AI 模块设计（评审稿）

> 状态：**待你拍板，尚未改代码。**
> 配套材料：[`读懂论文-示例回答.md`](读懂论文-示例回答.md) —— 四项能力 + 两个交互续写的**真实模型输出**（Attention Is All You Need，15 页，39,865 字），用来判断「这样回答是否真的帮人读懂」。

## 1. 结论先行

### 1.1 旧模块为什么「看不懂」

现状是 `public/js/ops.js` 的 4 个文档级操作 + 右侧问答区一段静态回答（`app.js` 的 `initOps()` / `runOperation()`）：

| 现在的入口 | 提示词实质 | 对「我还没读懂」的人 |
|---|---|---|
| 一句话速览 | 「只输出三行，每行一句话，对应问题/方法/结论，不要标题、不要展开」 | **压缩掉了理解链条**：只剩术语和结论，不知道问题从哪来、为什么难 |
| 方法拆解 | 输入输出、编号步骤、设计选择 | 默认读者已经懂领域和术语，讲得像目录 |
| 实验够不够支撑结论 | 数据集/基线/指标/消融逐项核对 | 这是**读完并读懂之后**才用得上的任务 |
| 局限与可疑之处 | 作者承认的 + 你怀疑的 | 同上，而且容易带着评判口吻，进一步打击读下去的信心 |

共同问题：

1. **只有结论，没有教学**：没有「先给直觉、再给定义」，也没有「术语就地解释」。
2. **没有从当前的「不懂」出发**：不知道用户卡在哪、会什么、不会什么。
3. **回答是静态终点**：不能点页码、不能「继续下一步」、不能「换个更简单的说法」；追问要用户自己想问题。
4. **一次性输出**：没有把「读懂」拆成可持续的多轮。

### 1.2 新模块怎么改

- **名称**：`读懂论文`（顶栏 ✦ 按钮保留，图标不变；鼠标悬停说明改掉）。
- **菜单只有 4 个入口**（结果仍进现有右侧问答区）：

| 入口 | 解决的问题 | 输出形态 |
|---|---|---|
| **先给我讲明白**（默认，排第一） | 这篇论文到底在干什么？ | 5 段入门讲解，几分钟读完；问题 → 教学例子 → 旧办法为什么不行 → 作者的办法（先直觉后术语）→ 结果与边界 |
| **我需要先懂什么** | 我卡在哪、缺哪些前置知识？ | 只列 3–5 项；每项：是什么 / 本文为什么需要 / **读到什么程度就够** / 现在必须懂 or 之后学 |
| **带我一步步读** | 从哪开始？跟上方法 | 先给 5–7 步路线（按理解依赖排，不按章节），**每次只讲一步**，可点「继续下一步」 |
| **讲懂图表与公式** | 文字懂了，图/公式跟不上 | 默认从**当前页**挑一个对象；图讲表达与看图顺序，表讲指标与比较条件，公式讲符号与运算；区分事实/作者解释/AI 推断 |

- **深入阅读降级**：原来的「实验够不够支撑结论」「局限与可疑之处」不再占菜单入口，改成「先给我讲明白」等回答末尾的后续建议按钮（提示词保留，结果形态不变）。
- **新增交互**：
  - 回答里的 `〔p.N〕` 变成**可点击页码**，点了跳回原文对应页；
  - 回答底部有轻操作按钮（继续下一步 / 讲简单一点 / 给个例子 / 这个我懂了 / 这里没懂）；
  - 「带我一步步读」的进度随会话保存，重开论文可以接着读。
- **新增学习档案**（回答「要不要做知识库」）：
  - 记录「知识点 + 理解程度 + **具体边界** + 判断依据 + 时间」；
  - AI 只能写「待确认」，**确认只能由用户点**；「讲过了」「继续」都不算掌握；
  - 每次调用模型都注入 **当前时间**，档案条目附「约 N 天前确认」和「是否可能生疏」的代码计算标签；
  - 第一版就做「可查看、可编辑」，但**不做自动判定掌握**。

## 2. 交互总流程

### 2.1 入口菜单（沿用 `#opsBtn` / `#opsMenu`）

菜单头部（新增）：

```text
读懂论文
先建立对这篇论文的整体理解；结果进右侧问答，可随时追问
┌──────────────────────────────────────────────┐
│ 学习档案 · 已确认 8 条 · 2 条待确认 · 最近 10-20 │  ← 点击打开档案
└──────────────────────────────────────────────┘
──────────────────────────────────────────────
✦ 先给我讲明白      几分钟讲清这篇论文在做什么
◈ 我需要先懂什么    只挑读懂本文必需的前置知识，标「现在必须懂」
🧭 带我一步步读      先给路线，每次只讲一步，可继续
📊 讲懂图表与公式    默认从当前页选图 / 表 / 公式，讲清怎么看
```

- 图标沿用 `icons.js` 里已有的 `bolt` / `graduation` / `compass` / `chart`，不引入新资源。
- 没有打开论文时：菜单项置灰并提示「先打开一篇论文」；学习档案入口仍可用（可以提前填自述）。
- 菜单不再出现分组、不再有「更多操作」，实验/局限两个旧入口彻底不在这里。

### 2.2 一条回答的通用结构

复用现有结果区管线（`addEntry` / `streamTarget` / `finishEntry` / 会话存档），所以停止、复制、存笔记、重新生成、恢复历史都免费继承。

```text
┌ role 行：tag = 能力名（先给我讲明白） + 第 N 页 ┐
│ 正文（renderMarkdown：标题/列表/表格/KaTeX/页码按钮）│
│ …                                              │
│ [隐藏的 prt 块 → 程序解析，不显示]              │
├ acts：能力相关按钮 + 复制 / 存笔记 / 重新生成     ┤
└ 可选：来源 / 教学进度元信息                       ┘
```

页码按钮：正文里的 `〔p.3〕`、`〔p.13–15〕` 渲染成 `.page-ref` 小按钮，点击 `jumpToPageWithHistory(N)`；超出总页数或格式不对就保持普通文字。

### 2.3 四个能力的交互细则

#### 2.3.1 先给我讲明白（默认主功能）

1. 点菜单第一项 → 一次调用（材料沿用 `buildDocContext()`：全文不超过 10 万字就按页发全文，超长降级成阅读索引 + 相关段落）。
2. 输出按固定五段（提示词见 §3 / 示例文档）。
3. 完成后按钮：`讲简单一点` `给个例子` `深入方法` `看实验是否撑得住结论` `它有什么局限`。
4. 缓存：按 `docId + profileRevision + promptVersion` 缓存，「已生成」可重开不花钱；「重新生成」强制重跑。档案变化（用户确认/纠正过）会让缓存自动失效。
5. 失败/停止：沿用现有失败重试、停止保留已生成内容。

#### 2.3.2 我需要先懂什么

```text
点入口
  ↓
一次调用：3–5 项清单（不展开讲）
  ↓
回答后：每项一个按钮「讲第 N 项：<名称>」 + 「大概都懂了，开始读」
  ↓
点某一项 → 第二次调用：单项讲解（接着清单上下文 + 学习档案）
  ↓
回答后：[这个我懂了] [这里没懂] [讲下一项]
  ↓
「这个我懂了」→ 写入学习档案（confirmed，lastConfirmedAt = 现在）；「这里没懂」→ 追问重讲，不推进
```

- 学习档案在源头就影响清单：已经确认且边界够用的项→模型跳过或一句带过；**待确认**项→不能当作已掌握；**超过 90 天**没确认→可能生疏，先简短确认。
- 点「讲第 N 项」时，把「清单 + 选中项 + 学习档案」一起发；回答结尾必须**回到论文原文**（章节/页码），这是旧功能没有的一步。
- 缓存同 2.3.1（清单与单项讲解都受 `profileRevision` 影响）。

#### 2.3.3 带我一步步读

1. 首次：一次调用 → 5–7 步路线（只写步骤名 + 章节 + 页码，不展开）+ **只讲第一步**（现在要弄懂的问题 / 去读哪里 / 核心解释 + 小例子 / 和下一步的联系）。
2. 教学状态（新增，随会话存档）：

   ```js
   state.teaching.walk = {
     docId, sid,
     route: [{ title, section, pages }],  // 也可直接存路线原文
     step: 1,                             // 已讲到第几步
     messages: [...],                     // 首次 prompt + 各步回答，用于续步
     updatedAt: '2026-10-24T12:30:00+08:00',
   };
   ```

3. 按钮：`继续下一步` `讲简单一点` `给个例子` `重新规划路线`。
   - 继续：追加一次调用，消息历史 = 首次请求 + 已讲各步 + `继续下一步`，**只讲下一步**，不重复、不展开后面。
   - 讲简单/给例子：同一套续讲调用，但只重讲当前步，不推进 `step`。
4. 自由追问：普通输入框提问照常走 `send()`，但会带一个 `【当前教学进度：第 N 步 · <步骤名>】` 的上下文块；回答后进度不变，**不会擅自推进下一步**。
5. 不设答题关卡：不做测验、不要求用户复述。
6. 菜单项若已有进度，标「进行到第 3 步」；会话恢复后点它 = 接着读（`重新规划路线` 才从头）。
7. 教学式回答不进缓存（交互性太强），但状态会存档。

#### 2.3.4 讲懂图表与公式

点入口后**先选对象**（不默认分析整页/整篇）：

```text
当前页候选识别（程序，见 §6.2）
  ├─ 0 个 → 「这一页没识别到图/表/公式编号」+ [看全文图表清单] [用框选截图问]
  ├─ 1 个 → 直接讲
  └─ ≥2 个 → 小选择器：图 2 · Scaled Dot-Product Attention / 公式 (1) / … + [看全文清单]
```

- 当前页没有时再给**全文图表清单**（从整篇文本里扫 Figure/Table 标题行），点某一项 = 跳到那一页 + 分析；不提供「分析全部图表」。
- 解释规范（提示词强约束）：
  - 图：先说想表达什么 → 坐标/图例/曲线/模块分别是什么 → 建议按什么顺序看；
  - 表：先说比较对象 → 每列指标含义、数值往哪个方向算好 → 在什么条件下比 → 能得出什么结论；
  - 公式：先说计算/描述什么 → 逐个符号 → 运算关系 → 必要时一组简单数值走一遍。
- 必须区分 `① 图表直接展示的事实 ② 作者正文里的解释 ③ 我的推断`；抽取文本缺图内标签/符号/单位时**明确说缺什么**，不补造。
- 回答后按钮：`换一个对象` `讲简单一点`；引用页码可点。
- 不收缓存（对象/页不同）。

#### 2.3.5 深入阅读（不出现在菜单）

- 旧 `evidence` / `limits` 的提示词保留为 `ADVANCED_OPS`，只由回答末尾的按钮或 `prt` 块触发：
  - 「看实验是否撑得住结论」→ `runOperation('evidence')`
  - 「它有什么局限」→ `runOperation('limits')`
- 结果 tag 与缓存行为不变；位置仍在右侧问答区，接在触发它的回答下面。

## 3. 四项能力的提示词

完整 system prompt（含通用规矩）见 [`读懂论文-示例回答.md`](读懂论文-示例回答.md)。落点：**新建 `public/js/teaching.js`**，`ops.js` 只保留「菜单目录 + 深入阅读两条」。

通用规矩（新建 `TEACHING_COMMON`）：

1. 只依据给定的论文全文作答，找不到就说「给出的内容里没有提到」。
2. 论文事实标 `〔p.N〕`（`N` 必须是材料里真实出现的页码；范围写 `〔p.N–M〕`）；参考文献 `[27]` 不是页码。
3. 中文；术语首次出现保留英文原词并用一句人话解释，不用更陌生的术语解释术语。
4. 公式用 `$...$` / `$$...$$`。
5. 先直觉后定义；不客套、不复述题目、不堆「首先/其次」空架子。
6. **当前时间** + **学习档案块**（见 §4）固定注入。

每个能力再追加自己的任务段（示例文档里有全文），关键约束：

| 能力 | 必须做 | 明确禁止 |
|---|---|---|
| 先给我讲明白 | 五段固定顺序；教学例子要标注；结果要写「还不能确定什么」 | 压成一句话、翻译摘要、把教学例子说成论文实验 |
| 我需要先懂什么 | 3–5 项；每项给「读到什么程度就够」的可检查边界；区分必须懂/之后学 | 泛泛学科清单；展开讲解（点开才讲） |
| 带我一步步读 | 路线按理解依赖排序；首轮只讲第一步；每步有「和下一步的联系」 | 一次生成整篇长讲解；机械按章节顺序 |
| 讲懂图表与公式 | 区分事实/作者解释/推断；缺信息要明说 | 补造图内文字、默认分析整篇所有图表 |

**篇幅（实测发现）**：模型对「1200–1600 字」不敏感，实际输出约 1.5–1.7 倍（示例里「先给我讲明白」2553 字、「讲懂图表」3045 字）。两种处理，需你选：

- **A（推荐）**：接受默认较长（约 2000–2600 字，5–6 分钟读完），但加一个「再压短」按钮（同一回答二次调用，只做压缩）；细节正确性优先。
- **B**：把提示词目标降到 800–1000 字，接受信息量变少；更符合「快速入门」，但可能又变成「太压缩」。

## 4. 学习档案（回答「要不要做知识库」）

### 4.1 判断

**值得做，但第一版做「学习档案」，不做「知识库」。**

- **值得做的原因**：同样解释注意力，起点不同讲法完全不同；档案直接决定「我需要先懂什么」跳过什么、「带我一步步读」从哪开始。
- **不做知识库的原因**：「知识库」隐含两件事——结构化领域知识 + 自动判定掌握程度。自动判定不可靠（讲过一次 ≠ 会用；说「继续」 ≠ 懂了），**记录错了比没有记录更糟**，会让 AI 跳步。
- **第一版原则**：
  1. 记录的是「**具体边界**」而不是一个「已掌握」的勾：会调用 / 懂原理 / 能实现 / 能推导是不同能力。
  2. **AI 只能建议，确认只能由用户点**：AI 判断用户「似乎已经理解」只能写成 `pending`（待确认），不参与「跳过讲解」。
  3. **每条写入都带时间**；后续每次回答把当前时间 + 每条的确认时间一起交给模型（用户明确要求）。
  4. 可查看、可编辑、可删除；第一版不做自动测试/测验。

### 4.2 数据模型

文件：`data/learning-profile.json`（全局一份，跨论文、跨会话；不进 git / 不进 papers / 不进打包）。

```json
{
  "version": 1,
  "revision": 12,
  "updatedAt": "2026-10-24T12:31:05+08:00",
  "selfReport": "学过 PyTorch，写过 CNN，矩阵运算基本会，概率论比较薄弱",
  "selfReportAt": "2026-10-20T21:14:00+08:00",
  "items": [
    {
      "id": "kp-1730000000000-a1b2",
      "topic": "残差连接",
      "aliases": ["residual connection", "Residual"],
      "level": "理解基本原理，能够实现",
      "boundary": "维度一致时的相加能解释；维度变化时的投影不熟",
      "basis": "user_confirmed",
      "status": "confirmed",
      "createdAt": "2026-07-20T20:05:00+08:00",
      "updatedAt": "2026-07-20T20:05:00+08:00",
      "lastConfirmedAt": "2026-07-20T20:05:00+08:00",
      "source": { "docId": "attention-arxiv-8f181016", "paper": "attention-arxiv.pdf", "capability": "prereq" },
      "note": ""
    },
    {
      "id": "kp-1730100000000-c3d4",
      "topic": "多头注意力",
      "aliases": ["Multi-Head Attention", "MHA"],
      "level": "能说清原理",
      "boundary": "知道并行多组投影再拼接；拼接后 W^O 的形状没算过",
      "basis": "model_inferred",
      "status": "pending",
      "createdAt": "2026-10-24T12:28:00+08:00",
      "updatedAt": "2026-10-24T12:28:00+08:00",
      "lastConfirmedAt": null,
      "source": { "docId": "attention-arxiv-8f181016", "paper": "attention-arxiv.pdf", "capability": "visual" },
      "note": "AI 观察：用户能跟上多头流程，但没追问形状"
    }
  ]
}
```

| 字段 | 含义 |
|---|---|
| `topic` / `aliases` | 知识点名称与别名（用于和论文文本匹配） |
| `level` | 理解程度：听得懂 / 理解原理 / 能实现 / 能推导（自由文本，不强制枚举） |
| `boundary` | **具体边界**：会什么、不会什么，必须能据此判断「本文够不够用」 |
| `basis` | `user_confirmed`（用户点确认/自己填写）、`user_self_report`（初始自述）、`model_inferred`（AI 观察，仅 pending） |
| `status` | `confirmed` / `pending`。**只有 confirmed 且边界够用，才允许 AI 跳过基础**；pending 一律按不会处理 |
| `createdAt` | 记录**写入**时间（用户要求的时间戳） |
| `lastConfirmedAt` | 用户**最近一次确认/纠正**的时间；pending 为 `null` |
| `updatedAt` | 最近修改时间（编辑边界/备注也算） |
| `source` | 由哪篇论文、哪个能力、哪次阅读写入（便于回看与纠正） |
| `note` | 备注/依据摘要（不存整段对话） |

`revision` 每次写入 +1，用于**让个性化回答的缓存失效**。

### 4.3 时间语义（「写入时带时间」怎么落地）

- **写入即落盘**：用户每次点击（确认、编辑、添加、删除）立刻写文件，不做延迟批量——避免「刚记的丢了」。
- **时间来源**：前端本地时钟，ISO 8601 带时区偏移（如 `+08:00`），由客户端生成；服务端只校验格式、不改写时间。
- **三个时间分开**：`createdAt` 是「这条记录什么时候写的」，`lastConfirmedAt` 是「用户最近一次确认/纠正」，`updatedAt` 是「最近一次任何修改」。三者不能混。
- **展示**：档案里显示绝对时间（`2026-07-20`）+ 相对时间（`约 96 天前确认`），相对值由代码算。
- **不自动续期**：讲解一次、用户说「继续」、用户没有反驳——都**不会**更新 `lastConfirmedAt`。

### 4.4 当前时间注入（用户明确要求）

1. **每次 AI 调用**（四项能力 + 普通问答 + 深入阅读）的 system 里固定加一行（前端生成，不用服务端时区）：

   ```text
   【当前时间】2026-10-24 12:31（周六，UTC+8）
   ```

   （翻译、阅读索引这类不涉及时间判断的调用可以不加。）
2. **档案条目附带代码算好的时间标签**（不让模型自己算日期差）：

   ```text
   - 残差连接：理解基本原理，能够实现；边界：维度一致时能解释相加，维度变化时的投影还不熟
     （2026-07-20 确认，约 96 天前确认；超过 90 天未确认 → 按可能生疏处理，先简短确认再跳过）
   - 多头注意力：能说清原理；边界：知道并行多组投影再拼接；W^O 的形状没算过
     （待确认；2026-10-24 由 AI 观察记录，用户尚未确认 → 不能当作已掌握）
   ```

   阈值写死在代码里：

   | 距 `lastConfirmedAt` | 标签 | 对 AI 的要求 |
   |---|---|---|
   | ≤ 30 天 | 较新 | 可以放心按记录讲快 |
   | 31–90 天 | 有一阵没确认 | 可以按记录讲快，但文中用法超出边界时补讲 |
   | > 90 天 | 可能生疏 | 先快速确认，不要直接跳过 |
   | `pending` | 待确认 | 不当作已掌握；讲到时先给一句可回答的确认 |

3. **提示词里的档案使用规则**（固定文本）：

   ```text
   【学习档案 · 只影响讲解深度，不是论文证据】
   1. 已确认且边界够用的，可以讲快、跳过基础铺陈；但本文用法超出所记边界时必须补讲差异。
   2. 待确认的，不能当作已掌握；讲到它时先用一句可回答的话确认。
   3. 超过 90 天未确认的，按「可能生疏」处理，先快速确认；不要用「你之前学过」下结论。
   4. 档案只决定怎么讲，不作为论文事实依据；回答里不要罗列整份档案。
   ```

4. **为什么两个都要**：模型看到「2026-07-20 确认」需要知道今天是几号，才能判断「三个月前」意味着什么；而日期差由代码算好，模型只负责用。只给时间不给标签，模型会算错；只给标签不给当前时间，模型无法处理「最近/今年」这类话。

### 4.5 读取：哪些条目进 prompt

不是整份档案都塞进去（太长、也无关）：

1. 先从论文全文/当前页/当前问题里取文本（小写）。
2. 对每条 `topic` + `aliases` 做匹配：在论文文本里出现（限次计分）×2 + 在问题/选区里出现 ×5。
3. 取分数最高的 8 条；`selfReport` 永远带（自述很短）。
4. 若一条都没匹配上：只带自述 + 一行「档案里还有 N 条与本文无关，未列出」。
5. 整个档案块封顶 **1200 字**，超出按分数截断；条目里超长 `boundary` 截到 200 字。
6. 提示词要求「不要罗列档案」，避免回答变成「档案播报」。

### 4.6 写入：谁在什么时候写

| 触发 | 写入内容 | 状态 | 时间戳 |
|---|---|---|---|
| 首次「简短填一下」 | 一段自述（学过什么、能做什么、哪里薄弱） | 存 `selfReport`，逐字保留 | `selfReportAt` = 现在 |
| 用户点「这个我懂了」 | 对应知识点：`level` 取 AI 建议或「本文所需层面已理解」；`boundary` 取该项「读到什么程度就够」 | `confirmed` | `lastConfirmedAt` = 现在，`updatedAt` = 现在；没有该条目则新建 `createdAt` = 现在 |
| 用户在学习档案里手动添加/编辑 | 用户填的 topic/level/boundary | `confirmed`（用户自己写的就是确认） | 同上 |
| AI 观察（`prt` 块里的 `profile`） | topic/level/boundary 建议 | `pending` | `createdAt` = 现在，`lastConfirmedAt` = null |
| 用户点「这里没懂」 | 当前回答立即换简单讲法（追问）；相关条目可标记为「需再确认」（pending + note） | 不确认、不更新 `lastConfirmedAt` | `updatedAt` = 现在（仅当条目标记改变） |
| 用户说「继续」/「讲过了」 | **不写任何确认** | — | — |
| 用户删除 | 删除条目；或清空整个档案（二次确认） | — | 更新 `revision` |

**冲突处理**：同主题归一化（去空格、大小写、别名）；pending 与 confirmed 同时存在时以 confirmed 为准；用户纠正边界即视为一次新确认。

### 4.7 界面

- **菜单头部**：档案摘要 + 入口（见 §2.1）；没有档案时显示「还没有学习档案 · 花 30 秒建立」；建立不是强制的，跳过也能用（AI 只是不给个性化）。
- **学习档案弹窗**（复用现有 `.modal` 样式）：
  - 顶部说明：只存在本机 `data/learning-profile.json`；AI 只会建议，不会自动判定你掌握了什么。
  - 「我的基础（自述）」textarea + 保存。
  - 「待确认」区：AI 观察到的条目，每条 `[确认掌握]` `[还不会]` `[删除]`。
  - 「已确认」区：topic / level / boundary / 依据 / 最近确认时间；`[编辑]` `[删除]`；`[手动添加一条]`。
  - 底部：`[导出 JSON]`（二期）`[清空档案]`（二次确认）。
- **回答里的轻操作**：
  - 「这个我懂了」只在「单项前置知识讲解」等有明确教学对象的回答上出现；点了写 confirmed 并 toast「已记入学习档案（今天）」。
  - 「这里没懂」→ 立即追问重讲（不推进教学进度），不会先去设置里改档案。
- **设置页**：一个开关「把学习档案用于个性化回答」（默认开）；关闭后不注入、不写入 pending（用户手动编辑仍可用）。

### 4.8 存储与接口

- 文件：`data/learning-profile.json`。写入用现有 `writeDataFile` / `store::write_json`（临时文件 + rename，串行化，失败不覆盖旧文件）。
- Node（`server.js`）：新增
  - `GET /api/profile` → 返回档案（不存在时返回默认空档案）；
  - `POST /api/profile` → 整份替换；校验失败 400，超限 413；响应 `{ ok: true, revision }`；
  - 校验：body ≤ 256KB；`items` ≤ 200 条；每条字符串 ≤ 2000 字；`version === 1`；时间符合 ISO 8601；不合法**不落盘**。
- Rust（`desktop/src/api.rs` + `server.rs`）：同接口、同校验；`limits.rs` 加 `BODY_PROFILE`；路由与 Node 对齐——桌面版是交付物，不能只有浏览器版能用。
- 权限与边界：`data/` 已 gitignore，不进 zip、不进 git；档案只在本机产生、本机读取。

### 4.9 隐私

- 档案只在本机；只有**被选中的少数条目**作为提示词的一部分发给模型，和论文文本走同一个 API，不会额外传出。
- 可整体关闭个性化、可删除；不把聊天原文写进档案（只写主题/边界/依据摘要）。
- 文档里明确告诉用户这一点（弹窗顶部说明）。

## 5. 页码与交互协议

### 5.1 页码引用（新增，改动小、收益大）

- 渲染层把 `〔p.12〕`、`〔p.13–15〕` 替换成 `<button class="page-ref" data-page="12">`，点击 `jumpToPageWithHistory(page, { smooth: true })`（现有函数）。
- 事件用委托绑在 `#aiArea`（流式重绘也不用重绑）；越界页码渲染成普通文字。
- 同时修正提示词：**强制** `〔p.N〕`，不允许「第 N 页」当页码引用（§3 通用规矩第 2 条），解析层再兜底一次。

### 5.2 `prt` 隐藏块（结构化输出协议）

回答正文最后允许追加一个程序用代码块（**模型不输出也能用**，静态按钮兜底）：

````text
```prt
{
  "chips": [
    { "label": "继续下一步", "prompt": "继续，下一步。" },
    { "label": "看实验够不够", "op": "evidence" }
  ],
  "profile": [
    { "topic": "多头注意力", "level": "能说清原理", "boundary": "知道并行多组投影再拼接；W^O 形状没算过", "basis": "inferred" }
  ]
}
```
````

- `chips`：≤4 个；`label` ≤ 10 字；`prompt` 会原样进入输入框发送；`op` 只允许 `evidence` / `limits`。
- `profile`：≤3 条；只能写 `pending`；`basis` 固定 `inferred`。
- 处理顺序：
  1. 流式时：检测到正文末尾出现 ` ```prt ` 的起点就隐藏之后内容；
  2. 收尾时：先 `JSON.parse`；失败 → 丢弃整块（正文照常显示，不把 JSON 露给用户）；
  3. 成功 → 剥掉块、渲染 chips、把 profile 建议写成 pending（去重）；
  4. 存会话与喂历史都用**剥掉块后的正文**，避免污染后续对话。
- 安全：字段白名单；label/prompt 当纯文本渲染；不 eval、不注入 HTML。
- 提示词附协议说明（instruction：只在适合时输出、必须最后一块、正文不要重复它）。

### 6.2 关键实现细节

- **菜单重建**：沿用 `el()` / `iconEl(hasIcon(...))`；菜单头部用独立 class，不破坏现有 `#opsMenu` 定位与「点外部收起」逻辑。
- **档案读取**：启动时 `GET /api/profile` 一次，内存缓存；失败静默（不挡 AI 功能，只在档案弹窗里提示）。写操作乐观更新 + 失败回滚 toast。
- **walk 状态**：跟 `sessionEntries` 一起存进现有 `session-*.json`（新增一个 `teaching` 字段）；恢复会话时读回，菜单显示「进行到第 N 步」。
- **缓存 key**：`${docId}:${opId}:${promptVersion}:${profileRevision}`；`promptVersion` 常量字符串，提示词改了就 +1。
- **图表对象识别**（从 `state.docText`，已有 `===== p.N =====` 分段）：
  - 图/表/算法：按行匹配 `^\s*(Figure|Fig\.?|Table|Algorithm)\s*(\d+)\b[.:]?\s*(.*)$`（大小写不敏感），取标题行；
  - 公式：`/\((\d{1,2})\)\s*$/` 的行 + 前后 200 字含 `=`/`^`/`_`/`softmax` 等数学线索；去重、限条数；
  - 全文清单 = 全部页的标题行集合；点选后先 `jumpToPageWithHistory(page)` 再分析；
  - 识别不到时明确提示，并给「框选截图（视觉模型）」的替代路径。
- **旧会话兼容**：老 tag（「一句话速览」「方法拆解」等）恢复显示逻辑不变；旧 `opsCache` 不删；菜单只显示新四项，旧结果仍能在问答区看到。
- **失败降级**：`prt` 解析失败、档案接口 500、模型没给页码——都不能让回答本身失败；最差是回到「一段纯文字回答」。
- **隐私开关**：关掉个性化后 `buildProfileBlock()` 返回空、`prt.profile` 不落盘；用户手动管理档案仍可用。

### 6.4 验收标准（自动化 + 手工）

**自动化（新增/改写）**

- 菜单：正好 4 项、标题/提示文案/顺序正确、没有 evidence/limits 入口、有学习档案摘要；
- 四项请求：system prompt 各自正确、带 `【当前时间】`、带 `【论文全文】`、任务段正确；
- 学习档案：CRUD、时间戳 ISO 格式、`pending` 不参与跳过（prompt 里可见「待确认」标签）、>90 天标签、`revision` 递增、缓存失效；
- `prt`：合法 JSON → chips 出现且正文不含 JSON；非法 JSON → 正文正常、无 chips、不报错；流式时块不闪；
- 页码：`〔p.3〕` 渲染成按钮、点击跳页、越界不渲染；
- walk：继续下一步带历史、step 递增、进度存档恢复、自由追问不推进；
- 图表对象：当前页 0/1/多对象三态、全文清单、跳页；
- 旧会话恢复、旧 tag 兼容；
- 无 console error / pageerror。

**手工**

- 用 2 篇以上真实论文（建议一篇熟悉的 + 一篇完全陌生的），每项各点一次，按示例文档末尾的 4 个问题判断；
- 关掉个性化开关再点一次，确认回答不再引用档案；
- 改档案后重开同一能力，确认缓存失效、讲法变化。

## 7. 风险与取舍

| 风险 | 取舍 / 缓解 |
|---|---|
| 模型不服从字数 | 接受默认较长（5–6 分钟）或加「再压短」按钮；不为了短牺牲正确性 |
| 模型不输出 `prt` 块 / JSON 坏 | 静态按钮兜底；解析失败只降级，不影响正文 |
| 图内文字抽取不到 | 明确说缺失 + 二期视觉模型截图；不补造 |
| 档案记错导致跳步 | 只有 confirmed 才跳过；pending 不参与；>90 天先确认；可随时编辑；关掉个性化 |
| 提示词/档案块变长 | 论文全文本来就是主要开销；档案块封顶 1200 字、最多 8 条 |
| 缓存与档案不一致 | `profileRevision` 进缓存 key；提示词版本号进 key |
| 新接口要 Node + Rust 双实现 | 已列进 P1 验收；桌面版必须同步，否则 exe 用不了个性化 |
| 旧测试大量断言旧文案 | `ops.mjs` 重写；`qa.mjs`/`context.mjs` 小改；先 `git commit` 再动手（AGENTS.md 惯例） |

## 8. 等你拍板（6 个问题）

1. **篇幅**：默认接受 2000–2600 字（约 5–6 分钟）并加「再压短」，还是把目标压到 800–1000 字？——建议前者。
2. **学习档案第一版就做吗？**——建议做（P1）。
3. **AI 可以自动写「待确认」条目吗？**——建议允许（不确认），否则个性化永远长不出来。
