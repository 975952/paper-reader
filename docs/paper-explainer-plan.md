## 一、为什么是「操作目录」而不是「一个老师」

最初的方案是「一键生成整篇讲解」。调研后否掉了：

- **读论文时想干什么是随时在变的** —— 有时只想 3 秒知道这篇值不值得读，有时要抠公式，
  有时要判断实验站不站得住。一个固定流程必然有一半时候是多余的。
- DeepTutor 的闭环之所以成立，是因为它有**持续的学习目标**（课程、考试）；
  读单篇论文通常没有这个前提，硬套会变成「被盘问」。
- 所以：**把常见需求做成可挑的操作**（同一份材料、不同 system prompt、按需调用、结果可缓存），
  想系统学的时候再开 coach。

### 已经实现的 15 个操作

| 组 | 操作 | 干什么 |
|---|---|---|
| **快速了解** | ⚡ 一句话速览 | 3 句：问题 / 方法 / 结论 |
| | 🗺 阅读路线 | 每节讲什么、精读还是略读、起始页 + 「只有 20 分钟读哪几节」 |
| | ★ 贡献与创新点 | 作者声称的 vs 真正新的，点出哪些只是既有组合 |
| | 🧭 定位与脉络 | 属于哪个方向、站在谁肩膀上、影响了什么 |
| **精读理解** | ⚙ 方法拆解 | 输入输出 / 步骤 / **每个设计选择背后的理由** |
| | ∑ 公式逐符号解释 | 关键公式逐个符号 + 为什么长这样 |
| | 📖 术语表 | 中英对照 + 一句话 + 首次出现页 |
| | 💡 打个比方 | 日常类比 + **类比在哪里失效** + 回到准确定义 |
| **评估判断** | 📊 实验够不够支撑结论 | 数据集 / 基线 / 指标 / 消融 逐项核对 |
| | ⚠ 局限与可疑之处 | 作者承认的 + 你没看出来但该怀疑的 |
| | ⚖ 审稿人视角 | 5 个具体可答的审稿问题 |
| | 🔁 复现要点 | 需要什么、**哪些细节没交代清会卡住复现** |
| **应用延伸** | 🎯 我能用上什么 | 可迁移的做法 + 什么时候不该用 + 最小验证实验 |
| | ✎ 自测题 | 5 道检索题，答案折叠，先自己想 |
| | 🔗 相关工作与后续 | 接下来读哪几篇 + 这个方向后来怎么样了 |
| **模式** | 🎓 Coach（按需开启） | 苏格拉底式多轮：它问、你答、答完才往下讲 |

每个操作 = 一次带独立 system prompt 的调用，共享同一条底线（只依据材料、标 `〔p.N〕`、
不编造、术语留英文）；材料复用已有的 `buildDocContext()`，所以**超长论文自动降级成
「阅读索引 + 相关段落检索」、按 docId 缓存**这些逻辑一份都不用重写。

交互上：结果流进「问答」块并打上操作名，可以接着追问；跑过的操作**再点直接用缓存不花钱**，
菜单里标「已生成」，条目上有「重新生成」。

## 二、Coach 模式：怎么做出「老师」的感觉

Coach 不是「更长的讲解」，而是**换一种交互**：它提问、等你回答，再决定下一步。

### 2.1 调研依据

**DeepTutor（HKU 2026）** [arxiv](https://ar5iv.labs.arxiv.org/html/2604.26962) 的 Interactive Guided Learning 是三段：
`DesignAgent` 按诊断出的薄弱点做学习计划（关键概念 / 前置关系 / 常见误解 / 难度阶梯）
→ `InteractiveAgent` **苏格拉底式多轮：逐步引入、追问、给脚手架提示而不是直接给答案**
→ `SummaryAgent` 收尾并回写记忆。它的评测用「学生视角」的 TutorBench，而不是老师自己按大纲打分。

**IntelliCode（EACL 2026）** [aclanthology](https://aclanthology.org/2026.eacl-demo.10/) 给了工程骨架：
集中式**学习者状态**（掌握度 / 误解 / 复习排期）+ 六个职责单一的 agent（技能评估、画像、
**梯度提示**、课程选择、间隔复习、参与度），**单一写者**保证掌握度更新可审计。
实验结论：**梯度提示能提高任务完成率**。

**Khanmigo 的辅导 prompt** [prompt](https://github.com/ifengtech/AgentRules/blob/main/prompts/Code%20Tutor.md)
是一线产品的行为规范，可直接迁移：先弄清学生卡在哪 → **一次只问一个问题** →
答错先问「你是怎么得到这一步的」→ 给渐进提示不泄露答案 → 警惕反复要提示的低投入 →
学生沮丧时说明「犯错是学习的一部分」。

**学习科学**：自我解释 / 检索练习（所以讲完必须问、必须让你复述）；
示例效应与**专长逆转效应**（所以深浅得跟着水平走，画像不是花架子）；
认知负荷（一次只推进一个概念）。

### 2.2 七个职责单一的调用

| # | 名字 | 输入 → 输出 | 频率 |
|---|---|---|---|
| 1 | 诊断 | 2~3 问（背景/目的/时间）→ 起始难度 | 每篇一次 |
| 2 | 备课 | 索引 + 目录 → 学习计划（每节为什么读/前置/难度） | 每篇一次 |
| 3 | 开讲 | 本节原文 + 画像 → **一个**引导问题 | 每节 |
| 4 | 讲授 | 你的回答 + 本节原文 → 分层讲解 + 一处检查性提问 | 每节多次 |
| 5 | **判答** | 你的回答 + 要点 → 对错判断 + **下一步决策**（加深/提示/换说法） | 每次回答 |
| 6 | 复述 | 你的复述 → 指出遗漏与误解（先让你补，不给标准答案） | 每节收尾 |
| 7 | 复习 | 到期项 → 1 个检索题 + 更新间隔（最简 SM-2） | 每次打开 |

**梯度提示**固定三档，由「判答」选：`① 指方向` → `② 缩小范围/给反例` → `③ 给出关键那一步`；
连续两次没进展就直接给 ③ 再往下走 —— 不能把人卡死。

### 2.3 学习者状态（本地文件）

`data/learner.json`（一个人一份）：`level / goal / minutesPerSession / mastered{概念:0-5} /
misconceptions[] / review[]（dueAt, interval, ease）/ sessions`。
`data/learn-<docId>.json`（一篇一份）：学习计划、每节进度、复述记录、当前停在哪。
掌握度**只有「判答」能改**，每次改动记一行原因，可审计，并提供「重置画像」。

### 2.4 界面

右栏「老师」块，是一条**对话**而不是一篇文章：顶部显示进度与复习队列；老师在等你回答；
`[不懂，给点提示]` `[换个说法]` `[这节我会了，下一节]` `[跳原文]`；每个论断后的 `〔p.N〕` 可点跳原文。

### 2.5 必须写进 system prompt 的规矩

1. 不直接给答案，先问再给梯度提示；2. **一次只问一个问题**，一次只推进一个概念；
3. 先判断卡在哪一步；4. 答错先问「你是怎么得出这一步的」；
5. 按画像调深浅（新手给完整示例+脚手架，熟练者给要点和边界）；
6. 事实必须能在本节原文里找到并标 `〔p.N〕`；7. 不奉承，反馈要具体；
8. 卡住时换角度而不是重复；9. **一轮最多 6 句**。

## 四、测试计划（`test/teacher.mjs`）

`/api/chat` 用桩，断言的是**行为约束**而不只是「有输出」：

1. 诊断：首轮只问一个问题；
2. **不直接给答案**：构造「用户答错」的回合，断言下一轮出现提示性措辞而不是完整结论；
3. **一次一个问题**：教师回合里问号 ≤ 1；
4. 计划与 `viewer.getOutline()` 对得上，`〔p.N〕` 可点可跳；
5. 掌握度只由判答写：答对上升、答错进 misconceptions；
6. 进度持久化：关掉再打开接着上次那节；复习队列到期项数正确；
7. 复述不过关不放行；
8. 无 Key / 401 → 复用已做好的「API Key 失效」提示；
9. 扫描版 PDF → 明确说抽不出文字，不做假讲解。

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| 模型忍不住直接给答案（最常见） | prompt 写死 + **测试里专门断言这条**；必要时后处理检测「答案泄露」 |
| coach 多轮成本 | 每轮只带「本节原文 + 画像摘要 + 最近 4 轮」；面板显示已用调用数 |
| 掌握度乱涨 | 单一写者 + 每次改动记原因 + 可重置 |
| 只想「讲给我听」 | 保留 `[直接讲]` 一键跳过提问 —— 不强迫交互 |
| 操作太多挑花眼 | 菜单首屏只放速览 / 阅读路线 / 方法拆解 / 术语表，其余仍按 4 组收进默认收起的「更多操作」；每项一句话说明，跑过的标「已生成」 |
