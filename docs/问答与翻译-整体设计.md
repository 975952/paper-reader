> 状态：**已实施**（设计稿 2026-11-01；P0/P1/P2 当日落地，P3「OCR 转录缓存」按调研结论排在后续轮次）。
> 对应 `problems.txt` 的五项改进与「测试不要打扰正在使用的应用」的要求；落地验收见 §10。
> 阅读顺序：§1 现状核对 → §2 结论先行 → §3–§7 分项设计 → §8 测试隔离 → §9 分阶段实施 → §10 实施记录。

## 1. 用户口径（problems.txt 原文摘要）

1. **扫描版 PDF**：第一次打开时判断类型；若无文本层，问答时上下文默认用**图片**（页面图）或全文；“读懂论文”结果进右侧问答栏，每一项都能接着追问。
2. **右栏文本可操作**：问答区与翻译结果里的文字，要和正文文本一样有「加入问答区」「直接解释」。
3. **记忆**：同一会话是否记得前文、是否一起发给模型；要一套**全局记忆系统**，参考 Codex 桌面应用。
4. **PDF 构成扫描 + OCR**：打开时扫描一遍，标出哪里是文字、哪里是图；图片里的文字/手写文字也要能识别。先调研评估现成方案。
5. **整体设计**：综合以上，决定问答与翻译最终以哪种形态改。
6. **测试/构建不要打扰用户**：不要反复关掉用户正在用的应用；不要弹出窗口抢到最前面。

|---|---|---|---|

| 3 | 论文内跨会话 | 会话摘要落盘；新会话首轮注入「这篇论文之前的讨论摘要」，可清除 | P2 |

| 6 | 测试/构建隔离 | 构建与测试**绝不按进程名杀进程**；验收 exe 用沙箱副本 + `--background`（不抢焦点、不占前台）；测试用独立端口与独立数据目录 | P0 |

**不改的**（避免过度设计）：

- 不做向量数据库/嵌入检索：论文级检索仍用「页码切片 + 词频」，够用且零依赖。
- 不把论文全文常驻发给模型：扫描件用采样页图 + 索引，不逐页全传。
- 不自动写「用户画像事实」：学习记忆只按现有证据规则提取；全局记忆的**可编辑文本只由用户写**。
- 不为测试单独做一个无窗口模式：原生窗口验收仍有价值，只要求它「不抢焦点」。

## 3. 现状核对（代码事实，2026-10-31 基线 `0bd421d`）

### 3.1 PDF 与扫描件

- 文本来自 PDF.js 文本层：`pdfview.js` 的 `getPageText()`（p.1415）与 `getAllText()`（p.1438），整篇按 `===== p.N =====` 拼接。
- `openDoc()`（`app.js` p.2705）加载后按需读取：默认不抽全文，用户选「整篇论文」才 `warmDocText()`；问答 `buildDocContext()`（p.6764）超 10 万字降级成「阅读索引 + 相关段落」。
- **扫描件现状**：文本层为空 → `buildDocContext()` 返回 `null`，问答只剩当前页上下文（也为空）；`sendScopeText()` 显示「整篇论文暂不可提取」；README「已知限制」写着「扫描版 PDF 没有文本层，划词不可用，需要用框选交给视觉模型」。
- 唯一的视觉入口是框选截图：`captureRegion()`（`pdfview.js` p.1704）→ 图片附件 → 消息里拼 `image_url`。
- **视觉模型配置是断的**：`visionModel` 在 `config.json`、设置白名单、预设里都存在，但 ① 设置页没有输入框；② 前端请求永远用主模型；③ 服务端 `/api/chat` 只读 `config.model`，且请求体里的 `model` 属 `CHAT_FORBIDDEN`（`security.js` p.122）。所以带图请求实际发给主模型。

### 3.2 右栏文本

- 划词气泡 `#bubble`（`index.html` p.213，`app.js` `initSelection()` p.3348）只绑定 `#viewer` 的 PDF 文本层选区；`viewer.getSelectionInfo()` 只查正文 span。
- 右栏 `.msg .text`（问答回答、解释、教学结果、译文条目）选中后没有任何操作入口；`doExplain()` / `addToChat()` 本身不依赖正文 `box`，可以直接复用。
- 已有的 `docs/右栏交互增强-设计.md`（2026-10-31，待评审）就是本项的设计，本文件吸收并扩展它。

### 3.3 记忆

- **同一会话**：`state.history` 每轮追加 `readingTurn()`（问题 + focus + guidance + 回答），最多 80 条、每条 ≤12000 字，随会话 JSON 落盘；**发给模型的只有最后 6 条**（`historyMessages()`，`reading-context.js` p.101），约最近 3 轮。更早内容不发，但用户曾明确说过的讲解偏好（`guidance`）会从整段历史里找回来。
- **切换/新建会话**：`state.history = []`，互不继承；同一篇论文的不同会话彼此不知道对方聊过什么。
- **跨论文/长期**：后台学习记忆（`learning-memory.js` + `profile.js`）在每次问答/教学后异步提取「知识边界」与「持续偏好」，存 `data/learning-profile.json`，请求时按相关度注入 ≤1200 字。它只回答「用户会什么/喜欢怎么讲」，不记「这篇论文讨论过什么」，也**没有用户可编辑的长期记忆**。
- 结论：用户问的「同一会话有没有前文记忆」——**有，但只有最近 3 轮**；全局记忆只有学习画像，没有 Codex 式「全局说明 + 会话沉淀」。

### 3.4 测试与构建对用户的干扰

- `desktop/build.bat` 第 48–52 行：按**进程名**强杀 `论文阅读器` / `paper-reader` / 同标题进程 → 会关掉用户桌面正在使用的应用（本机当前实例 PID 64448 正在运行）。
- `test/desktop.mjs` 第 28–48 行：先 `taskkill /IM paper-reader.exe`，再按 exe 路径 `Stop-Process` 并轮询「残留实例」→ 同样会杀用户实例；随后直接启动根目录交付 exe（`spawn(EXE)`，无 `windowsHide`、无端口隔离参数）。
- `test/qa.mjs`、`test/profile.mjs` 的 exe 后端直接 `spawn(ROOT/论文阅读器.exe)`；`sidebar-reopen.mjs`、`translation-layout.mjs` 已先复制 exe 再启动（正确做法），但没有「不抢焦点」参数。
- 交付 exe 的窗口创建（`desktop/src/window.rs` p.217）没有「后台启动」选项：`WindowBuilder` 默认可见并激活 → 测试一跑，窗口就跳到前台。
- 其它测试套件（Node 服务 + 无头 Chrome）本身不打扰用户；`e2e.mjs` 默认 `BASE=http://127.0.0.1:8787`，如果用户应用正占着 8787，会先摸到用户实例（虽然 `_env.mjs` 的隔离断言随后会拦住写入，但应改为「默认必须显式 BASE」）。

## 4. 改进一：扫描件识别与图片上下文（P1）

### 4.1 打开时判定类型（PDF 构成扫描，第一版）

在 `openDoc()` 加载成功后启动后台任务 `scanDocProfile()`，逐页取两项指标（不阻塞首屏，进度显示在现有状态区）：

| 指标 | 来源 | 用途 |
|---|---|---|
| 文本字符数 `textChars` | `page.getTextContent()`（去空白） | 判断是否有文本层 |
| 图片覆盖比 `imageRatio` | `page.getOperatorList()` 里 `paintImageXObject / paintInlineImageXObject / paintImageMaskXObject` 的变换矩阵面积 / 页面面积 | 判断扫描图 / 插图 |
| 绘制操作数 | 同上（`operatorList.fnArray.length`） | 纯矢量页 / 空白页 |

页分类（阈值先按经验值，实施时用真实论文校准）：

- `text`：`textChars >= 100`；
- `scan`：`textChars < 20` 且 `imageRatio > 0.5`；
- `mixed`：`textChars >= 20` 且 `imageRatio > 0.3`（插图页/整页图配图注）；
- `other`：其余（空白、纯矢量）。

文档级：`scanned = text 页占比 < 20%` 或「平均每页字符 < 50」；同时记录 `scannedPages`、`figurePages`（候选图表页，供「讲懂图表与公式」和框选提示）。结果按 **docId + size + mtime** 缓存到 `localStorage`（带版本号，论文更新后失效），同一篇第二次打开直接命中。

UI 表现（不用弹窗）：

- 打开后状态行按需提示一次：`扫描件：没有文本层，已按页面图片理解（问答与读懂论文都可用）`；
- 输入框上方范围提示：整篇项文案从「整篇论文暂不可提取」改为「整篇论文（按页图理解）」；
- 左栏目录 / 全文搜索对扫描件仍不可用 → 明确提示原因，不静默空结果。

### 4.2 扫描件的问答上下文

新增 `buildDocContext()` 的扫描件分支：不返回文本，返回**页图列表**：

```js
{ mode: 'scan', pages: [ {page: 3, dataUrl: 'data:image/jpeg;base64,...'}, ... ], chars: 0 }
```

选页规则（控制一次请求的图片数与 token）：

| 场景 | 带哪些页图 |
|---|---|
| 普通提问（当前页/选区） | 当前屏幕页（无选区时 `viewer.currentVisiblePage()`；有选区时选区所在页） |
| 追问（顺着上一轮说「为什么/它/继续」） | 上一轮话题所在页（不跟着屏幕滚动跑）；只有明说「这一页/这里」才切回屏幕页 |
| 问题里明说「第 5 页 / p.5」 | 那一页（即使屏幕在别页） |
| 问题明确提到「这篇论文整体/方法/结论」 | 当前页 + 文档首 2 页（标题/摘要）+ 末 2 页（结论/参考文献前的正文） |
| 用户选「整篇论文」 | 均匀采样 4–6 页（首 2 页 + 方法/实验/结论代表页，按 `scannedPages` 的文本位置取），并在提示词里说明「只看到采样页，未看到的不要编造」 |
| 附件里已有该页截图 | 复用附件，不重复渲染 |

渲染：`pdfview.js` 新增 `capturePageImage(pageNum, { maxDim = 1400 })`（整页渲染 → JPEG 0.82，单张 ≤ ~250KB），复用现有 `captureRegion()` 的画布逻辑；多页串行渲染，带「正在准备第 N 页图片」提示。

消息组装：在 `askMessages()` / `teachMessages()` 的 user 消息里，图片以 `image_url` 形式追加，并在文本里加标签：

```
【第 3 页原图】见附图
【第 1 页原图】见附图
```

系统提示词追加一句：`附带的是论文页面图片；只依据图片里实际可见的内容回答，看不清/被裁掉的地方说不确定，不要补造。`

### 4.3 扫描件的「读懂论文」

四项教学能力都需要「读懂整篇」，扫描件不能每页都发。设计：

1. 首次在扫描件上触发教学能力时，后台生成一份**图片阅读索引**：
   - 采样页（首 2 页、方法/实验/结论代表页共 6–8 页，按 `scannedPages` 与页面尺寸选）；
   - 逐页（或每 2 页一批）发给视觉模型：「转录本页正文（保留论文原话与数字）+ 本页图表/公式要点 + 页码」；
   - 汇总成 ≤3000 字的《图片阅读索引》，缓存 `localStorage`（键含 docId+size+mtime+提示词版本）；
   - 进度提示：「扫描件：正在阅读第 3/8 页…」，可停止；失败保留已完成页并明确提示。
2. `runTeaching()` 的 `buildDocContext()` 对扫描件返回 `{ text: 图片阅读索引, mode: 'scan-digest', pageImages: 相关页 }`；
   - 「讲懂图表与公式」：从 `figurePages` 里取当前页附近候选 → 直接渲染该页图（整页或框选区域）随请求发送，不再依赖文本层识别编号；
   - 「带我一步步读」路线里的页码仍可用（页码来自页面顺序）。
3. 追问沿用「当前页图 + 阅读索引」；用户框选截图时仍走原有 `regionMessages()`。

### 4.4 视觉模型真正生效

- 前端：`streamChat()` 在消息含 `image_url` 时，先尝试 `Settings.data.visionModel`（设置页新增「视觉模型（可选）」输入，空则用主模型）；请求体加白名单字段 `useVision: true`（不传 model，保持「模型只能来自本机 config」的安全口径）。
- 服务端（Node `handleChat` + Rust `chat.rs`）：`useVision` 为真时取 `stored.visionModel || stored.model`；无视觉模型时仍用主模型（行为与现在一致），前端在首次发图前提示「未配置视觉模型，将用主模型；如果它不支持图片，请到设置里填一个视觉模型」。
- 若上游返回「不支持图片」类错误：错误提示追加「换一个视觉模型 / 用框选截图」的可操作建议。

### 4.5 失败与降级

- 视觉模型不可用 / 未配置 / 超时：明确 toast + 保留问题与附件；不阻塞阅读，不静默改发主模型（除用户确认的「主模型也支持视觉」）。
- 页图渲染失败（损坏页）：跳过该页并在提示里说「第 N 页渲染失败」。
- 扫描件下仍可用：框选截图（原有最强路径）、文字对话（不依赖文本层的问题）、联网搜索。

## 5. 改进二：右栏划词气泡（P1）

设计沿用 [`右栏交互增强-设计.md`](右栏交互增强-设计.md) §1，并做以下收口：

### 5.1 触发与范围

- 在 `#aiArea` 内、`.msg.assistant .text`（问答回答 / 解释 / 教学结果 / 译文条目）中选中文字并松手 → 显示同一个 `#bubble`；
- 用户消息（`.msg.user`）不提供（避免自我引用）；
- 选中内容 < 2 字不弹；与正文选区互斥：右栏选区出现时清掉正文选区状态（反之亦然）。

### 5.2 按钮子集

| 按钮 | 右栏显示 | 行为 |
|---|---|---|
| 加入问答区 | ✅（文案用「加入问答区」） | 作为文字附件加入当前会话，来源标注「右栏回答/译文」 |
| 直接解释 | ✅ | 进入问答区，`doExplain()` 同一链路 |
| 复制 | ✅ | 复制选中文字 |
| 翻译 | ❌ 不显示按钮，但快捷键 T 仍生效 | 用户明确按 T 时翻译，不挡这个意图 |
| 写笔记 | ❌ 隐藏（笔记需要正文锚点） | — |

实现：气泡容器加 `data-source="right"`，CSS 隐藏多余按钮；`mousedown` 防选区丢失沿用现有逻辑。

### 5.3 选区对象

```js
{ text, cleanText, page: viewer?.current || null,
  box: { left, top, right, bottom, width, height },   // window.getSelection().getRangeAt(0).getBoundingClientRect()
  source: 'right' }
```

`addToChat()` / `doExplain()` / `copyText()` 都不依赖 `box`，可直接复用；不调用 `viewer.paintSelection()`（不画正文选区块）。

### 5.4 收起的规则

- 点正文任意处 / 点右栏空白 / Esc / 切换到另一条消息 → 收起；
- 滚动正文**或**右栏都会收起（旧设计说「滚动右栏不误关」，但实测中右栏选中后滚动基本等于放弃选区；实施时以「滚动即收起」为默认，若误关明显再放宽）；
- 气泡定位用 DOM selection 的 rect；视口边界钳制沿用 `showBubble()`。

### 5.5 追问与「接着问」

- 每条回答已有的「接着问」按钮保持不变；
- 教学结果的 chips（讲第 N 项 / 继续下一步 / 再压短…)同样保留；
- 右栏「加入问答区」后自动把「问答」面板切到前台并聚焦输入框（复用 `addToChat` 行为）。

### 5.6 所在页与上下文选择（2026-11-01 第二轮修订）

第一轮为了修「定位到当前屏幕显示的区域」，把**所有**提问的所在页都按发送时的屏幕页算；
结果是**追问**也被屏幕页顶掉：先解释过第 2 页、滚到第 8 页再问「为什么」，模型看到
【论文】（第 8 页）+ 第 8 页整页文字，回答就强调第 8 页的内容（用户反馈的问题）。
第二轮把「所在页」拆成四种来源，由 `reading-context.js` 的 `resolvePageRole()` 统一判定：

| 优先级 | 来源 | 什么时候用 | 上下文取哪 |
|---|---|---|---|
| 1 | 附件选区页 | 这一轮挂了选区/截图 | 选区所在页 + 选区附近 700 字 |
| 2 | 问题里明说的页码 | 「第 5 页 / p.5」 | 那一页整页（超出总页数则忽略） |
| 3 | 追问的话题页 | 短追问、代词、为什么/继续等，且上一轮对象有页 | 话题所在页（沿用的原文附近或整页） |
| 4 | 当前屏幕页 | 新问题、或明说「这一页 / 这里 / 当前页」 | 屏幕页整页 |

配套改动：

- `resolvePageRole()` / `screenPageRequested()` / `explicitPageIn()` 放进 `reading-context.js`（可单元测试）；
- **不再**把屏幕页写回继承的 `focus.page`：否则上一轮的页面会被污染，下一轮追问甚至找不到原文
  （旧实现里 `focus.page` 被覆盖成屏幕页，`getContextAround()` 在该页找不到旧选区 → 上下文为空）；
- 「这一页 / 这里」被识别为**问眼前页面**：不继承上一轮选区（`inherited=false`），上下文直接给屏幕页整页；
- `askMessages()` 按来源给不同标注：【论文】（读者当前在第 N 页）/（第 N 页）/（问题指定的第 N 页）
  /｜当前话题在第 N 页；上下文块也改成【当前屏幕页上下文】/【当前话题所在页上下文】/【问题指定页的上下文】，
  系统提示加一条「追问不要因为读者滚到别的页就把那页当新话题」；
- 回答条目的页码标注跟「所在页」一致（追问标话题页，问屏幕页标屏幕页），点页码能跳回对应位置；
- 重试/跨重启沿用第一次发送时定下的 `pageRole/firstPage`，不随后续滚动变化。

**右栏划词不是 PDF 原文（2026-11-01 第二次修订）**：用户实测「上一轮回答里的解释文字被当成第 2 页原文」
（当时右栏选区的 `page` 取 `viewer.current`，既可能慢一拍，也会让模型拿它去对照页图里的手写内容）。
现在：

- 右栏（问答回答 / 译文）里划的选区 `page = null`，附件行只标「右栏」、**不标第 N 页**；
- `selectionSource='right'` 一路传进 `resolveReadingRequest()`（`focus.source='right'` 随会话历史保存），
  `askMessages()` 把它标成「来自右栏回答 / 译文，不是论文原文」，并在规则 1.2 要求模型不要给它标页码、
  不要拿它对照页图手写内容；
- 它以附件形式提问时，PDF 语境退回**当前屏幕页整页**（`getContextAround(page, '')`），
  不会拿它去正文里做「原文附近」定位（那样必然 0 命中、上下文为空）；
- 追问沿用右栏文字时，它仍没有页码，语境跟着屏幕页走——不会再把「上一轮回答」说成某页原文。

### 5.7 会话内记忆（现状确认）

有，分三层（详见 §6）：

1. **最近 3 轮原样发送**：`historyMessages()` 取最近 6 条（user/assistant 各 3），user 消息里保留
   `【当轮原文 · 第 N 页】`，所以追问能接上原文；每条 ≤12000 字；
2. **滚动摘要**：历史超过 8 条后，更早的（保留最近 6 条之外）压成 ≤1200 字摘要，放在 system
   `【本次会话早先内容摘要】` 里继续带；
3. **本篇之前的讨论**：新会话首轮注入最近 2 个会话的摘要（可在会话菜单关掉）。

回答里出现「我没有上文/不知道你在说什么」，通常不是没带记忆，而是**所在页被屏幕页带跑**
（第一轮那个 bug）；第二轮修正后追问会同时看到「最近 3 轮 + 话题原文 + 话题所在页上下文」。

## 6. 改进三：会话记忆与全局记忆（P2）

### 6.1 先回答用户的问题

- 同一会话**有前文记忆**：最近 3 轮原样随请求发送（每条 ≤12000 字），更早的存盘但不发送；用户说过的讲解偏好（例如「以后先给例子」）会一直带上。
- **但**：① 长会话超过 3 轮后，早先的约定/结论只靠 guidance 漏传；② 换会话就断片；③ 换论文后完全不知道之前的讨论；④ 没有用户能写死的长期偏好（如「我在读多模态方向，术语保留英文」）。
- 本项就是补这四条。

### 6.2 分层设计（对照 Codex，调研结论见 `记忆系统调研-Codex.md`）

| 层 | 内容 | 写入 | 注入 |
|---|---|---|---|
| L1 会话内 | 最近 3 轮原文 + **滚动摘要**（更早内容压缩成 ≤800 字） | 每轮问答结束后后台增量更新；也保留原始 history 落盘 | 每次问答/教学 |
| L2 论文内跨会话 | 每个会话的摘要落盘；打开论文/新会话时注入「本篇之前的讨论摘要（最近 2 个会话）」+ 未解决问题 | 会话保存时写入 `summary` 字段（`/api/session` 已允许额外字段，无需改接口） | 新会话首轮，及「接着问」缺少上下文时 |
| L3 长期偏好 / 身份 | ① 现有学习画像（自动、只影响讲解方式；含用户明确自述的**称呼/名字、研究方向、长期目标**，kind=`identity`，隐私红线过滤）；② **用户可编辑的「长期记忆」文本**（全局，≤4000 字，设置页多行输入） | ① 后台提取，只认用户原话；② 仅用户点保存 | 所有问答/教学 system，长度封顶；身份类与问题关键词无关也常驻注入 |

实现要点：

- **滚动摘要**：`state.history` 超过 8 条且比上次摘要多出 ≥4 条时，后台让模型把「已摘要范围之外、但不在最近 6 条内」的轮次合并进摘要（输入只含这些轮次的问答，输出 ≤800 字），存 `session.summary`；失败静默保留旧摘要，不阻塞回答。会话恢复时读回摘要。
- **跨会话论文记忆**：`openDoc()` 已有 `loadSessionList()`（读 `/api/sessions`）；新会话（`state.history` 为空且不是恢复当前会话）在首次发送前拉最近 2 个会话的 `summary`，拼成「【这篇论文之前的讨论】」注入 Q&A system。注入内容在输入框范围提示里不显示（属于内部上下文）；会话菜单加「清除本篇的对话记忆」（只清摘要，不删会话）。
- **用户可编辑全局记忆**：`config.json` 新增 `longTermMemory` 字段（Node `security.js` 白名单 + Rust `limits.rs` + 两端默认值），设置页加多行文本框「长期记忆：写给你自己看的、希望 AI 一直记住的背景与要求」。注入位置在 system 末尾的 `【长期记忆（用户手写）】`，与学习画像区分（不是论文证据、不是用户掌握程度）。
- **注入顺序与预算**（一次问答的总上下文预算）：

```
长期记忆(≤4000字) → 学习画像(≤1200字) → 论文讨论摘要(≤1200字) → 会话摘要(≤800字)
→ 最近 6 条对话 → 本轮材料（选区/页上下文/全文或索引/页图/联网/参考文献）
```

- **隐私与用户控制**：全部本机文件；设置页提供「清空学习记忆」「清空长期记忆」「清除某篇的对话记忆」；摘要通过用户当前配置的模型生成，不新增任何外部服务。

### 6.3 明确不做

- 不做跨设备同步、不做自动把论文事实写进长期记忆（避免记忆污染与幻觉沉淀）；
- 不让模型自己决定「记住这条」：只允许用户手写，或按固定证据规则提取学习画像。

## 7. 改进四：PDF 构成扫描与 OCR（P2/P3）

### 7.1 第一版（P2，跟随 §4.1）

- 打开时逐页出「文本 / 扫描图 / 混合 / 其它」分类 + 扫描页列表 + 图表候选页；
- 这些信息用于：问答选页图、教学选图表页、扫描件提示文案；
- 不做「文字区域/图片区域的精确坐标框」：本版只有页级分类。精确版面分析（text block / image region bbox）放到 P3，理由：当前 UI 没有需要它的交互，做了也没有入口。

### 7.2 OCR（P3：调研完成；视觉模型方案曾实现，已按用户要求移除）

调研结论详见 [`扫描件与OCR-调研.md`](扫描件与OCR-调研.md)，首选「复用已配置的视觉模型做页图转写」。
2026-11-01 曾实现过一版「生成文字版（OCR）」（逐页转写 + 按文件指纹缓存 + 问答优先用文字），
但用户评估后认为「自动判断该不该生成」的权衡太麻烦、手动按钮也少用，**要求整体移除**；
现在扫描件只走「页面图（视觉模型融合理解）+ 读懂论文的图片阅读索引」这一条路，不再有 OCR 文字版。
后续若重启 OCR，建议按调研 §10 记录：本地启发式判型 + 样张试探 + 默认只提示不自动全量。

## 8. 改进六：测试与构建不打扰用户（P0，先做）

### 8.1 构建（`desktop/build.bat`）

- **不再按进程名杀进程**（删掉现在的强杀段）；构建只负责产出 `target/release/paper-reader.exe`；
- 复制到项目根：目标被占用（有实例在跑）时重试 10 秒，仍失败则明确报错退出，不杀进程；
- 复制到桌面：目标被占用（用户正在用桌面上的 exe）时**打印提示并跳过**，不失败、不关闭用户的窗口；
  用户关掉应用后重跑 `build.bat` 即可更新桌面副本；
- 保留 SHA256 校验；两份一致时提示，不一致时明确列出哪份没更新。

### 8.2 交付 exe 的「后台启动」开关（Rust，已实现）

- 新增 `--background` 参数 / `PRT_BACKGROUND=1` 环境变量：
  - 窗口创建为**隐藏**（`with_visible(false)`），首次显示用 `SW_SHOWNOACTIVATE`（不抢前台/不抢焦点）；
  - `with_skip_taskbar(true)`（不占任务栏、不闪）；
  - 不改变正常双击启动的行为（照旧可见并聚焦）。
- 目的：验收脚本启动 exe 时窗口不跳到用户面前；普通用户启动体验不变。
  实测（`desktop.mjs`）：`EnumWindows` 能找到窗口与标题，但 `IsWindowVisible=false`。

### 8.3 测试（`test/`）

- 新增 `test/_exe.mjs` 公共 helper：
  - `stageExe()`：把交付 exe 复制到 `test/artifacts/...` 独立目录（**绝不启动仓库根 exe**，更不会杀用户实例）；
  - `spawnReader()`：统一 `--background` + 独立端口 + 隔离数据目录，返回子进程；
  - `stopChild()`：只 `taskkill /PID /T /F` 自己启动的子进程；
- `desktop.mjs`：删除 `killRunning()` / `aliveCount()` 与「残留旧实例」断言，改为「启动的是本次沙箱副本 + 用 fixture 论文识别自己的实例」；
- `qa.mjs` / `profile.mjs` 的 exe 后端、`sidebar-reopen.mjs`、`translation-layout.mjs`：改用 `stageExe()` + `--background`；
- `e2e.mjs` 等需要 BASE 的套件：**必须显式给 BASE**（去掉默认 8787），避免误触用户正在运行的应用；
- 文档 `docs/PROGRESS.md` / `README.md` 的测试说明同步。

### 8.4 验收标准

- 用户桌面实例正在运行（占 8787）时，跑 `desktop.mjs` / `qa.mjs`（exe 后端）：用户实例不被杀、不被打断；测试自己找空闲端口并全绿；
- 测试全程不出现抢到前台的窗口（`MainWindowTitle` 仍存在，但窗口不激活、不进任务栏）；
- `node test/desktop.mjs`、`node test/qa.mjs`、`MEMORY_BACKEND=exe node test/profile.mjs` 通过；
- 构建时用户实例不退出。
