# 左栏文件夹管理 — 设计方案

> 状态：待评审（2026-10-31）
> 范围：左侧「文件」面板从平铺 PDF 列表升级为文件夹树；打开 / 划词 / 问答 / 笔记等既有能力不变。
> 涉及代码：`server.js`（Node）+ `desktop/src/api.rs`（Rust 交付版，两套后端行为必须一致）+ `public/js/app.js` / `style.css` / `index.html`（前端）。

## 1. 核心选型：真文件夹（papers/ 下真实子目录）

**方案**：文件夹 = `papers/` 下的真实子目录，不引入虚拟文件夹元数据。

理由：

- 与本地文件系统一致：资源管理器里看到的 `papers/` 结构 = 界面里的树，永远不漂移；
- 用户可直接在资源管理器里建夹、移文件，刷新即生效；
- 文件夹操作就是 fs 操作（mkdir / rename / rmdir），无元数据同步问题；
- 现有安全校验 `safeJoin` / `safe_join` 已支持子路径，无需新机制。

**代价与对策**：docId = djb2(文件名)，同名 PDF 放不同文件夹会串号（笔记 / 会话 / 进度共用）。
对策：**全库文件名唯一** —— 移动 / 导入遇到已有同名文件时自动加 `(2)` 后缀（与现有 `uniquePdfName` 行为一致）。
这保持「一个 docId = 一个文件 = 一份数据」不变式：**文件在文件夹之间移动，docId 不变，笔记 / 会话 / 阅读进度零丢失**。

## 2. 使用方式（交互设计）

### 2.1 左栏结构

```
┌ 文件 ──────────────── [+ 新建文件夹] ──┐
│ [筛选框…]                             │
│ ▼ 📁 深度学习                          │
│    ≡ attention.pdf          ×         │
│    ≡ transformer.pdf       ×          │
│ ▼ 📁 课程/复变函数                     │
│    ≡ 级数.pdf               ×          │
│ ▸ 📁 待读                             │
│ ≡ 根目录散文件.pdf           ×         │
└───────────────────────────────────────┘
```

- 文件夹行：箭头展开/折叠（状态记 localStorage）+ 文件夹名 + 计数（**不设行尾 ×**，删除走右键菜单，防误删整夹）；
- PDF 行：抓手 + 文件名 + 删除 ×；**× 默认隐藏，鼠标移到该行时才显现**，中性灰（非红色）；行尾 × 只删文件；
- 筛选框输入时：树切换为**扁平过滤结果**，每行前缀显示所在文件夹（如 `深度学习/attention.pdf`），清空恢复树。

### 2.2 操作清单

| 操作 | 触发 | 行为 |
| --- | --- | --- |
| 打开 PDF | 点文件名 | 与现在一致 |
| 展开 / 折叠 | 点文件夹行箭头 | 展开状态持久化 |
| 新建文件夹 | 面板头部 `+`，或右键空白处/文件夹 → 新建文件夹 | 内联输入名，Enter 确认；默认名「新建文件夹」，重名自动 `(2)` |
| 重命名文件夹 | 右键 → 重命名（或双击文件夹名） | 内联改名 = 改磁盘真实目录名；内部 PDF 的 docId / 笔记 / 会话不受影响 |
| 删除文件夹 | 右键 → 删除 | 空夹直接删；非空弹确认：① PDF 移到根目录再删（默认推荐）② 连同 PDF 一起删 |
| 移动 PDF | 拖拽 PDF 到目标文件夹行 | 目标行高亮；落点 = 跨目录移动（磁盘 rename），目标已有同名自动 `(2)` |
| 调整顺序 | 同一目录内拖拽 PDF（现有逻辑） | 顺序写 `papers-order.json` |
| 导入 PDF | 拖 PDF 到文件夹行 = 导入该夹；拖到根 / 拖入区 / 「打开 PDF」= 根目录；从资源管理器拖入**文件夹** = 创建同名夹并导入其中 PDF | |
| 删除 PDF | 行尾 × | **默认隐藏，鼠标移到该行时才显现**；颜色用中性灰（非红色），hover 加深；只删文件，笔记 / 会话 / 进度保留在 data/ |
| 筛选 | 顶部筛选框 | 扁平结果视图；结果可直接打开 / 删除 |

### 2.3 明确不做（v1）

- 文件夹本身不拖拽排序（按名称排序）；PDF 排序保留；
- 不做「选中多篇批量移动」（拖拽单篇 + 右键菜单已够用，后续可加）；
- 导入的文件夹递归子文件夹：先只读一层（后续按需加）。

## 3. 数据模型

- **磁盘**：`papers/` 下任意层级子目录（服务端不限制层级，前端树递归渲染）。
- **`data/papers-order.json` 升级**：

  ```json
  { "order": ["a.pdf", "深度学习", "深度学习/attention.pdf", "课程"] }
  ```

  - 元素 = 相对路径（根目录 PDF、文件夹名、`文件夹/文件.pdf`）；
  - 描述**整棵树**的顺序：渲染某目录时，其子项按 order 中出现的先后排列，未出现的按 mtime 倒序排最前（沿用现规则）；
  - **旧数据自动兼容**：现有纯文件名数组 = 根目录顺序，无需迁移。

## 4. 后端 API（Node 与 Rust 同步实现）

| 接口 | 变更 |
| --- | --- |
| `GET /api/papers` | 保持 `papers` 数组（每项新增 `folder`、`path` 字段，url 改 `?path=`），**新增** `folders` 数组（name / path / count）。老断言与 mobile 不破 |
| `GET /api/pdf` | 新增 `?path=相对路径`；`?name=` 继续可用（根目录；找不到时按 basename 全库递归回退）→ 旧最近记录、旧链接不断 |
| `DELETE /api/papers` | `name` → `path`（相对路径） |
| `POST /api/papers` | order 元素放宽为合法相对路径（仍拒绝 `..`、`\`、控制符、空；文件类元素必须 `.pdf`） |
| `POST /api/folders` | `{name}` 新建根文件夹 |
| `PATCH /api/folders` | `{from, to}` 重命名（磁盘 rename） |
| `DELETE /api/folders` | `{path, mode}`，mode = `to-root`（PDF 移到根再删，默认）/ `recursive`（连同 PDF 删） |
| `POST /api/move` | `{from, toFolder}` 移动 PDF 或文件夹；同名自动 `(2)` |
| `POST /api/upload` | 增加 `folder` 参数（默认根） |
| `POST /api/import-pdf` | 增加 `folder` 参数（默认根） |

安全：全部经 `safeJoin` / `safe_join`（已有），拒绝 `..`、绝对路径、控制符、路径分隔符混用。

## 5. 兼容与迁移

- 现有 `papers/` 根文件 = 根目录，**零迁移**；
- docId 不变 → 移动后笔记 / 会话 / 进度仍关联；
- 旧 `/api/pdf?name=` URL 全库回退查找，最近记录与旧链接不断；
- 前端 active 高亮由「比对 url」改为「比对 docId」（文件移动后 url 会变）；
- mobile（`public/mobile`）只按 url 参数打开单篇 PDF，不受影响；
- 测试：`test/` 与 `desktop/tools/acceptance.ps1` 旧断言保持兼容（papers 数组仍在），新增文件夹用例（隔离临时目录，不写死用户书架）。

## 6. 实施步骤

1. `server.js`：`listPapers` 递归列目录（folders + papers 带 path）；新增 folders / move 接口；pdf / upload / delete / import 支持 path；
2. 前端 `app.js`：`renderPaperList` → 树渲染（递归 + 展开状态）；右键菜单（新建 / 重命名 / 删除 / 移动到）；内联重命名；拖拽到文件夹 = 移动；筛选扁平视图；`style.css` 树缩进与高亮样式；
3. `desktop/src/api.rs` 同步实现（保持与 server.js 行为一致）；
4. 测试：扩展 `test/` 与 `acceptance.ps1`；
5. `desktop\build.bat` 构建 .exe，全量回归。

## 7. 需要拍板的决策点

| # | 决策 | 推荐 | 备选 |
| --- | --- | --- | --- |
| 1 | 文件夹层级 | 任意嵌套（树递归，磁盘天然支持） | 只做一层（实现更省，但与磁盘现实不符） |
| 2 | 同名 PDF 策略 | 全库文件名唯一，自动 `(2)`（笔记不串号） | 允许同名但共用一份笔记（不推荐） |
| 3 | 删除非空文件夹默认动作 | PDF 移到根目录再删 | 连同 PDF 一起删 |
| 4 | 导入默认位置 | 根目录（拖到文件夹行才进该夹） | 进当前展开/选中的文件夹 |
