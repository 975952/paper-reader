## 项目是什么

本地 PDF 阅读器 + AI 辅助（划词翻译/解释、整篇问答、15 个论文操作、文献关系）。
- 前端：`public/`（**零依赖原生 ES module，无打包器**）
- 后端两套：`server.js`（Node 零依赖）与 `desktop/`（Rust：wry + tao + tiny_http + ureq + rust-embed）
- 手机版：`android/`（Gradle + WebView 壳，零第三方依赖，完全离线）
- 交付物：`论文阅读器.exe`（绿色版，`papers/` 与 `data/` 相对 exe 目录）、`论文阅读器-手机版.apk`

## 环境与命令（都实测过）

```powershell

node android\sync-assets.mjs --check     # 只查资源是否同步
```

## 绝对要遵守的纪律（都踩过）

1. **改任何文本文件只能用编辑工具（read/write/edit）**，不要用 PowerShell 的
   `Set-Content` / `Out-File` / `>` —— 中文 Windows 上会按 ANSI(936) 写回，整文件变乱码。
   已经因此写坏过 3 次源码。必须用脚本时走 Node + `fs`。
2. **`.bat` 必须纯 ASCII**：cmd 按 OEM 代码页解析，中文注释会吞掉后续命令。
3. **前端是编译期内嵌的**：改 `public/` 不重新编译不生效；**新增文件不会触发重编译**，
   `desktop/build.bat` 会先 touch `src/assets.rs`。
4. **不要动用户的真实数据**：`data/`（含 API Key）、`papers/`（私有论文）只读。
   测试一律用 `test/artifacts/` 下的隔离目录，`test/_env.mjs` 会拒绝真实数据目录。
5. **不要杀用户的进程**：`8787` 是用户自己的实例；测试用 8800/8877/8878 等端口。
   曾经两次误杀，都要重新起回来。
6. **不要相信只量 DOM**：这个项目出过好几次「DOM 尺寸全对、画面是坏的」。
   量化手段按可用性排序：
   - 截图 → 解码到 canvas → 统计像素（纸面比例、逐行差异）
   - `CDP CSS.getMatchedStylesForNode` 问浏览器"这个属性的到底是哪条规则设的"（顶栏那个 bug 就是靠它一击命中）
   - 逐点 `document.elementFromPoint` 命中测试
   - `visualViewport` / `window.devicePixelRatio` 对齐检查
7. **大改动前先备份**：仓库已有 git，`git commit` 一下即可回滚。
8. **改完要重新编译两个交付物**并给出新哈希：
   `cmd /c "desktop\build.bat"` 与 `cmd /c "android\build-apk.bat"`。

## 关键设计口径（用户明确定的，别改回去）

- **一类功能只有一个主要入口**：右栏「译文/问答」切换器只有底部那一组；译文栏**没有输入框**。
- **一栏只开一个**：右栏两栏各自最多一个面板。
- **划词翻译直接进侧栏**，不弹浮窗。
- **浮窗（应用内卡片）**：8 向可拉伸、点外部不关闭、只能 ✕/管理器/Esc 收回、不创建系统窗口。
- **顶栏默认悬停才出现**（屏幕最上沿细带触发），文章不动、不遮正文。
- **深色模式**：界面深暖灰 + 正文纯白；**PDF 保持白纸黑字**（刻意设计）。
- **配色**：暖灰 + 米白 + 深灰 + 橄榄绿，**不要蓝色**；图标统一 24×24 线性 SVG。
- **手机版**：阅读时只显示 PDF；字号只放大文字（图片/表格/公式尺寸不变）；长按选词/长按图片放大。
