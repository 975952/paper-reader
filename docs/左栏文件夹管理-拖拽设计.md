# 左栏文件夹管理 — 拖拽交互细化设计

> 状态：待评审（2026-10-31）
> 依赖：主方案见 `docs/左栏文件夹管理-设计.md`。本文只细化左栏内所有拖拽行为的判定、反馈与边界。

## 0. 拖拽语义总原则

**同目录 = 排序（插入线）；跨目录 = 移动（目标高亮）。**

排序与移动用「是否同目录」一刀切开，杜绝"这一下到底算排序还是移动"的歧义：

| 拖起源 | 悬停目标 | 判定 |
| --- | --- | --- |
| PDF（同目录） | 本目录其他 PDF 行 | **排序**：上/下半 → 插入其前/后 |
| PDF（跨目录） | 其他目录的 PDF 行 | **移动**：移入该行所在文件夹（不做插入） |
| PDF / 文件夹 | 文件夹行 | **移动**：移入该文件夹 |
| PDF / 文件夹 | 根目录空白区 | **移动**：移到根目录 |
| PDF | 展开文件夹的子区空白 | **移动**：移入该文件夹末尾 |
| 外部文件 / 文件夹 | 文件夹行 / 根空白 | **导入**：复制进该夹 / 根 |

## 1. 拖拽角色

### 1.1 库内拖拽（左栏里的元素）

- **PDF 行**：整行可拖（保留抓手，但不再要求抓着手柄才能拖）；
- **文件夹行**：可拖，语义是**改变层级**（移入另一文件夹 / 移到根）；**不做同级排序**（v1 文件夹按名称排序）；
- 拖拽数据：`dataTransfer.setData('application/x-prt-paper', JSON.stringify({ path, kind: 'file'|'folder' }))`，同时保留 `text/plain` 兜底；
- 内部拖拽与外部拖拽的判别升级：内部拖拽**不再**用 `text/plain` 判断，改为优先读 `application/x-prt-paper`（避免与外部 Files 混淆）。

### 1.2 外部拖拽（资源管理器 / 桌面）

- 单个 / 多个 PDF：导入（复制语义，光标带 `+`）；
- **文件夹**：在 `papers/` 下创建同名文件夹（重名自动 `(2)`），导入其中直接含有的 PDF；
  - v1 **只读一层**：文件夹内部的子文件夹忽略，toast 提示"已忽略 N 个子文件夹"；
  - 实现：`dataTransfer.items` → `webkitGetAsEntry()` 异步读取（Chromium 支持）；
- 混合（PDF + 文件夹混拖）：分别按上述规则处理。

## 2. 命中判定细则（按优先级）

悬停时按「命中元素最近的放置语义」判定，逐级检查：

1. `closest('[data-folder]')` 命中文件夹行 → **移入该文件夹**：整行蓝色高亮 + 文件夹图标点亮；空文件夹额外显示"移入并置于顶部"；
2. `closest('li[data-name]')` 命中 PDF 行：
   - 与拖起源**同目录** → **排序**：按 `clientY` 与行中线比较，上=插前、下=插后，显示 2px 蓝色插入指示线（复用现有 `drop-before` / `drop-after`）；
   - **跨目录** → **移动**：移入该行所在文件夹（高亮的是文件夹而非插入线）；
3. 命中**展开文件夹的子区空白**（该文件夹的子项列表尾部）→ 移入该文件夹末尾；
4. 命中**文件列表容器空白 / 根区域** → 移到根目录（根区域虚线框高亮）；
5. 命中**非放置区**（目录 / 笔记 / 参考文献面板、右栏、工具栏）→ 不处理，浏览器默认 `no-drop`；
6. 拖出窗口 / 按 **Esc** → 取消，无任何副作用。

### 2.1 文件夹拖拽的禁区

- **不能拖到自己**（`from === to`，忽略）；
- **不能拖进自己的子孙目录**（目标 path 以 `from + '/'` 开头 → 拒绝，光标 `no-drop`，toast"不能把文件夹移到自己的子目录里"）；
- 服务端 `POST /api/move` 做**同样的二次校验**（前端防误操作，后端防越权）。

### 2.2 筛选激活时的拖拽

**v1 规则：筛选输入非空时，库内拖拽整体禁用**（draggable=false + toast"请先清空筛选再拖拽"）。
理由：筛选时是扁平视图，行与行的目录关系被隐藏，拖拽极易误判成"排序"实为"移动"。空筛选才恢复拖拽。
（放宽方案：筛选时只允许"拖到文件夹行=移入"，不做行间操作 —— 列为后续可选项。）

## 3. 视觉反馈规格

| 阶段 | 反馈 |
| --- | --- |
| 拖起 | 被拖行 `opacity .4` + 阴影；库内移动光标 `move`，外部导入光标 `copy`（`+`） |
| 悬停·文件夹行 | 整行蓝色高亮 + 图标点亮（表示"移入这里"） |
| 悬停·同目录 PDF 行 | 蓝色插入指示线（上/下 2px），可同时有多处出现但只保留当前判定的一处 |
| 悬停·根空白 | 根区域虚线框高亮 |
| 禁止目标 | 浏览器 `no-drop` 光标（CSS 辅助 `.drag-no`） |
| 放置成功 | toast「已移动 x.pdf → 深度学习」（自动改名时注明新名：→ 深度学习/x (2).pdf）；随后 `refreshPaperList()` 刷新（展开状态在 localStorage，不丢） |
| 放置失败 | toast 错误 + 刷新列表（目标可能已被另一窗口删除） |

## 4. 冲突与边界处理

| 场景 | 处理 |
| --- | --- |
| 目标文件夹已有同名 PDF | 服务端自动加 `(2)`（与导入行为一致），返回 finalName，toast 注明新名 |
| 拖到自身 / 目标不存在 | 忽略 / 服务端 404 → toast + 刷新列表 |
| 移动**正在打开**的 PDF | **不打断阅读**：阅读区不重载，仅更新内部 `state.doc.url` 与路径；下次重开走新位置。active 高亮按 docId 判定（url 会变） |
| 移动后顺序 | 源目录 order 中移除该项；目标目录追加到末尾；`papers-order.json` 由服务端在 move 时一并更新 |
| 多选批量拖拽 | v1 不做（单篇拖拽），列为后续 |
| 从资源管理器拖入的文件夹为空 | 仍创建文件夹（用户可随后拖入），toast 提示"已创建空文件夹" |

## 5. 服务端 `POST /api/move` 契约

```
POST /api/move
body: { "from": "深度学习/attention.pdf" | "待读", "to": "" | "课程" }
  to 为空字符串 = 移到根目录
返回: { ok, from, to, name?, docId? }
  name 仅在发生同名自动改名时返回（如 "attention (2).pdf"）
校验（Node server.js 与 Rust api.rs 一致）:
  1. from 存在且是 PDF 或文件夹；to 存在且是文件夹（或空=根）
  2. 拒绝 .. 、绝对路径、\ 混用、控制符（经 safeJoin / safe_join）
  3. 文件移动：目标目录已有同名 → 自动 (2)(3) 后缀（复用 uniquePdfName 规则）
  4. 文件夹移动：from 不得是 to 的祖先或等于 to
  5. 成功后同步更新 papers-order.json（源目录摘除、目标目录追加）
```

前端流程：drop → `POST /api/move` → 成功 → `refreshPaperList()` + toast；失败 → toast + `refreshPaperList()`。

## 6. 与现有实现的差异点（改动清单）

1. `bindPaperReorder` 重写为 `bindPaperDrag`：新增「跨目录=移动」判定与文件夹行命中；
2. 拖拽数据：新增 `application/x-prt-paper` MIME；`isExternalFileDrag` 改为优先读该 MIME；
3. 外部拖入：新增 `webkitGetAsEntry` 文件夹读取（只读一层）；
4. 新增放置目标高亮 class：文件夹行高亮、根区域虚线框；
5. `draggable` 绑定移到「文件树渲染」时统一处理；筛选非空时置 false；
6. 服务端：Node + Rust 新增 `POST /api/move`（含 unique 改名与 order 同步）。
