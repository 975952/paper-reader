# 阅读助手界面设计（设置页 / AI 回答卡片 / 依据 / 跳转 / 笔记 / 发送范围 / 状态）

> 交付物：`design/reader.html`（可直接双击打开的可交互设计稿）+ `design/reader.css` + `design/js/*`

> 状态：**设计稿已完成并实测全绿；尚未合并进 `public/` 的正式界面**

## 0. 一句话

一个**安静的阅读助手**：左边论文、右边回答，AI 回答正文是唯一的视觉主体，
依据、笔记、范围、跳转都收在图标里，不抢空间、不需要学习成本。

## 2. 设计原则（每条都可被自动化断言复现）

1. **回答正文是主体**：卡片没有标题、没有「AI回答 / 回答完成 / AI译 → 中文」这类内部状态标签。
2. **图标优先，文字只用在容易歧义的低频操作上**：右上角「恢复默认设置」、失败卡片「回答未完成」才用文字。
3. **不猜范围**：发送框永远显示当前范围的图标 + 极短标签（选中文字 / 当前页面 / 论文 / 论文 + 网络）；
   回答卡片底部同样保留本次实际使用的范围图标，悬停给出完整说明。
4. **不猜依据**：依据图标带数字，展开后每条依据都带状态图标（对勾 = 原文直接支持、波浪线 = 模型归纳、问号 = 未找到直接依据）。
5. **不打断阅读**：保存笔记只有图标原地变化 + 一条窄标题行；没有大型成功提示；复制只在图标上闪一下对勾。
6. **一切可恢复**：跳转原文有返回箭头；停止生成保留内容并可继续；失败不清空问题与已生成内容；恢复默认只重置三项。
7. **禁止项**（整套 CSS 由脚本扫描）：emoji、表情符号图标、拟物图标、渐变、发光、厚重阴影、
   大面积彩色按钮、永久展开的设置栏、大型弹窗、红色/橙色告警块。

## 4. 图标规范

唯一来源：`design/js/icons.js`（`window.PRT_ICONS`）。所有图标：

```
viewBox="0 0 24 24"   fill="none"   stroke="currentColor"   stroke-width="1.5"
stroke-linecap="round"   stroke-linejoin="round"   aria-hidden="true"   focusable="false"
显示尺寸 16–18px（默认 17）   颜色一律跟随 CSS color
```

- 只允许 `path / circle / rect / line / polyline`，**不放 `<text>`** —— 从根上排除 emoji 与字体依赖。
- 默认低对比度灰（`--fg-faint`），悬停 / 激活变低饱和蓝（`--accent`）。
- **每个图标按钮必须同时有 `aria-label`（语义）与 `data-tip`（悬停提示）**，脚本逐按钮断言。
- 普通状态只显示图标；只有「恢复默认设置」这类低频且容易误解的操作才带文字。

关键图标（名字 → 语义）：

| 图标 | 名字 | 用在哪 |
| --- | --- | --- |
| 引用/文献（左右双引号） | `quote` | 依据图标（右下角带数字徽标） |
| 纸张折角 + 小加号 | `note-plus` | 「添加到笔记」未保存态 |
| 同一张纸 + 对勾 | `note-check` | 「已在笔记中」已保存态 |
| 更多（三点竖排） | `more` | 卡片操作菜单 / 输入框更多 |
| 上箭头 `↑` | `send` | 发送 |
| 实心小圆角方块 | `stop` | 停止生成 |
| 实心圆角三角 | `play` | 继续生成 |
| 双圆弧箭头 | `regen` | 重新回答 / 重试 |
| 方框四角 | `selection` | 范围：当前选中文字 |
| 单页 | `page` | 范围：当前页面 |
| 打开的书 | `book` | 范围：整篇论文 |
| 地球（细线） | `web` | 范围：联网搜索 |
| 对勾 / 波浪线 / 问号 | `sup-direct` / `sup-infer` / `sup-none` | 依据状态 |
| 对角箭头 | `jump` | 跳转原文 |
| 左箭头 | `back` | 返回跳转前的阅读位置 |
| 显示器 / 太阳 / 月亮 | `monitor` / `sun` / `moon` | 主题三态 |
| 眼睛（开/闭） | `eye` / `eye-off` | API Key 显示/隐藏 |
| 双向圆弧 | `restore` | 恢复默认接口地址 |
| 上/下折线 | `chev-up` / `chev-down` | 展开发送范围 / 收起 |

## 5. 整体布局

```
┌───────────────────────────────────────────────────────────────────────────┐
│ 顶栏 35px  论文阅读器 │ Attention Is All You Need.pdf      主题 · 设置 · 窗控 │
├────┬──────────┬──────────────────────────────────┬────────────────────────┤
│活动│ 左窄栏    │ 正文（PDF）                       │ 助手面板 372px          │
│栏  │ 208px    │ 白纸 660px 居中，可滚动            │ ┌ 卡头（会话操作）      │
│44px│ 论文      │ 页码 / 缩放浮条（底部居中）        │ ├ 回答卡片（滚动区）    │
│    │ 笔记(同步)│ 返回原位置浮条（跳转后出现在左上） │ ├ 发送范围上拉栏（可选）│
│    │          │                                  │ └ 发送框（固定底部）    │
└────┴──────────┴──────────────────────────────────┴────────────────────────┘
```

- 阅读区与助手面板之间只有 1px `--line` 分割线；活动栏用 `--bg-sunken` 稍深一点区分层次。
- 助手面板宽度固定 372px（`--as-w`），窄窗降到 320px；阅读区优先保宽度，`< 1180px` 先收起左窄栏。
- 发送框**固定在面板底部**（不随回答滚动）：上方是范围上拉栏，再上方是会话滚动区。
- 窄窗实测：1024 / 900 / 820px 下阅读区仍有 ≥ 240px 可用宽度，无横向溢出。

## 7. 回答卡片（第 3–6、13–14 态）

```
┌────────────────────────────────────────────┐
│ Transformer 使用自注意力机制，能够同时关注   │  ← 正文 14.5px/1.80（视觉主体）
│ 输入序列中的不同位置，因此更好地处理长距离   │
│ 依赖关系。                                  │
│                                            │
│ ────────────────────────────────────────── │  ← 展开依据时分隔线
│ 依据                                    ⌃  │
│ ✓ 论文短标题 · p.4                          │
│   “...jointly attend to information...”  ↗ │
│ ≈ 论文短标题 · p.3                          │
│   “...compatibility function...”         ↗ │
│                                            │
│ [书][地球]   [引用②]        [纸张+][⋯]      │  ← 操作条：范围 · 依据 · 笔记 · 更多
└────────────────────────────────────────────┘
```

- 卡片 `padding: 12px 13px 4px`，`border: 1px --line`，圆角 10px，**无阴影**。
- 操作条：左起「本次使用的范围图标（只显示图标，悬停给完整说明）」→「依据图标 + 数字徽标」→ 弹性空白 →「笔记图标」「更多」。
- 正常回答**不重复显示用户问题**（省掉一行，正文更突出）；生成中 / 停止 / 失败三种状态才显示问题，因为那时「这条回答在答什么」是必要信息。
- 依据条目：`18px 图标 · 弹性正文 · 26px 跳转箭头` 三列网格，摘录最多 2 行（`-webkit-line-clamp: 2`），
  命中片段用低饱和蓝底标出；条目整行可点（也可 Tab + Enter）。
- 更多菜单：复制 / 重新回答 / —— / 删除。**复制、重新回答、删除永远不占卡片常驻空间。**

## 8. 发送范围（第 7–9 态）

收起：

```
┌────────────────────────────────────────────┐
│ 输入问题……                                  │
│ ⌃  论文                             ⋯   ↑  │
└────────────────────────────────────────────┘
```

展开（在发送框**上方**浮出，不挤占回答区）：

```
┌────────────────────────────────────────────┐
│ 发送范围                                ⌄  │
│ ◉ 当前选中文字                              │
│ ○ 当前页面                                  │
│ ○ 整篇论文                                  │
│ ○ 整篇论文 + 联网搜索                    ⊙  │
└────────────────────────────────────────────┘
```

交互规则（全部由脚本实测）：

| 规则 | 实现 |
| --- | --- |
| 点箭头展开 | `#cpBar` 的上箭头 → `aria-expanded=true`，面板从下往上淡入 160ms |
| 点箭头可手动收起 | 面板右上角的 `chev-down` |
| 点选项立即更新 | `aria-checked` 切换 + 发送框标签与图标同步 |
| 选完自动收起 | 选完 130ms 淡出收起 |
| 点外部自动收起 | `pointerdown` 落在 `#rangePanel` / `#cpBar` 之外即收起 |
| 发送后自动收起 | `send()` 内强制收起 |
| 范围沿用到下一次 | `state.scope` 不随发送重置，实测下一次发送仍是「论文 + 网络」 |
| 没有选中文字时置灰 | 「当前选中文字」`disabled`，悬停提示「请先在正文中选择文字」，不用红色告警 |
| 刚选过文字就默认切过去 | 正文 `selectionchange` → 范围自动变 `selection`，并把选中文字显示为发送框上方附件 |
| 联网搜索带细线网络图标 | `web` 图标只出现在选项行尾 |
| 设置页只决定初始值 | 设置页改的是「默认发送范围」，发送框改的是「本次范围」，互不覆盖 |

## 9. 跳转原文与返回（第 5 态）

1. 点依据条目右侧的对角箭头（或整行）→ 左侧 PDF 滚动到对应页（`scroll-behavior: smooth`）。
2. 相关段落加 `.pg-hit`：低饱和蓝底 + 同色内描边；900ms 后淡到更轻的「定位标记」状态。
3. 右侧回答卡片**保持可见**：不新开窗口、不关面板、不清空会话。
4. 卡片左上角出现返回箭头（`back`），阅读区左上角同时出现「返回原位置」浮条（双入口，不必回头找）。
5. 点返回：恢复跳转前的页码与滚动位置，清掉高亮。

> 高亮不是「闪一下就没」：它淡到一个很轻的常驻标记，因为论文阅读里「我刚才是从哪跳过来的」比「闪一下」更有用；
> 返回时统一清除，所以不会累积。

## 10. 笔记、复制、生成与失败

**保存为笔记（第 6 态）**

```
┌────────────────────────────────────────────┐
│ [回答正文……]                                │
│ ┌──────────────────────────────┐  ✓   ✕   │  ← 窄标题行，默认 = 用户的问题
│ │ 为什么自注意力能替代循环结构？ │            │
│ └──────────────────────────────┘            │
│ [书]  [引用②]              [纸张✓]   [⋯]    │
└────────────────────────────────────────────┘
```

- 点纸张+ → 图标原地变「纸张+对勾」并变蓝（`aria-label` 变「已在笔记中」），**不弹任何成功提示**。
- 标题行右侧**只有确认与取消两个图标**；取消则回到未保存态。
- 保存后关联：用户问题、AI 回答、论文名称、页码、原文依据、创建时间（`card.note` + `state.notes`）。
- 左栏「笔记」计数与列表同步 +1（实测 2 项 / 计数 2）。
- **注意**：已保存态的卡片不再显示标题输入行（避免常驻一行输入框占空间）；要改标题请从左侧笔记条目进去改。

**复制（更多菜单里）**：内容 = 回答正文 + 空行 + `—— 论文短标题 · p.3` + `引用：` 列表（每条 `- 标题 · p.4：「摘录」`）。
复制反馈落在**仍然可见的卡片「更多」图标**上：变对勾 1.1 秒后恢复（菜单已经收起，反馈放在菜单项上会看不见）。

**生成中（第 10 态）**：保留问题 + 已生成文字 + 光标；底部**只有**停止图标；依据 / 笔记 / 复制按钮全部不出现；
发送键临时变成停止键（面板底部与卡片底部两处都能停）。

**停止后（第 11 态）**：继续生成 / 重新回答 / 更多；已生成内容一字不删；小字说明「已停止，已生成的内容保留」。

**失败（第 12 态）**：卡片不消失，保留问题、已生成部分、附件、发送范围；底部只有**重试 + 更多**；
短提示「回答未完成」（`--warn` 灰褐，不用红框）；重试是**同一张卡片原地重来**，用户输入不被清空。

## 11. 设置页

三张分组卡片，一屏内可看全（640px 宽居中，行内标签 96px + 控件）。

**卡片一 · 连接**

| 字段 | 控件 | 要点 |
| --- | --- | --- |
| API Key | 密码输入框 | 默认隐藏；右侧眼睛图标切换显示/隐藏（`aria-pressed` + `aria-label` 同步变）；设计稿里放的是假值 `sk-demo-…`，**不展示真实密钥** |
| 模型名 | 单行输入框 | 普通文本 |
| 接口地址 | 单行输入框 | 默认 `https://api.apiyi.com/v1`；右侧 `restore` 图标一键恢复默认地址 |

**卡片二 · 阅读助手样式**

- 主题：跟随系统 / 浅色 / 深色 三选一（`seg-opt`，当前项**蓝边框 + 浅蓝底**）。
- 阅读字号：`− 17 px +`，改完立即生效；下方一行实时预览文字（`--preview-fs` 跟随）。
  范围 13–21px，预览文字用真实句子而不是「示例文字」，这样字号是不是合适一眼能看出来。

**卡片三 · 默认发送范围**：4 个单选（不是两个独立复选框），当前项蓝点 + 浅蓝底。
只决定发送框的初始值；实际发送时可临时改。

**底部**：「恢复默认设置」低强调度文字按钮（下划线灰字，悬停变蓝）。
只重置 **主题 / 阅读字号 / 默认发送范围**；**不删** API Key、论文、笔记、历史问答、阅读进度。
点了之后给一行小字说明「已恢复主题、阅读字号与默认发送范围；API Key、论文、笔记与历史问答都保留。」

## 12. 无障碍

- 每个图标按钮：`aria-label` + `data-tip`（悬停提示）双写；tooltip 元素 `role="tooltip"`。
- 范围单选用 `role="radiogroup"` + `role="radio"` + `aria-checked`；置灰项用原生 `disabled`（能 Tab 到但读屏会报不可用）。
- 依据条目 `role="button"` + `tabindex="0"`，Enter / Space 可触发跳转。
- 展开类按钮带 `aria-expanded`；开关类带 `aria-pressed`；菜单 `role="menu"` / `role="menuitem"`，Esc 关闭且焦点回到触发点。
- 全部可点控件命中区 ≥ 20px 高（脚本断言）；`:focus-visible` 用 2px 蓝色描边。
- `prefers-reduced-motion: reduce` 时关闭动画与平滑滚动。

## 14. 与现有应用的关系（合并路径）

**现状差别**：`public/` 现在用的是**暖米色 + 橄榄绿**（`--bg: #F3E8C3`、`--accent: #556B2F`），
本设计稿用的是**白/浅灰 + 低饱和蓝**。这是两套皮肤，不能靠微调叠加，需要一次**换肤**。

**已经可以直接复用的部分**（不依赖皮肤）：

1. `design/js/icons.js` —— 与 `public/js/icons.js` 同构（同样的 viewBox / 描边 / 无障碍写法），
   只差描边粗细（1.8 → 1.5）和 20 多个新图标（`quote` `note-plus` `note-check` `stop` `play` `web` `selection` `sup-*` `jump` `restore` …），可以整块搬过去。
2. 交互规则本身：范围栏的九条规则、依据展开、跳转 + 返回、笔记标题行、停止 / 重试、复制内容组成，
   都是可以直接照着实现的**行为契约**（脚本里的断言就是验收用例）。
3. `design/reader.css` 的令牌表（§3）—— 把 `public/style.css` 的 `:root` 换成这张表即可换肤，
   注意要同步换掉所有硬编码的暖色（`--sel` `--hl` `--paper` `fig-*` 等）。

**建议的合并顺序**（每步可独立验收、可回退）：

1. 先换令牌（只改 `:root` 两张表 + 硬编码色），跑既有 `test/ux.mjs`、`test/e2e.mjs` 看有没有视觉断言被打红。
2. 再换图标文件（1.8 → 1.5 + 新图标），跑 `test/left-rail.mjs`、`test/ops.mjs`。
3. 最后做「回答卡片 + 依据 + 笔记 + 范围栏」四件套（这是本设计稿真正新增的交互），单独加套件覆盖 §13 的交互动线。
4. 任何一步都要重编 exe（前端是 rust-embed 编译期内嵌的，新增文件不会触发重编译）。

**风险提示**：

- 现有 `public/style.css` 有大量针对暖色的硬编码值，换肤会牵动多处；建议先备份 `public/`（AGENTS.md 的纪律）。
- 现有应用里问答是「结果卡片」形态（有 `#aiArea` 会话流），本设计稿是「一条问答一张卡片」；
  合并时需要决定历史回答是否保留旧卡片形态（设计稿的做法：卡片 + 更多菜单里的删除，不提供全局清空）。
- 设置页现在是弹窗（`#settingsModal`）；设计稿是窗口内的整页卡片页。
  两者都能满足「不是大型弹窗」的要求，合并时二选一即可，**不要两套并存**。

## 15. 明确没做的（避免以后重复讨论）

| 项 | 为什么不做 |
| --- | --- |
| 聊天式气泡、头像、时间戳 | 需求明确：不做成聊天软件；卡片只承载回答与操作 |
| 依据侧边栏 / 新窗口对比 | 会抢正文空间；依据就在卡片内部展开 |
| 笔记编辑的富文本、标签、目录 | 笔记只需要「问题 + 回答 + 论文 + 页码 + 依据 + 时间」，多一层就是负担 |
| 全局「清空会话」 | 有删除单条 + 返回原位置就够了；全局清空是不可撤销的大动作 |
| 联网搜索的独立开关 | 已经作为「整篇论文 + 联网搜索」一个范围选项，避免两处状态互相打架 |
| 设置页的「启动时继续上次论文」等新开关 | 按项目既有纪律，不扩大设置页 |
| 常驻的键盘快捷键浮层 | 不做成控制台；快捷键只在 tooltip 里顺带说明 |
