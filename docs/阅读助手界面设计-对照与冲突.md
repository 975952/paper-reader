## 3. 直接冲突：7 处必须二选一

下面每一条都是「同一个位置，两种做法」，不是谁对谁错。

### 冲突 1 · 发送范围放在哪（最要紧的一处）

| | 现有应用 | 新设计稿 |
| --- | --- | --- |
| 位置 | **设置页**里的两个复选框 | **发送框底部**的上拉栏，4 个单选 |
| 形态 | `#cfgUseFullText` + `#cfgUseWeb`，**默认都开着** | 当前选中文字 / 当前页面 / 整篇论文 / 整篇论文 + 联网 |
| 发送框 | 只有一行 `#composerHint`，而且代码**故意清空不显示** | 常驻显示当前范围（图标 + 极短文字） |
| 代码位置 | `index.html:331-332`、`app.js:4974-4980`（`updateSendScope()` 主动把 `#sendScope` 清空） | — |

**关键背景**：现有代码里有一段注释，写明这是**你的口径**：

> `app.js:206-211`：「范围 / 选中文本 + 当前页 / 清空会话这些……第一个应该是默认全文加联网，在设置里面调节」
> → 所以范围菜单从输入框那排撤掉，搬进设置页，并且 `renderScopeMenu()` 被留成空函数（`app.js:5245`）。

而这次的需求 7/8 又要求把范围上拉栏放回发送框。
**这两个是互斥的，不能同时成立。**

- 选 A（回到发送框上拉栏）：最贴合这次需求，且「不能让用户猜当前发送范围」这条只有 A 能做到
  （现有做法是发送框什么都不显示）。
- 选 B（保持设置页复选框）：符合你十月那次「设置里调节 + 默认全文加联网」的口径，但和本次需求 7/8 冲突。

**我的建议**：选 A，但把 B 的默认值语义保留下来 —— 设置页那组「默认发送范围」单选，只决定发送框的**初始值**（这次需求 2 卡片三本来也是这个意思）。这样两边的诉求都能满足。

### 冲突 2 · 「整篇论文 + 联网搜索」是一个选项还是两个开关

- 现有：两个独立复选框，可以「只看论文不联网」「只联网不带论文」「两个都开」三种组合。
- 设计稿：合并成一个范围选项，共 4 个互斥取值。
- 影响：合并后会**丢掉「只联网、不带整篇论文」**这个组合。
- 建议：按需求选合并；如果确实需要「只联网」，就在上拉栏加第 5 项「仅联网搜索」——不额外占空间，仍是一列单选。

### 冲突 3 · 发送框在哪、会话在哪

- 现有：`#composer` 在 **右栏内部**（`index.html:195`，`#rightCols > #rightSide` 里），下方还有 `#aiBar` 标签行；
  左栏 / 正文 / 右栏共用一条 44px 的**全宽底栏** `#viewerFoot` 放翻页与缩放（`index.html:227-245`）。
- 设计稿：发送框固定在助手面板底部（**一致**）；但翻页 / 缩放做成了浮在 PDF 右下的小条，且没有 `#aiBar` 标签行。
- 影响：改动会牵动 `test/topbar-autohide.mjs`、`test/ux.mjs` 里对底栏与侧栏开关的断言。
- 建议：**保留现有全宽底栏和 `#aiBar`**（它们已经过测试与你的多轮调整），设计稿按现状改；
  浮条版翻页只是设计稿的装饰差异，不值得为它动已验证的底栏。

### 冲突 4 · 设置页是弹窗还是整页

- 现有：`#settingsModal`（模态框，`.modal`）。
- 设计稿：窗口内整页卡片页。
- 影响：`#settingsModal` 被多套测试引用；改成整页要动 `openSettings/closeSettings` 与相关断言。
- 建议：**这条可以不动**。两者都不违反「不是大型弹窗」（现有弹窗结构紧凑、三组字段一屏看完），
  但需求 2 的「三张分组卡片」需要把现有弹窗内部重排成分组卡片——这是纯样式改动，风险低。

### 冲突 5 · 阅读字号控件

- 现有：`<input type="range" min="12" max="19">`（滑块），**没有实时预览文字**。
- 设计稿：`− 17 px +` 步进器 + 一行实时预览文字。
- 影响：换控件本身很小；预览文字是新增元素。
- 建议：按需求换步进器（需求 2 明确写了「左侧减小图标 / 右侧增大图标」），预览文字一起加。

### 冲突 6 · 笔记的数据结构不一样

| | 现有 `state.highlights[]` | 设计稿的笔记 |
| --- | --- | --- |
| 锚点 | `page` + `rects[]`（PDF 坐标）+ `text`（正文摘录）+ `note`（用户写的想法） | 问题 + AI 回答 + 论文 + 页码 + 原文依据 + 创建时间 |
| 来源 | 只从**正文划选**产生 | 从**AI 回答**保存产生 |
| 入口 | 划选气泡的 `pencil` → `#noteBox` | 回答卡片的纸张折角图标 |
| 代码 | `app.js:2558-2576`（`addHighlight`）、`app.js:2825`（`saveNoteBox`） | — |

**这是真正的功能缺口**：现有结构能存「正文摘录 + 我的想法」，但存不下「用户问题 + AI 回答正文」。
- 建议：**不新建一套笔记存储**，在 `highlights[]` 的条目上加一个 `source: 'answer'` 分支：
  - `text` = 用户的问题（当标题）
  - `note` = AI 回答正文（或回答正文 + 依据摘录）
  - `page` = 回答对应的页码（有依据时用依据页码，没有就不写）
  - `rects` = 空（不参与 PDF 高亮，就当一个"文档级笔记"）
- 这样左侧笔记列表、`/api/notes` 读写、删除、编辑全部复用，**服务端一行都不用改**。

### 冲突 7 · 卡片形态：会话流 vs 一条问答一张卡片

- 现有：`#aiArea` 是**消息流**，`.msg` 节点 + `.ai-block`（译文 / 问答两块，一栏只开一个），
  译文按时间堆叠，问答是连续对话（历史会随请求发出去，`app.js:4964-4968` 说明了这点）。
- 设计稿：一条问答 = 一张独立卡片，卡片自带操作条；不强调对话连续性。
- 影响：这是本次需求里**改动量最大**的一条（需求 3-6、10-12 全部建在这个形态上）。
- 建议：**折中**——保留现有会话流容器与恢复机制，把「每条问答结果」的渲染从现在的块状改成卡片
  （卡片就是 `.msg` 内容区的新皮肤 + 新操作条）。这样历史、恢复、重试、缓存命中都不用改。

## 4. 换肤不是冲突，但要说清代价

现有皮肤是**暖米色 + 橄榄绿**（`--bg: #F3E8C3`、`--accent: #556B2F`），设计稿是**白/浅灰 + 低饱和蓝**。
这不是「对不对得上」的问题，是「要不要换」的问题：

- 只改 `:root` 两张令牌表 → 大部分地方会跟着变，**但** `--sel`、`--hl`、`--paper`、`fig-*` 这些地方有硬编码暖色，要一并换。
- 图标描边现有是 `1.8`（`public/js/icons.js:36`），设计稿是 `1.5` → 全局换数字即可，视觉更细。
- 现有图标是"每处内联 SVG"，设计稿是 `icons.js` 集中定义 → 合并时统一走 `iconEl()`。
- **有测试按视觉/结构断言**：`test/ux.mjs`、`test/topbar-autohide.mjs`、`test/left-rail.mjs` 等，
  换肤后要重跑一遍看有没有被打红（README 里列了完整套件清单）。

## 5. 建议的执行顺序（等你拍板冲突 1/2/3/6/7 之后）

1. **先换肤**（令牌 + 图标描边 1.8→1.5），跑 `test/ux.mjs`、`test/e2e.mjs`，修被打红的地方。可独立回退。
2. **设置页分组卡片化**（不动弹窗结构，只重排内部 + 字号换步进器 + 加预览）。跑 `test/ux.mjs`。
3. **发送范围上拉栏**（冲突 1/2 定稿后做）。这是纯新增，先用假数据验证交互，再接线。
4. **回答卡片化**（冲突 7）：`.msg` 内容区换卡片皮肤 + 操作条（依据 / 笔记 / 更多）。跑 `test/stream.mjs`、`test/e2e.mjs`。
5. **笔记双来源**（冲突 6）：`highlights[]` 加 `source: 'answer'` 分支，复用 `/api/notes`。
6. 全部做完：`node test/*.mjs` 全绿 + `desktop\build.bat` + `node test/desktop.mjs`，重编 exe。

每一步都能单独验收、单独回退；**任何一步都不要和另一步混在一个提交里**。

## 6. 一句话回答"和现有功能不对应怎么办"

- **功能上不对应的只有 1 个**：从 AI 回答保存的笔记（现有笔记只从正文划选产生）→ 用 `source: 'answer'` 分支复用现有存储，最小改动。
- **其余"不对应"分两种**：
  - 设计稿漏画现有功能 → **已经补完**（论文操作、划选气泡、页边标记、截图、会话历史、结果标签）。
  - 位置/形态二选一 → **7 处冲突，等你一句话**；其中冲突 1（发送范围放设置还是放发送框）最关键，因为它和你十月那次的口径正好相反。
