# 给 DeepSeek 的下一阶段施工提示词

你正在继续论文阅读器的删减施工。当前核心删减已经落地，但仍是中间态。请按下面顺序完成，不要扩展新的产品功能，也不要为了让测试变绿而先删断言。

## 一、先收尾当前删减，不要先做首页

### 1. 保持并检查备份

- 继续保留 `backup/radical-trim-before-20261005-001306/`。
- 不修改真实 `data/`、`papers/`。
- 所有测试使用 `test/artifacts/` 隔离目录。

### 2. 完成尚未收口的删减

按当前单写者安排依次完成：

- 删除 `#popover` 和完整答案浮层；选区气泡只保留动作和状态提示。
- 清理 `?topbar=static`、`panelWindow`、旧独立窗口兼容路径、废弃第二栏引用。
- 完成 `整篇 / 联网` 的范围菜单，但默认发送范围必须仍是选中文本 + 当前页。
- 将文献关系收敛为“参考文献”，只保留列表、详情、跳回正文、复制引用、用户主动查找 PDF。
- 设置页只保留正式产品需要的字段，不要保留禁用但可见的实验控件。

每删一项都同时清理：DOM、CSS、事件绑定、状态字段、存档迁移、注释、文档和测试引用。

## 二、测试顺序

先跑现有测试，记录真实失败，再决定哪些是产品回归、哪些是旧契约：

```text
node --check public/js/app.js
node test/ux.mjs
node test/selection.mjs
node test/stream.mjs
node test/left-rail.mjs
node test/panels-right.mjs
node test/cards.mjs
node test/e2e.mjs
```

`test/smoke.mjs` 只能作为启动探针，不能当通过依据，因为它明确是零断言。

对已删除功能的测试可以归档，但必须保留归档原因和旧契约说明；禁止把仍然需要的主干断言一起删掉。

## 三、安全工作流必须与删减分开验收

按 `docs/安全与数据边界审计.md` 处理：

- 本地 API token；
- `/api/chat` 禁止请求体覆盖已保存 Key 和地址；
- PDF 导入每一跳重定向重新做私网检查；
- 配置字段白名单和范围限制；
- session / notes / state 的 payload 限制；
- 错误信息和 `/api/papers` 路径脱敏。

Node 和 Rust 必须保持相同结果。安全改动完成后单独跑接口测试，再跑前端回归。

## 四、最后再做首页 / 书架入口

删减和安全回归通过后，新增一个轻量首页，不要做仪表盘。

### 启动规则

- 第一次打开：显示“打开 PDF / 拖入 PDF”和空的最近论文区。
- 普通启动：显示首页和“继续阅读”卡片，不自动进入上次论文。
- 用户双击 PDF、拖入 PDF 或带明确打开参数启动：直接进入阅读页。
- 可在设置中提供“启动时继续上次论文”，默认关闭。

### 首页只保留

- 打开 PDF；
- 拖入 PDF；
- 最近打开；
- 继续阅读；
- 文件名、页码、阅读进度；
- 移除最近记录。

不要添加推荐、统计、阅读时长、学习计划、AI 操作、关系图或空的功能卡片。

### 实现边界

- 把现有 `#welcome` 从阅读区空状态提升为首页状态；
- `renderPaperList()` 负责首页列表；
- `openDoc()` 只在用户选择论文后进入阅读态；
- 明确区分 `home`、`reading`、`search` 三种状态；
- 不要让“无论文空状态”“欢迎页”“错误页”继续共用一个模糊容器。

## 五、最终构建和交付

前端每次改动后必须：

```text
cmd /d /c desktop\\build.bat
node test/desktop.mjs
```

确认根目录 exe 与桌面副本大小、SHA256 一致，并确认测试启动的是新 exe，不是旧进程。

最终汇报必须包含：

1. 实际删除了哪些用户入口和运行时状态；
2. 哪些兼容代码仍保留以及为什么；
3. Node 测试结果；
4. Rust / exe 测试结果；
5. 未完成事项和风险；
6. 首页是否已完成，若未完成不得把它写成已交付。

不要在本阶段新增 Coach、推荐、统计、术语库、更多 AI 操作或新的面板布局。
