## 0. 结论摘要

项目功能完成度高、注释密度罕见（大量"为什么这么写"的实测记录，这是**资产**），
但代价是：**所有约束只活在注释里**——没有构建、没有类型、没有 lint、没有 CI，
删除功能后留下的"墓碑"与在用的代码混在同一个 6800 行文件里，读者无法判断哪条分支还活着。

## 2. P0：会丢数据 / 会坏交付物 / 有安全面

### 2.1 【安全】不校验 Host + 首页免认证吐 token → DNS rebinding
- `server.js:1168`：`const url = new URL(req.url, \`http://${req.headers.host || HOST}\`)` —— `host` 只被用来拼 URL，从未被校验。
- `server.js:1445` 起：`/` 走静态分支，**不经过 token 校验**，而返回的 HTML 里注入了 `<meta name="prt-token" content="…">`。
- `security.js:157-169`：`originAllowed()` 在 Origin 与 Referer **都不存在**时直接 `return true`。
- `desktop/src/server.rs:113` 同样只用不验。

后果：恶意页面把域名 rebind 到 `127.0.0.1:8787` → 同源 `fetch('/')` 读到 token → 之后所有 `/api/*`（含使用用户 API Key 的 `/api/chat`、全部笔记与会话）都可用。

改法：两个后端都在入口校验 `Host ∈ {127.0.0.1:PORT, localhost:PORT, [::1]:PORT}`，不匹配直接 403；`originAllowed` 的默认值改成 `false`（非浏览器客户端改成显式白名单或自定义头）。**加一条开了 token 的冒烟测试**（现在 `test/desktop.mjs:95` 用 `PRT_REQUIRE_TOKEN=0` 起 exe，这条路径零覆盖）。

### 2.2 【数据】Rust 版空 body 会把整篇笔记清空
- `desktop/src/api.rs:723-728`：`parse_json` 对空 body 直接 `Ok(json!({}))`。
- `desktop/src/server.rs:199-204`：`read_to_end` 失败当作「空 body」返回 `Ok(Vec::new())`。
- `desktop/src/api.rs:414-422`：`items` 缺失/非数组 → `json!([])` → **整体写盘** → 回 `{ok:true}`。

后果：传输中断/读体失败 → 该论文的笔记被覆盖成 `[]`，且前端会提示成功。Node 版这条路是 400 且不写盘（`server.js:134`），所以这是 exe 独有的静默数据丢失。`POST /api/session` 同理。

改法：读体失败返回 `Err` → 400；`items` 缺失一律 400，绝不写空数组。

### 2.3 【功能】Node 版 `DELETE /api/session` 不可达
- `server.js:1349-1369`：`/api/session` 分支内 `GET`/`POST` 之外**直接 `return 405`**。
- `server.js:1417-1425`：`DELETE /api/session` 的实现写在它后面，**永远执行不到**。

后果：用 `node server.js` 开发时删会话静默失败；而 exe（Rust）是真实现的 —— 两套后端行为分叉，测试默认打 exe 所以红不了（`test/stream.mjs:278` 断言 200，但跑的是 exe）。

改法：把 DELETE 合进同一个 `if (pathname === '/api/session')` 分支；并补一条「同一个套件分别打 Node 与 exe」的契约测试。

### 2.4 【安全】Rust 侧 SSRF 拦截可绕过
- `desktop/src/api.rs:881` `is_private_host(host: &str)` 走的是手写 `split_once("://")` + 点分四段（`parse_ipv4_quad` 要求恰好 4 段、每段纯数字）。
- 于是 `http://127.1/`、`http://2130706433/`、`http://0x7f000001/` 全部**不算内网**；而 ureq 底层用 WHATWG 的 `url` crate，会把这些规范化成 `127.0.0.1` 真去连。
- Node 侧用 `new URL()`（`server.js:880`）能规范化，所以两侧安全边界不等价。

改法：Rust 侧改用 `url::Url::parse(...).host_str()` 做判定，删掉手写切分；`resolve_redirect` 同样处理。

### 2.5 【数据】中文名论文的 docId 两套后端算出不同的键
- `server.js:186` 附近：用 **UTF-16 code unit** 累加哈希，并**折叠**连续非法字符。
- `desktop/src/api.rs:473` 附近：用 **UTF-8 字节**累加、逐字符替换不折叠，还少一个候选分支。

后果：ASCII 文件名一致，**中文命名**的论文会算出两个键 —— 会话列表时有时无、删除删不掉、笔记"消失"。

改法：Rust 侧改成逐 `encode_utf16()` 累加 + 折叠 + 补齐候选；加一条「同一组文件名两侧结果相同」的对照测试。

### 2.6 【数据】阅读进度可能清空其它论文的记录
- `app.js` ≈2104：`catch { serverState = {}; }` —— GET `/api/state` 一次失败就把本地镜像清空。
- ≈2110-2112：紧接着用 `{...serverState, docs}` 整体 POST。
- `server.js:1284-1285`：服务端是 `{...cur, ...patch}` **浅合并**，`docs` 这个整键被替换。

改法：GET 失败进入"禁止落盘"态（或按 docId 改增量接口），绝不能拿空镜像整体覆盖。

### 2.7 【数据】`config.json` 损坏 → API Key 被静默清零
- `server.js:208-209`：`readDataFile` 把 ENOENT 与 JSON 解析失败合并成同一个 fallback `{}`。
- `server.js:1269`：`const next = { ...DEFAULT_CONFIG, ...cur, ...patch }` → `apiKey` 取到空串并写回。

改法：区分不存在/损坏；损坏时回 5xx 并拒绝写入（先改名为 `config.json.bad`）。

### 2.8 【交付】源码 zip 是坏的（本次已修）
- `test/pack.mjs` 的 `INCLUDE` 曾漏掉 `security.js`（`server.js` 第一句就是 `require('./security')`）、漏 26/47 个套件、还列着不存在的 `test/export.mjs`。
- zip 用 PowerShell 5.1 的 `Compress-Archive` 打，条目名是**反斜杠**（实测 323/328），Linux/macOS 解开全毁。

已修：白名单改成「`test/` 整目录 + DENY 黑名单」，补 `security.js`，打包改用 `tar -a -c -f`（bsdtar，正斜杠）。
实测新包 389 条目、0 个反斜杠、含 `./security.js`、含全部 47 个套件、0 个 `profile-*`/`artifacts` 条目。

### 2.9 【仓库】623 个 Chrome 用户目录文件进了 git（本次已清理）
`git ls-files test` 共 671 个，其中 `test/profile-launch-*` 占 **623**（≈61MB），源头是
`test/left-rail.mjs` 的 `userDataDir` + 一次 `git add -A`；`.gitignore` 里只有 `test/artifacts/`。

已修：`git rm -r --cached`，`.gitignore` 增加 `test/profile-*/`，`pack.mjs` 的 DENY 同步加规则。

### 2.10 【可维护性根因】没有分层：一个类 + 一个巨型模块吃掉全部状态
- `PdfViewer` 构造函数里 30+ 个 `this.*` 字段；`app.js` 的 `state` 字面量只声明了一半字段，
  其余靠 `state.xxx = ...` 现场创建（`openSeq`/`msgSeq`/`_lastPt`/`_fileEntries`…）。
- 状态有 4 条并行轨道：`state` + 模块级单例（`localObjectUrl`/`citeActionTimer`/`sessionSaveInFlight`/`cardPos`）+ DOM expando（`root.__sessionRecord`/`__noteBtn`/`__question`）+ 服务端与 localStorage。
- 唯一对外测试接口是 `window.__ctx`（40 键，含 `setFullLimit` 这种改内部量的后门）。

改法：先做"最低成本分层"——把纯计算（布局宽度、范围推导、文本裁剪、图片几何）抽成无 DOM 依赖的模块，
`state` 字段全部进字面量声明，`__ctx` 只暴露稳定契约。

- `test/links.mjs:233` 30s 超时（联网检索）；`test/relations.mjs` 2 条联网断言红。
  这两类的共同问题是**把外网依赖当成本地回归**，应当在无网环境下 skip 而不是 fail。

### 5.7 套件自起的服务不保证回收
`translate-order.mjs` / `stream.mjs` 这类套件会自己 `spawn(server.js)` 起一个随机端口的服务。
实测跑完一轮 5 个套件后，机器上残留 **6 个 `node server.js` 进程**（占用 8971~8997 端口）——
下一次跑测试时若端口被占，套件可能连到**上一轮的旧服务**（旧代码、旧数据）上，
结论就不可信了。建议 runner 里用 `try/finally` 统一 kill，或在启动前扫一遍端口。

### 5.8 交付链一致性只靠 mtime 启发式
- `desktop/build.bat` 靠"改 `src/assets.rs` 的 mtime"强制重编译（rust-embed 不跟踪新增文件）；
- `test/desktop.mjs:79` 用「exe 不比 public 新」判定是否重新内嵌 —— 而 build.bat 又把 exe 的 mtime 设成 public 的最新时间，这个断言**恒真**。
- `PROGRESS.md` 里记的 exe 大小（10,181,632 B）与实测（10,210,816 B）已经不一致。

建议：`build.rs` 里 `println!("cargo:rerun-if-changed=../public")`，让 cargo 自己判断；
再加一条「exe 内嵌资源数 == `public/` 文件数」的自检（`assets.rs` 已有 `count()`，只差断言）。
