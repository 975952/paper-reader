# 首页 / 书架页设计方案

> 状态：**方案，未施工**。本文只描述要做什么、边界在哪、怎么验收。
> 依据：`docs/给DeepSeek的下一阶段提示词.md` §四。**不新增任何 AI 入口、推荐、统计、学习计划、关系图或空功能卡片。**

## 0. 一句话定义

首页只解决两件事：**选择要读的论文**、**继续上次阅读**。
它不是仪表盘，是一个带"最近打开"的文件入口。

## 1. 现状（施工前必须知道的事实）

| 部件 | 现在是什么 | 位置 |
| --- | --- | --- |
| `#welcome` | 阅读区里的**空状态**：logo + 一句 tagline + 三步提示 + `#welcomeWarn` | `index.html:142-151` |
| `renderPaperList()` | 把 `state.papers` 渲染成 `#fileList` 里的 `<li>`，点击 → `openDoc()` | `app.js:1985-2007` |
| `openDoc()` | 切换论文的唯一入口；隐 `#welcome`、清会话、`viewer.load()` | `app.js:2067+` |
| `maybeReopenLast()` | 启动时：有 `?open=` 就开那一篇；否则**自动打开上次论文** | `app.js:5750-5775` |
| `state.json` | `{ docs: { <docId>: {page,scale,fit,ts,name} }, lastDoc, lastUrl, lastName }` | 服务端 `data/state.json` |
| 拖入 / 选文件 | `#dropzone` + `#fileInput`，走 `openLocalFile()` → 上传 → `openDoc()` | `app.js:2009-2065` |

**关键冲突**：`maybeReopenLast()` 现在**无条件自动打开上次论文**，这正是要改掉的行为。

## 2. 页面结构

```
#main
├── 左栏（不变）  文件 / 目录 / 笔记 / 参考文献
├── 正文区 viewer-wrap
│   ├── #home                       ← 新增：首页面板（#welcome 升级而来）
│   │   ├── .home-head             应用名 + 一句话 tagline
│   │   ├── .home-actions          [打开 PDF] [拖入 PDF 区]
│   │   └── .home-recent           「最近打开」
│   │       ├── .home-continue     继续阅读卡片（有记录时才有）
│   │       └── .home-list         最近论文列表（每行可删）
│   ├── #searchBar（不变）
│   ├── #viewer（不变，PDF 画布）
│   └── .statusbar（不变）
├── 右栏（不变）
└── 活动栏（不变）
```

**为什么把首页放进 `viewer-wrap` 而不是新开一页**：不引入路由，不破坏"一次只显示一个正文态"的既有结构；
`#home` 与 `#viewer` 互斥显示（`body.reading` 有/无）。

### 首页元素清单（**只允许这些**）

| 元素 | 说明 |
| --- | --- |
| 应用名 | 复用现有 logo + 「论文阅读器」 |
| 打开 PDF | 触发现有 `#fileInput` |
| 拖入 PDF | 复用 `.dropzone` 的拖放逻辑（整页可拖，不只是那个小方块） |
| 继续阅读 | 单张卡片：文件名 + `第 N 页 / 共 M 页` + 进度条 + 缩略图占位（**不引入 PDF 缩略图渲染**，用页数比例条即可） |
| 最近打开 | 列表，按 `ts` 倒序；每行：文件名 + 页码 + 相对时间 |
| 文件名 / 页码 / 阅读进度 | 上面两处都用同一份数据 |
| 删除最近记录 | 每行一个「×」，只删**这一条的阅读记录**，不删 `papers/` 里的文件 |

**明确不做**：AI 操作按钮、推荐、统计、阅读时长、学习计划、关系图、装饰性空卡片。

## 3. 状态转换图

三个顶层态：`home`（首页） / `reading`（在读） / `search`（全文搜索打开）。

```
                    ┌──────────────────────────────────────────┐
                    │                                          │
   [启动]           │                                          │
     │              │                                          │
     ├─ 有 ?open= ──┼──────────────────────────► reading       │
     ├─ 拖入/双击 ──┼──────────────────────────► reading       │
     └─ 其他 ───────┴──► home                                 │
                                                              │
   home ──点「继续阅读」/ 点列表项 ──────────────────► reading  │
   home ──点「打开 PDF」→ 选文件 ────────────────────► reading  │
   home ──拖入 PDF ─────────────────────────────────► reading  │
                                                              │
   reading ──点顶栏「首页」/ Esc(无搜索) ────────────► home ────┘
   reading ──Ctrl+F ────────────────────────────────► search
   search  ──Esc / 关闭 ────────────────────────────► reading
```

**返回首页时论文不卸载**：`viewer` 保持已加载的 PDF，正文只是被 `#home` 盖住。
理由：重新打开同一篇要重走 `openDoc()`（重新取 PDF、清会话、重解析），代价高且会丢当前会话上下文。
返回首页只做 `body.reading = false`，`state.doc` 保持不变；再点「继续阅读」若无变化则直接 `body.reading = true`。

## 4. 八种状态的具体表现

| # | 状态 | 首页表现 |
| --- | --- | --- |
| 1 | **首次启动、`papers/` 没有论文** | 打开 PDF + 拖入提示；最近区显示一句「还没有论文，拖一个 PDF 进来」；**不显示**继续阅读卡片 |
| 2 | **有论文但没有阅读记录**（`docs` 为空） | 最近列表按文件名列出全部论文，每行无页码；**不显示**继续阅读卡片 |
| 3 | **有最近论文**（有 `docs`，但 `lastDoc` 为空） | 列表按 `ts` 倒序，显示页码与相对时间 |
| 4 | **有一篇可继续阅读**（`lastDoc` 有效且在列表里） | 顶部一张「继续阅读」大卡：文件名 + `第 N 页 / 共 M 页` + 进度条；下方列表里该条高亮为当前 |
| 5 | **最近文件已被移动或删除** | 该条**不再出现在首页**（不显示死链接）。首次发现时静默清理 `state.json` 里对应的 `docs` 条目与 `lastDoc`；若被删的正是 `lastDoc`，继续阅读卡片消失，其余列表照常 |
| 6 | **拖入 PDF** | 整页进入拖放态（描边高亮）；松手 → 上传 → 直接进 reading，**不经过首页** |
| 7 | **打开文件选择器** | 点「打开 PDF」触发 `#fileInput`；选完 → 上传 → 直接进 reading |
| 8 | **当前已有论文时返回首页** | 首页照常渲染（继续阅读指向当前这篇）；`#viewer` 仍在内存里；再点该篇**不重新加载** |

## 5. `state.json` 如何复用

**结论：不改结构，只改写入时机与新增一个"删除记录"接口。**

现状结构已经够用：

```jsonc
{
  "docs": {                       // 每篇论文一条阅读记录
    "<docId>": { "page": 11, "scale": 1, "fit": false, "ts": 1791115129095, "name": "attention-is-all-you-need.pdf" }
  },
  "lastDoc": "<docId>",           // 继续阅读指向谁
  "lastUrl": "...",
  "lastName": "..."
}
```

复用映射：

| 首页要显示 | 取自 |
| --- | --- |
| 最近打开列表的成员与排序 | `docs` 的键，按 `ts` 倒序 |
| 每行页码 | `docs[id].page` |
| 每行文件名 | `docs[id].name`（**不依赖 `papers/` 列表**，这样文件被移走也能识别该记录已失效） |
| 「继续阅读」指向 | `lastDoc`（缺失时退回 `docs` 里 `ts` 最大的一条） |
| 总页数 M | **不存**；打开时由 `viewer` 报（首页卡片在未加载时只显示"第 N 页"，已加载则显示 `N / M`） |

**需要新增的唯一服务端能力**：删除一条阅读记录。
建议 `DELETE /api/state?doc=<docId>`，语义是「从 `docs` 里删掉这一条；如果 `lastDoc` 正是它，则一并清空 `lastDoc/lastUrl/lastName`」。
**不删 `papers/` 里的文件** —— 文案必须是「移除最近记录」而不是「删除论文」。

> 备选（不推荐）：在首页直接给 `serverState.docs[docId] = undefined` 再整体 POST。
> 现有 `POST /api/state` 是浅合并 `{...cur, ...patch}`，`undefined` 不会真的删键，要额外实现深合并语义，反而更容易写坏旧数据。独立的一个动词更清楚，也更好限制（只允许删 `docs` 里的一个键）。

## 6. 改造边界

### 6.1 `#welcome` → `#home`

- **保留 `#welcomeWarn` 的角色**：它现在承载「没配 API Key」等警告（由 `checkConfigWarning()` 驱动）。
  改造后把警告移到 `.home-head` 下方，**id 与驱动逻辑都不动**，避免牵动既有断言。
- `#welcome` 的 `hidden` 类语义从「有没有文档」改为「是不是首页态」。
  现有三处直接操作它（`openDoc` 隐、打开失败显、boot 显），改成统一走一个 `setView('home'|'reading')`。
- 三步提示（1 拖入 2 划选 3 按 ✦）**删掉**：它教的是 AI 用法，而首页的职责只是选题。
  首次使用的引导改由「打开 PDF」按钮本身 + 空列表文案承担。

### 6.2 `renderPaperList()` —— 不动，另加一个渲染函数

`renderPaperList()` 是**左栏文件列表**的渲染器，与首页职责不同：

| | 左栏 `#fileList` | 首页最近列表 |
| --- | --- | --- |
| 数据源 | `state.papers`（磁盘上的文件） | `serverState.docs`（阅读记录） |
| 排序 | 服务端给的 `mtime` 倒序 | `ts` 倒序 |
| 筛选项 | 有 `#fileFilter` | 无 |
| 点击语义 | 打开该论文 | 同上，但若是当前篇则不重载 |

**所以新增 `renderHome()`，不改 `renderPaperList()`。** 两者共用 `openDoc()` 这一个出口。

### 6.3 `openDoc()` —— 只加一个"同篇短路"，不改内部

- 新增：`openDoc(same)` 时若 `state.doc.docId === docId && viewer?.pdf`，只 `setView('reading')` 并直接返回，**不重走加载与会话清理**。
- 其余逻辑（会话保存、代数令牌 `openSeq`、`relBumpGen()`、清空缓存）**一行不动**。
- `openDoc` 内现有的 `$('#welcome').classList.add('hidden')` 改成 `setView('reading')`。

### 6.4 `maybeReopenLast()` —— 行为反转（本次的核心改动）

```
现在：有 ?open= → 开那一篇；否则 → 自动开上次论文
改为：有 ?open= → 开那一篇（进 reading）；否则 → 一律留在 home
```

- **删除**「自动打开上次论文」那一段（`app.js:5758-5773`），只保留「清理已失效的 `lastDoc`」这段副作用——
  它现在是死代码路径，改造后要**保留并前移到首页渲染时**执行，因为首页需要知道 `lastDoc` 是否还有效。
- `?open=` 找不到文件时：现在弹 toast 后继续走自动恢复；改后弹 toast 并**留在首页**。
- **不新增"启动时继续上次论文"设置**（按产品负责人要求，避免继续扩大设置页）。

## 7. 布局规则

### 浅色 / 深色

- 全部用现有主题令牌，**不新增颜色常量**：背景 `--bg`、卡片 `--panel`、边框 `--line`、次要文字 `--muted`、强调 `--accent`。
- 继续阅读卡片与列表行在两种主题下都靠 `--panel` + `--line` 区分层次，不依赖阴影（深色下阴影不可见）。
- 进度条：轨道用 `--line`，填充用 `--accent`，两种主题下都满足对比度。
- 主题切换必须**即时生效**（现有 `applyUiStyle()` 驱动），首页不能缓存颜色。

### 窄窗口（关键）

按宽度分三档，**优先保证正文不被压到 0**（这是已被 e2e 覆盖的既有约束）：

| 窗口宽 | 首页行为 |
| --- | --- |
| `≥ 900px` | 单列居中，内容区 `max-width: 720px`；继续阅读卡片横向布局（左文件名+进度，右「继续阅读」按钮） |
| `600–900px` | 内容区吃满，继续阅读卡片改为纵向；最近列表行高收紧 |
| `< 600px` | 首页自身可纵向滚动；**左右栏允许被自动收起**（沿用现有 `applyResponsiveLayout()` 逻辑，首页不额外干预）；按钮改为整行等宽，点击热区 ≥ 40px |

其他硬约束：

- 首页**不改变左右栏的收起状态**：进入/离开首页不写 `sideIntent`，否则用户回来发现侧栏被动过。
- 首页不触发 `refitViewer()`（没有正文要重排），但**返回 reading 时要补一次**，因为期间窗口可能变过。
- 长文件名：单行省略号 + `title` 属性给全名；页码与时间不参与省略。
- 键盘可达：`打开 PDF`、`继续阅读`、每个列表项、每个「×」都必须能 Tab 到，`Enter` 触发；`×` 要有 `aria-label`（`移除「文件名」的阅读记录`），删除后焦点落到相邻项（删除的空状态则落到「打开 PDF」）。

## 8. 验收用例（8 条）

每条都要在**隔离目录 + 全新服务**上跑，不碰真实 `data/`、`papers/`。

| # | 用例 | 期望 |
| --- | --- | --- |
| A1 | 首次启动，`papers/` 为空 | 停在首页；显示「打开 PDF」「拖入 PDF」；最近区是空态文案；**没有**继续阅读卡片；零 pageerror |
| A2 | `papers/` 有论文、`state.json` 为空 | 停在首页；列表列出全部论文、每行无页码；**没有**继续阅读卡片 |
| A3 | 有阅读记录（`docs` 非空，`lastDoc` 有效） | 首页顶部出现继续阅读卡片，显示正确的文件名与 `第 N 页`；列表按 `ts` 倒序 |
| A4 | **普通启动不自动进入上次论文** | 带 `state.json` 启动后 `document.body` 不是 reading 态、`#home` 可见、`state.doc === null`；**这是本次最重要的一条** |
| A5 | 点「继续阅读」才进入阅读页 | 点击后进入 reading，且**恢复到记录里的页码与缩放**（与 `docs[id].page/scale/fit` 一致） |
| A6 | 带明确 `?open=<文件名>` 启动 | **直接进 reading**，不停留首页 |
| A7 | 拖入 PDF / 双击 PDF | 上传后**直接进 reading**，并出现在最近列表里 |
| A8 | 最近文件已被删除 + 移除最近记录 | 启动后该条**不出现在首页**、`state.json` 里对应键被清掉、`papers/` 里的文件**没有被删**；点某行「×」只移除该行记录，焦点落到相邻项 |

回归护栏（首页改完后必须仍然全绿）：
`boot-probe`、`zoom`、`outline`、`links`、`math`、`stream`、`ops`、`left-rail`、`selection`、`ux`、`e2e`，
以及 `desktop\build.bat` + `node test/desktop.mjs`。

**已实测核对（施工前就验掉了，不必等施工）**：担心「A4 反转自动恢复会打破既有套件」，实际**不冲突**：

- 需要文档的套件一律显式带 `?open=`（A6 路径，仍然直接进阅读页）：
  `e2e.mjs:188`、`stream.mjs:86`、`ux.mjs:129` 都是 `?open=<文件名>&topbar=static`。
- 不带 `?open=` 的套件（`zoom:46`、`outline:39`、`selection:57`、`context:117`、`relations:131`、`ux:125`）
  在 `goto` 之前会先 `POST /api/state` 把 `lastDoc/lastName/lastUrl` **显式置空**，
  所以它们本来就没在依赖「自动恢复上次论文」这条路径。
- `e2e.mjs:1312-1315` 专门 `about:blank` → 清 state → 重新打开，同样不依赖。

结论：**`maybeReopenLast()` 的反转不会打破现有门禁**，但施工后仍要实测确认（这是纪律，不是怀疑）。

## 9. 施工顺序（批准后）

1. `index.html`：`#welcome` → `#home` 结构（保留 `#welcomeWarn`）。
2. `style.css`：首页样式 + 三档窄窗规则（只用现有令牌）。
3. `app.js`：`setView()`、`renderHome()`、`openDoc()` 同篇短路、`maybeReopenLast()` 行为反转。
4. `server.js`：`DELETE /api/state?doc=`（只删一条记录，不删文件）。
5. 新增 `test/home.mjs` 覆盖 A1–A8。
6. 跑全部门禁 + `build.bat` + `desktop.mjs`，重编 exe。

## 10. 风险与权衡

| 风险 | 处理 |
| --- | --- |
| A4 与既有 e2e 的启动假设冲突 | 施工前先跑一遍 `e2e.mjs` 记录基线；改完对比，确认 e2e 走的是 `?open=`（A6 路径） |
| 用户习惯"打开就是上次那篇" | 这是产品负责人的明确要求；代价是每次多一次点击。若日后要恢复，加设置项即可（本次明确不加） |

| 阅读记录多时首页变长 | 列表默认只显示最近 8 条，其余折叠为「全部 N 篇」——**先不做**，等真出现再定；本版直接全列并可滚动 |
