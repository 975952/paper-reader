# 论文阅读器安全与数据边界审计

审计范围：`server.js`、`desktop/src/api.rs`、`desktop/src/chat.rs`、前端发送范围。
本文件只记录问题和修复要求，不修改产品行为。

## P0：本地 API 没有认证

Node 和 Rust 服务都绑定在 `127.0.0.1`，但以下接口没有 token、会话 nonce 或 Origin 校验：

- `/api/chat`
- `/api/config`
- `/api/state`
- `/api/notes`
- `/api/session`
- `/api/upload`
- `/api/import-pdf`

任何本机进程都可以调用；浏览器页面还可能通过 CSRF 或简单请求触发写入、上传、联网请求和 AI 请求。

### 修复要求

1. 启动时生成不可预测的随机 session token。
2. 只把 token 注入本应用页面，所有 `/api/*` 请求必须带自定义请求头。
3. Node 和 Rust 两套后端使用同一套校验规则。
4. `Origin` / `Referer` 白名单只作为附加防线，不能替代 token。
5. token 不出现在日志、错误信息或普通页面 DOM 文本中。
6. 401/403 不应写入任何用户数据。

浏览器开发模式可以通过启动参数或测试环境变量注入 token；不能为了测试把生产认证关闭。

## P0：聊天请求允许调用方覆盖 API 地址和 Key

`server.js:266-269` 和 `desktop/src/chat.rs:63-77` 会从请求体读取 `baseURL`、`apiKey`、`model`。
这意味着拿到本地 API 调用权的页面可以：

- 把用户 Key 转发到任意服务器；
- 让应用服务器向任意 URL 发出带 Key 的请求；
- 绕过设置页的用户确认。

### 修复要求

- 普通 `/api/chat` 只使用已保存配置里的 `baseURL` 和 `apiKey`。
- 请求体只允许传 `messages`、`stream`、受限的 `temperature`、`max_tokens`、上下文范围等字段。
- 自定义 API 地址只能通过设置页保存，并在保存时做协议、主机和路径校验。
- 若必须支持单次临时地址，必须显式弹出确认，且不能自动带出已保存 Key。
- Node 与 Rust 的字段白名单和校验必须完全一致。

## P1：PDF 导入的重定向可能绕过内网检查

`server.js:737` 只检查初始 URL 的主机，`fetch(..., redirect: 'follow')` 会自动跟随重定向。
一个公网地址可以重定向到本机、局域网或云元数据地址。

### 修复要求

- 改为手动跟随重定向。
- 每一跳重新解析协议和主机，并执行私网、回环、链路本地、云元数据地址检查。
- 限制重定向次数，例如最多 3 跳。
- 最终响应仍必须检查大小、`Content-Type`、`%PDF-` 文件头。
- Rust `import_pdf` 使用相同策略。

## P1：配置字段没有严格白名单和范围限制

`/api/config` 会合并请求体字段；`temperature`、`idleMs`、模型名、接口地址等可能写入任意值。

### 修复要求

只接受明确字段：

```text
apiKey, baseURL, model, visionModel, targetLang,
temperature, stream, idleMs, theme, fontSize
```

并限制：

- `temperature` 在合理范围内；
- `idleMs` 有最小值和最大值；
- URL 只允许 `http` / `https`，禁止凭证、控制字符和明显内网地址；
- 字符串长度有上限；
- 未知字段直接忽略或返回 400。

## P1：状态、笔记、会话接口可被大 payload 拖垮

通用 JSON 读取上限为 64MB，但 `state`、`notes`、`session` 没有按接口设置更小上限。
会话内容还可能包含大量历史回答和附件元数据。

### 修复要求

- `state`、`config`：小于 1MB；
- `notes`：按条目数量和总字数限制；
- `session`：按论文限制历史条目数、总字符数和附件元数据大小；
- 超限返回 413，不截断后静默保存。

## P1：API Key 明文落盘

当前配置写入 `data/config.json`。这对本地开发可接受，但正式 Windows 版至少应该保护文件权限，最好使用 Windows Credential Manager 或 DPAPI。

### 修复要求

分阶段处理：

1. 立即：确保配置文件只对当前用户可读，日志和错误不打印 Key。
2. 桌面版：使用 DPAPI / Credential Manager 存储 Key，`config.json` 只保存是否已配置。
3. 浏览器开发版：明确提示这是本机明文开发存储，不把它伪装成安全保险箱。

## P2：接口泄露本地路径

`/api/papers` 返回 `dir: PAPERS_DIR`。这会把用户本机的绝对路径暴露给任何能访问本地服务的页面。

### 修复要求

- 正式接口删除 `dir` 字段。
- 诊断模式才允许返回路径，并且必须显式开启。

## P2：错误信息过度暴露实现细节

部分错误会把完整上游 URL、文件路径或底层网络错误直接返回给前端。

### 修复要求

- 用户提示保留可操作信息。
- 详细 URL、路径和底层异常只写本地诊断日志。
- 日志统一过滤 `Authorization`、`apiKey`、请求正文和论文原文。

## 验收要求

- [ ] 未带 token 的本地 API 请求全部返回 401/403。
- [ ] 页面不能通过请求体把保存的 Key 转发到任意地址。
- [ ] 导入 PDF 的每次重定向都会重新做私网检查。
- [ ] Node 与 Rust 对 URL、字段、大小限制的结果一致。
- [ ] 配置、状态、笔记、会话超限返回 413/400，不写坏旧数据。
- [ ] `/api/papers` 默认不返回绝对路径。
- [ ] 日志和错误响应中搜索不到 API Key 或 Authorization 内容。
- [ ] 现有隔离测试仍能运行，但测试认证必须显式注入，不能依赖生产后门。

## 排期建议

1. P0 本地 API token + 聊天配置覆盖禁止。
2. P1 重定向 SSRF + 配置字段白名单。
3. P1 payload 限制 + Key 存储保护。
4. P2 路径和错误信息脱敏。

在这些项目完成前，不建议继续增加联网搜索、自动导入或更多 AI 入口。
