## 二、顺手抓到并修掉的两个真 bug

### A. Rust 后端缺 `/api/sessions`（多会话在 exe 里是坏的）

Node 版加了 `/api/sessions`，但 **exe 用的是 Rust 后端**，那边没有这个路由：
请求落到 SPA 回落 → 返回 `index.html` → 前端 `JSON.parse` 失败 → 当成"还没有会话"。
**表现就是：开发时能用，装到 exe 里新建会话后列表永远是空的。**

已在 `desktop/src/api.rs` 补 `sessions()`（列会话 + 元信息）与 `session_file()`
（`sid` 支持 + DELETE 删除），路由在 `desktop/src/server.rs` 注册，
`store.rs` 补 `list_data_files()` / `remove_file()`。`cargo check` 零 warning 零 error。

### B. 点已开的图标会把整条左栏收掉

`initRails()` 里原本是「再点同一块 → 收成活动栏」，与你的口径
「点击已开的图标也不会关闭侧栏，**而是不做反应**」相反。已改成 no-op；
收起左栏改由顶栏按钮 / 拖分隔条负责。

## 1. 底栏应该一直都有，主页也要有

**用户原话**：「底栏应该是一直都有，主页也要有」

**现状**：底栏（`#viewerFoot`）只在阅读态出现 —— CSS 里有一条
`body:not(.reading) .viewer-foot { display: none; }`（当初的想法是「首页没有正文，
翻页/缩放没意义」）。但这让整体布局在首页时少一截，看起来像坏了。

**改法**：去掉那条隐藏规则，底栏常驻；首页时把「与文档相关」的控件置禁用态
（翻页、页码、缩放按钮 `disabled`），而不是整条消失 —— 布局稳定，且用户一眼看出
「这些要打开论文才能用」。

**验收**：首页态下 `#viewerFoot` 高度 = 44、贴窗口底部、控件存在且 `disabled`；
进入阅读态后自动启用。

## 2. 从 PDF 回首页有残留，还能滚动

**用户原话**：「现在的首页就是从 pdf 回到首页，会有一部分 pdf 残留，还可以滚动」

**现状**：`setView('home')` 只把 `body.reading` 去掉、给 `#home` 去掉 `hidden`，
但 `#viewer` 里已经渲染的 PDF 页面**没有隐藏**。CSS 里 `#home` 与 `#viewer` 是兄弟，
但没有任何规则让「非阅读态时 viewer 不显示」—— 于是 viewer 的内容还占着位置/还能滚。

**改法**：补一条 `body:not(.reading) #viewer { display: none; }`（与 `.home` 对称），
并确认首页时 `#viewer` 的滚动位置不会被保留成「半截」。

**验收**：阅读态 → 点顶栏「首页」→ `#viewer` 的 `getBoundingClientRect()` 高度为 0、
`.page` 不可见、首页可见且自身可滚动；再点「继续阅读」回到原页。

## 3. 左侧栏有两处可以调的图标（重复入口）

**用户原话**：「现在左边侧栏有两处可以调的图标」

**现状**：左栏有**两个**面板入口：
- 左栏最左边那条**活动栏** `#railLeft`（四个图标：文件/目录/笔记/参考文献）
- 左栏**底部**的图标坞 `#panelDock`（同样四个图标）

两处点同一个东西，属于重复入口（用户前面已经表达过「入口太多」）。

**改法**：二选一。倾向**保留左边那条窄活动栏**、删掉底部的 `#panelDock` ——
因为活动栏常驻在最左边、正是用户说的「左侧栏应该一直都是几个选项在最左边的一个小侧栏」。
需要同时清掉 `initPanelDock()`、`syncPanelDock()` 的调用与相关 CSS。

**验收**：DOM 里只有一处四图标入口；两处点击行为一致地只开一块。

## 4. 底部的调节图标点了没反应（渲染不变）

**用户原话**：「底部的调节图标还动不了，可以点但是渲染没变动不了」

**注意**：与第 3 条区分 —— 第 3 条是「左栏图标重复」，这条说的是**底栏**（翻页/缩放）点了不生效。

**怀疑**：底栏按钮确实绑上了（实测 `#footNextPage` / `#footZoomIn` 在探针里有效），
但**真实鼠标点击**可能没生效。可能原因：
- 底栏被别的元素盖住（z-index / pointer-events）；
- `#main` 改成 grid 后，底栏虽然视觉在底部，但命中区域与实际位置不一致；
- 按钮在 `body:not(.reading)` 时被隐藏，用户点的是「看不见的」那一条。

**改法**：先用 `elementFromPoint` 在底栏按钮中心做命中测试，确认命中的是不是按钮本身；
再按结果修（补 z-index / pointer-events 或修布局）。

**验收**：在底栏每个按钮的**中心坐标**上 `elementFromPoint` 命中该按钮；
用 `page.mouse.click(x, y)`（真实坐标点击，不是 DOM `.click()`）能翻页/缩放。

## 5. 问答是否要做多对话、分对话

**用户原话**：「问答是不是要做多对话分对话」

**这是设计问题，不是缺陷。** 现状：一篇论文**一个**问答流，存在
`data/session-<docId>.json`，换论文就换一套（按 docId 分叉）。

**可选方向**：
- A. 保持现状（一篇一个流）—— 最简单，符合「阅读器」而不是「聊天工具」的定位；
- B. 一篇论文下支持多个会话（像 ChatGPT 的左侧会话列表）—— 需要新 UI + 新存储结构 + 迁移；
- C. 只加「新建会话 / 清空当前会话」两个动作，不引入会话列表。

**建议先不施工**，等用户确认取舍 —— 这一项会影响存储结构，做错了迁移成本高。

**验收（若做 B）**：会话列表可切换、每篇论文各自独立、老存档能迁移。

## 6. 一打开，右侧栏开启点不动

**用户原话**：「现在的一打开，右侧栏开启点不动」

**现状**：右栏两块默认都不显示 → `body.right-empty` → 整条右栏 `display:none`；
此时 `sideIntent.noRight` 本来就是 false，所以「展开右栏」是 no-op。
而右侧那条小的活动栏已按用户要求删除，页面上**只剩顶栏那一个**右栏开关。

**已做的修复**：`bindSideToggleButton` 里补了「栏是空的就先开一块」；
实测点一次后 `rightEmpty=false`、`chatInput` 有尺寸（见 `test/artifacts/righttoggle.mjs`）。
**但用户报告仍点不动**，说明还有别的路径没覆盖 —— 需要复现「一打开」（首次启动、
无 localStorage、无阅读记录）这个具体状态，而不是我探针里的状态。

**验收**：清空 localStorage + 清空 state.json 后启动，点顶栏右栏开关**一次**即出现右栏；
再点收起；再点再出现（来回都有效）。
