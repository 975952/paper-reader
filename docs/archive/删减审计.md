# 论文阅读器删减审计

> 本文是一次**只读审计**的记录 + 删减施工的开工基线。
> 审计基于审计当时的工作区快照（`backup/radical-trim-before-20261005-001306/`）。
> 施工过程中的进度与验收结果追加到本文末尾的「施工记录」。

## 0. 结论：问题不是功能不够，是主干被布局状态包围

一个本地论文阅读器，被做成了"可编排的 AI 工作台"。素材（读论文）是主干，
但用户打开之后先要理解的是一套 IDE 式的布局概念：**停靠、列、浮出、固定、换栏**。

审计发现的四个结构性问题：

1. **面板编排系统自成一套产品**。`public/js/app.js` 里与"把面板放哪儿"有关的代码
   （面板管理器 + 应用内浮窗 + 底部停靠 + 拖拽停靠 + 第二右栏）约占全文件四成。
   这些代码不是阅读功能，而是布局功能，且每一条布局路径都带一串状态与兼容分支。
2. **同一次 AI 结果有多个落点**。选区旁 popover、右栏译文/问答、浮层卡片、历史会话
   都能显示同一段结果，用户无法判断哪个是"正式结果"。
3. **把 prompt 包装成了产品功能**。`ops.js` 的 15 个预设本质上是 15 段 prompt，
   外加一个未交付的 Coach 模式，占据了顶栏入口和整块菜单。
4. **低频调试参数暴露给正式用户**。设置页里主题、阅读字号之外，还有结果密度、
   控件大小、代码大小、结果透明度、结果最大宽度、PDF 纸张背景、显示页码、
   显示原文引用、默认展开来源等多组视觉实验参数。

验收只该看四件事：

- 打开论文后，界面是否马上知道怎么用。
- 一次操作是否只触发一个明确结果。
- 是否还需要理解"停靠、列、浮出、固定、换栏"等内部概念。
- AI 是否服务于阅读，而不是让用户先学习一套 AI 工作台。

### 面板编排系统的调用面（`app.js` 内部，按定义行统计）

审计用脚本统计了每个候选函数的**定义行**与**来自该函数体之外的调用点**，结论：

- `floatPanel` 7 处外部调用、`dockPanelTo` 22 处、`bringFloatToFront` 9 处、
  `floatPanels` 14 处 —— 浮出/停靠是一张**高连通**的网，不是几个孤立函数。
- `renderCols` 9 处、`renderCol` 4 处、`applyRightColsDom` 5 处、`setPanelColumn` 10 处
  —— 右栏列系统直接长在右栏渲染主路径上。
- `dockFloatColumn`、`renderRightSlots`、`showPopover`、`rightPanelsAll` 外部调用为 0
  —— 这四项是纯遗留，可直接删。

**这就是为什么不能只删几个函数名**：`#rightCol2` 的列系统与右栏渲染主路径是同一段代码。

## 2. 逐项审计结论

### 2.1 面板管理器的高级布局（最高优先级）

**现状**：面板管理器（`renderPanelMenu` / `togglePanelMenu`，`app.js` 2404–2670 区段）
每行提供：固定 / 取消固定、上移 / 下移、浮出、停靠到左 / 右 / 底部、
放到第 1 栏 / 放到第 2 栏、再开一栏 / 收起第 2 栏、应用内卡片，
外加一个"批量显示 / 批量收回"折叠区。

**问题**：用户必须先学会"dock / home / order / visible / collapsed / pinned / rect / z / w / col"
这一整套模型，才能预测点下去会发生什么。普通阅读器不需要这套概念。

**处置**：删掉整个面板管理器弹出层与其键盘导航，只保留顶栏的「收起左栏 / 收起右栏」
与一个统一的「恢复默认布局」。

### 2.2 右栏第二栏（最高优先级）

**现状**：`#rightCols` 容器 + `#splitRight` + `#rightSide.col-1` + `#rightColSplit` + `#rightCol2.col-2`；
状态存在 `state.panels.rightCols = { count, w2 }`，另有 `p.col` 记录归属栏。

**问题**：`colOf()` / `rightColsWanted()` / `dockedAreaFor()` / `enforceOnePerColumn()` /
`rightPanelInCol()` / `renderCol(n)` 全部要按"第几栏"分叉。第二栏是**默认不存在但代码永远要考虑它**的状态。

**处置**：右栏恒为一栏。右栏顶部只显示当前面板标题，底部只留「译文 / 问答」标签切换。
删除 `rightCol2` / `aiArea2` / `panelDockRight2` / `right-col2-off` / `rightCols.count` /
`renderCol(2)` / `renderCols` / `applyRightColsDom`。

### 2.3 重复的 AI 结果入口（最高优先级）

**现状**：同一段结果可能在四处出现：`#popover`（选区旁就地浮层）、右栏译文/问答面板、
`#floatLayer` 里的应用内卡片、历史会话记录。

**问题**：一次操作触发多个结果落点，用户不知道哪个是正式结果，也不知道该关掉哪个。
`showPopover` 外部调用为 0，说明它已经只剩兼容残渣。

**处置**：选区气泡只负责**选择动作**；右栏面板是**唯一**正式结果区；
流式输出、失败重试、复制都在右栏完成。选区旁只允许出现"正在请求 / 已发送到译文/问答 / 点击右栏查看"。
删除 `#popover`、`.popover`、`#floatLayer`、`.panel-float`。

### 2.4 AI 操作目录（最高优先级）

**现状**：`ops.js` 导出 15 个操作 + 4 个分组 + `COACH`。

**问题**：这些操作的差别只是 prompt 不同，却被包装成 15 个产品功能，
真实使用率极低。用户真正需要时，直接在问答框追问即可。

**处置**：只保留 4 个文档级操作（一句话速览 / 方法拆解 / 实验是否支撑结论 / 局限与可疑之处），
划词场景保留翻译 / 解释 / 加入问题 / 写笔记。删除分组菜单、"更多操作"、Coach 模式。
顶栏 `✦` 由「论文操作」改名为「论文摘要」，结果统一进问答面板。

### 2.5 「整篇」与「联网」的位置（较高优先级）

**现状**：`#optFull`、`#optWeb` 是输入框下方常驻 chip。

**问题**：
- 「整篇」会显著增加成本、等待时间与隐私暴露面，常驻按钮容易被误点。
- 「联网」会改变答案来源，在正式产品里应当是一个**明确动作**，而不是并列小开关。

**处置**：「整篇」移入发送范围菜单，默认始终是"选中文本 + 当前页"，
选整篇时给一次性确认（将发送全文 / 可能增加请求量 / 是否确实需要）。
「联网」改为问答菜单里的"联网查资料"，默认不联网，答案必须把"论文内容"与"外部资料"分开。

### 2.6 文献关系（较高优先级）

**现状**：`#relFindPdf`、`#relScanLib`、`#relFilter`、`#relSort`、`#relSearch`，
配合 `renderRelations` / `renderCiteDetail` / `showRefDetail`，
构成一个接近独立的文献管理器：自动解析全部参考文献、书架匹配、开放版本搜索、
扫描库内引用、反查引用、状态筛选、排序、分组统计、单条重试、详情卡。

**问题**：这是第二条产品线，不是阅读功能。

**处置**：左栏改名为「参考文献」，只保留参考文献列表、点击查看完整条目、跳回正文、
复制引用、用户主动点「查找开放 PDF」。删除自动后台解析全部关系、扫描库内引用、
找未入库 PDF 批量操作、"被引用"状态、状态筛选、排序、多层分组计数、自动下载导入。

### 2.7 左栏（中优先级）

保留文件 / 目录 / 笔记。文件筛选框默认隐藏，点搜索图标才出现。
点击左栏图标只做一件事（切换面板），不同时改变多个隐藏状态；左栏不做拖动 / 浮出 / 换栏。

### 2.8 设置页（中优先级）

**现状**：API Key、模型名、接口地址、主题、结果密度、顶栏、界面字号、控件大小、
阅读字号、行高、代码大小、结果最大宽度、结果透明度、PDF 纸张背景、
显示页码、显示原文引用、默认展开来源、恢复默认布局、恢复默认样式。

**处置**：只保留 API Key、模型名、接口地址、主题、阅读字号、恢复默认设置。
其余属于调试与视觉实验参数，从正式产品移除。

### 2.9 重复的栏控制（中优先级）

**现状**：顶栏左栏按钮、顶栏右栏按钮、左侧活动栏、右侧活动栏、面板底部 dock、
面板标题栏操作菜单、面板管理器 —— 七个入口。

**处置**：保留顶栏「收起左栏 / 收起右栏」；收起后由活动栏恢复。其余删除。

### 2.10 IDE 式快捷键（中优先级）

**删除**：`Alt+↑/↓` 面板换位、`Alt+H` 隐藏面板、`Shift+F10` 面板管理器、
`Ctrl+Alt+←/→` 浮动面板停靠、拖动面板标题改布局、右键面板图标改列归属、
双击分隔线改布局。

**保留**：`T` 翻译、`E` 解释、`Q` 加入问题、`R` 框选图片、`Ctrl+F` 搜索、
`+/-/0` 缩放、`Esc` 取消当前操作。

### 2.11 遗留代码与兼容逻辑（第三批）

用户侧已不存在、但代码里仍在的功能：

- `topbarHot` 顶栏热区

- "系统级独立窗口"文案
- 旧的第二栏测试契约

**处置**：全部删除。这些遗留会让后续维护者误以为功能仍然存在。

### 2.12 非产品文件（第三批）

## 5. 施工纪律（本次施工必须遵守）

1. **改动前先整目录备份。** 仓库虽有 git，但 `public/` 前端是 rust-embed 编译期内嵌进 exe 的，
   改坏了没有可回退副本就没法救。备份落在 `backup/radical-trim-before-<时间戳>/`。
2. **测试断言后改，先跑再判断。** 第三批第 6 条：先跑测试，看真实失败，再决定是代码错还是断言过时。
   禁止为了让测试变绿而先削断言。
3. **中文文件不要用 PowerShell 写。** `Set-Content` / `Out-File` / `>` 在中文 Windows 上
   默认按 ANSI(936) 解析再写回，会把整个文件的 UTF-8 中文变成乱码（本项目踩过一次）。
   改文件一律用编辑工具；必须用脚本时显式指定 UTF-8。
4. **`data/` 与 `papers/` 是用户数据，只读。** 测试用 `test/artifacts/` 下的隔离目录。
5. **测试断言不要写死用户的书架内容。** 用户随时可能导入新论文。

#### 门禁过程中查出并修掉的真缺陷

1. **`node --check` 抓不到 ES module 错误**（我自己踩的坑）。Node 把 `.js` 当 CommonJS 解析，
   而浏览器当模块解析 —— 期间 `app.js` 在浏览器里是**死的**（`Illegal return statement`），
   而 `node --check` 一直报 OK。**现在一律复制成 `.mjs` 再做解析检查。**
2. **超长配置字段被静默截断后返回 200**。审计明确要求「超限返回 413/400，不截断后静默保存」。
   已改成 400 且不落盘（`model` / `baseURL` / `targetLang` / `apiKey` / `glossary` 全覆盖）。
3. **`navigator.sendBeacon` 装不下认证头**（安全加固引入的真回归）。
   关页/刷新时的最后一笔保存走 `sendBeacon`，而它**无法设置请求头**，
   于是这笔保存在令牌校验下静默变成 401 —— 用户看到的是「刚翻到的那一页又回去了」。
   已改成注入的 `fetch` + `keepalive: true`（同样是「卸载后仍送达」的语义，且能带令牌）。
   这条是 `stream.mjs` 的「重启页面后恢复会话」断言抓出来的。
4. **两个 SSRF 绕过**（安全工作流自查发现）：`http://localhost./`（尾点，解析到 `::1`）与
   `http://[::ffff:169.254.169.254]/`（IPv4-mapped IPv6）。Node 与 Rust 两侧都已封。
